# 工單：一個沒能活過提交的開放項（Q-088）

> 佇列 `nlang-spec/meta/WORK_QUEUE.md` Q-088（原 Inbox「欄位裡的 `$`：沒有外層演化時被觀測成 ⊥，兩個不同的演化模板 `=` 相等」，偵察改寫）／**不需裁定**／依據 `SPEC_07` §4.2 P3（自由 `$` 的式子是開放項：可定義、可儲存，不觀測不坍縮；無包圍演化時觀測得 ⊥ `#no_context`；身分是含 `$` 的語法幾何）、P1（`|>` 是重綁點）、`GUIDE_03` §6.1（「急切求值在演化期就坍縮開放項（存進去的是 `_|_` 而非開放項本體）」）、§11.2（管道右邊的 thunk 攜帶該管道的 `$` 綁定）
> 探針（已預先提交並校準）`crates/oo/tests/an_open_term_that_did_not_survive_commit_probe_test.rs`
> 基線：dev `9a7d5bb`／`oo v0.89.0` ⟹ **1 綠 4 紅**；四支紅的都紅在一般斷言，只紅在非對照格，零空洞讀數。

## 1. 缺陷

〔量，v0.89.0；v0.78.0 同〕存進宇宙的演化模板，提交時被凍死：

*   `t: { a: $.b + 1 }` 提交後 `{ b: 1 } |> _.t` ⟹ `{ a: _|_ #no_context, b: 1 }`；就地寫 `{ b: 1 } |> { a: $.b + 1 }` ⟹ `{ a: 2, b: 1 }`；就地以名字引用 `{ t: { a: $.b + 1 }, r: { b: 1 } |> t }.r` 也對。
*   `t: { l: [$.b, 2], n: { c: $.b * 10 } }` 提交後 `{ b: 1 } |> _.t` ⟹ 清單與巢狀欄位裡皆 ⊥——**這一個的根兩版相同**（存放沒壞），壞在讀回之後。
*   兩個不同的模板演化後 `=` ⟹ `#true`（兩邊都是 ⊥）。
*   `evolve`、`status` 保留開放項（`status` 印 `w: { x: $["s"] }`）；`run --observe v.w.x.a`（`SPEC_07` §4.2.2 正典範例）提交前得 `"Logic"`。**只有提交與提交之後壞。**

〔讀〕成因兩處：

*   `lib.rs` `project_for_commit`：純 thunk 強制後若得 ⊥ 就存 ⊥（D33／D44 要的是「發散的定義說出為什麼」）——開放項在沒有包圍演化時被強制，得 `#no_context`，就被當成那種 ⊥ 存下。
*   `eval.rs` `pipe_apply_value` 合併分支：字面寫在管道右邊的 thunk 建立時就帶著 `$`（`context` 槽），**從倉裡讀出的模板沒有**；合併結果裡留著未綁的開放項，之後被沒有綁定的觀測方強制。

## 2. 裁定與依據

*   **不需裁定**：P3 逐字「可定義、可儲存（不觀測不坍縮）」；`GUIDE_03` §6.1 把「存進去的是 `_|_` 而非開放項本體」寫成錯的那一邊；P1 指定 `|>` 是重綁點，§11.2 寫明管道右邊的 thunk 帶該管道的綁定。
*   **原 Inbox 列寫的「兩個模板 `=` 相等」改寫**：沒有包圍演化時觀測兩個開放項，兩邊都是 ⊥、`=` 為 `#true`——那是 P3 的觀測本身，屬 Inbox「`=` 對 Thunk 外延、位址內涵」。本卡要的是**演化之後**的兩個值不相等（r3）。
*   **位址**：〔量，參考實作〕只有提交時被凍成 ⊥ 的開放項之根移動（`t: { a: $.b + 1 }` `de67b895…` → `e3f6218e…`；`w: { x: $.s }` `c71dfc64…` → `2c8854d5…`）；沒有開放項的值、表（D109 已處理）、發散與數值錯誤的定義皆不動（g1）。

## 3. 射程＝不變式（不是機制）

*   **I1 存起來的模板演化起來與寫出來的一樣**：任何深度、清單、巢狀記錄裡的開放項（r1、r2）。
*   **I2 兩個不同的模板，演化後是兩個值**（r3）。
*   **I3 每個 `$` 保有自己的綁定**：表本體的 `$` 是被匹配的輸入（D109）；沒有包圍演化時觀測開放項仍是 ⊥ `#no_context`（P3）（r4）。
*   **I4 提交照舊保存「有自己理由的 ⊥」**：發散（`c: c + 1`）、數值錯誤（`1 / 0`）照樣以 ⊥ 存下（D33／D44）；沒有開放項的值根不動（g1）。
*   **若你找到另一個讓開放項提前坍縮、或讓右值的開放項錯過管道綁定的入口**（展開 `...` 帶進的模板、態射施用的結果、`&` 合併……），一併在射程內，並在 8.1 列出。「開放項只在包圍演化裡被觀測」是要守的不變式；改那兩處只是一種機制。
