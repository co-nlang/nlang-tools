# Q-036 —— 匯入就是 spread，而頂層的 spread 沒有展開

> 開單 2026-08-24。基線 `dev c38e1c6` ／ `oo 0.31.0`（**開單當下實測，見 §3**）。
> 裁定 **O72**（六點＋⑦），本弧**不新增裁定**。
> 規格收尾由**驗收方**做；交付方若認為需要改規格，**先回報再動**。

## 0. 這一弧要證明的一句話

**「交集即匯入」今天在唯一重要的那一步上沒有實作，而 O72 選定的正準拼法
`...` 在頂層有三種不同的錯法。**

**同時要說清楚它不是什麼**：本弧**不**引入 mount、**不**引入 overlay、
**不**新增任何查找規則。〔量，§1 案例 S〕**裸名解析今天就會動**——
把模組成員放成根座標之後，`result: /if (#true, …)` 就是 `"yes"`。
**缺的只有「把模組展平進根」那一個動作。**

## 1. 量測（2026-08-24，`oo v0.31.0`，真二進位，每個案例一個獨立倉）

> 二進位使用前先問了一個已知答案的問題：`~%Math./add (1,2)` → `3` ✓

### 1.1 沒有任何拼法能讓正典範例跑起來

`SYNTAX_05` §3 與 `SPEC_09` §5.2 的範例**都是頂層程式**，都期待裸名解析得到。

| 案例 | 源碼（頂層） | `result` 那一格 |
| :--- | :--- | :--- |
| **A** | `_: ~%Cond` ＋ `result: /if (#true, …)` | **未求值**（原式印回） |
| **B** | `...~%Cond`（前面有 `a: 1`） | **未求值**，且 `a` 變成 `1..#_["~%Cond"]` |
| **C** | `_: { ...~%Cond }` | **未求值** |
| **E**（對照） | `result: ~%Cond./if (#true, …)` | **`"yes"`** ✓ |
| **F**（對照） | `c: ~%Cond` ＋ `c./if (…)` | **`"yes"`** ✓ |

⟹ **完全限定與別名都通，只有匯入不通。**

### 1.2 頂層 spread 有三種錯法，依前一行而定

| 前一行 | 結果 | 性質 |
| :--- | :--- | :--- |
| 無 | 落在一個叫 `"..."` 的鍵底下，內容原封未展開 | 錯得看得見 |
| `a: 1` | **`a: 1..#_["~%Cond"]`** | **靜默**——spread 被 `..` 吃掉 |
| `a: "x"` | `a: "x"..#_["~%Cond"]` | 靜默（連字串都吃） |
| `a: 1..5` | **`a: ⊥ #conflict`** | **靜默塌陷** |
| `a: 1,`（逗號） | 恢復成 `"..."` 鍵 | 逗號會斷開 |

⟹ **同一個拼法在四種脈絡下有三種不同的錯誤答案，其中三種無聲。**
（Inbox 原列只記到第一種，**本次量測比原記載重**。）

### 1.3 裸名解析的真正形狀（本弧最重要的量測）

| 案例 | 形狀 | 結果 |
| :--- | :--- | :--- |
| **G** | 根層 `/double: (x -> x+x)` ＋ 根層 `out: /double 21` | **42** ✓ |
| **I** | 同上不帶前綴 | **42** ✓ |
| **O** | 根層 `/if2: ~%Cond./if` ＋ 根層 `res: /if2 (…)` | **`"yes"`** ✓ |
| **M** | 巢狀內 `{ /double: …, out: /double 21 }` | **未求值** ✗ |
| **N** | 根層定義，巢狀內用 | **未求值** ✗ |
| **J** | 巢狀內 `{ ...~%Cond, out: /if (…) }` | **未求值** ✗ |

⟹ **裸名只在「根座標、且從根層使用」這一格解析得到。**
這正是 **O72 ⑦**「求值路徑決定局部脈絡」的實測形狀。

### 1.4 ★ 決定性：修好頂層 spread，正典範例就通

**案例 S** —— 手工把模組成員放成根座標（＝頂層 spread 修好後應有的形狀）：

```nlang
/if: ~%Cond./if
result: /if (#true, (@any -> "yes"), (@any -> "no"))
```

〔量〕`result` → **`"yes"`** ✓
**案例 T** 同形：`/add: ~%Math./add` ＋ `res: /add (3,4)` → **`7`** ✓

⟹ **本弧不必發明任何東西。把展平做對，故事就閉合了。**

### 1.5 成因已定位（兩處，**皆為既有程式碼，非任何一次交付所造**）

**(a) 文法：`range` 沒有防 `...` 的護欄。**
〔讀 `crates/parser/src/n.pest`〕
`field_start = _{ field_key ~ ":" }` —— **要求一個冒號**。
頂層 `...~%Cond` 沒有冒號 ⟹ **不是 field_start** ⟹
`range = { range_start ~ ".." ~ (!field_start ~ range_end)? … }` 的
`!field_start` 護欄**擋不住它**，於是 `1` `..` `.~%Cond` 被讀成一個 range。
〔讀 `:9`〕`field_sep = _{ "," | ";" | WHITESPACE+ }` —— 逗號會斷開，換行不會。

**(b) 降階：展平只實作在 Combo 建構，另一個入口從來沒學會。**
〔讀 `crates/parser/src/lib.rs:57–63`〕頂層 spread 被降成
`FieldKey::Quoted("...")` 的一個普通欄位。
〔讀 `crates/interpreter/src/eval.rs:1227`〕該鍵的展開分支住在
`ExprKind::Combo { fields, .. }` 的建構路徑裡。
〔讀 `crates/interpreter/src/universe.rs:318`〕`Universe::evolve` 收一個 `Field`、
求值 `field.value`、寫進 `field.key`——**全程沒有任何 spread 分支**。

⟹ **與 D38 同族**：引擎做得出來，然後在另一個邊界上沒有接線。

### 1.6 爆炸半徑 ＝ 零〔量〕

*   全機 **207 個 `.n` 檔**，行首 spread **0 處**。
*   conformance **143 個向量**中用到 `...` 者 **12 個，全部巢狀**，行首 **0 處**。

⟹ **沒有任何既有源碼會因為頂層 spread 開始運作而改變意思。**

## 2. 射程（兩項，**都不動身分**）

### S1 —— 頂層 spread 必須展平進根，語義與巢狀的 spread **完全相同**

「完全相同」是可檢驗的：〔量〕巢狀 `{ ...~%Cond, v: 1 }` 打開封閉性
（`is_cocoon` → `#false`）、可交換、碰撞即 ⊥、效果逐欄位保留。
**頂層必須給出同一組答案。**

**釘的是性質不是拼法**：不要求任何特定的實作位置，只要求
「頂層 `...X` 與 `_.` 被 `{ ...X }` 取代之後**可觀測地相同**」。

### S2 —— `...` 不得被 `..` 吃掉

`range` 必須在 `...` 面前讓路。**這是 S1 的前置**——S1 做完而 S2 沒做，
`a: 1` 底下那一行 spread 仍然靜默消失。

**⚠ 兩者必須同批**，理由是它們合起來才等於一句可檢驗的話；
單獨任一項都會留下一個無聲的錯誤答案。

### S1 落地時必須順帶檢查的三個交互（**報告中逐項回答**）

1.  **與 Q-035 派送閘的交互。** 頂層 spread 會把 49 個 `~%Math` 成員放進**根**，
    而 Q-035 的閘（v0.31.0，本月剛出貨）以「這個宇宙的標準根有沒有投影這個名字」
    為憑證。〔量，巢狀形〕`lib: { ...~%Math }` 之後 `lib./add (1,2)` = `3`
    而憑空發明的名字仍得 `#unprojected_builtin` ⟹ **巢狀已驗，根層未驗**。
    請確認：spread 進根之後合法呼叫仍通、**偽造仍被擋**。
2.  **與 `~` 私有性的交互。** L2-36／37 釘住 spread **不搬** `~` 欄位。
    根層必須一致。
3.  **與根層碰撞的交互。** 根上已有 `/add` 而又 spread `~%Math` ⟹
    依 O72 應為 ⊥（碰撞即 ⊥），**不得是覆寫**。
    〔背景〕O65 已把 `/add` 移出創世頂層，所以該座標今天是空的。

### 明確不做

*   **不得**引入 mount／overlay／任何新的查找規則（O72 ④ 已裁不要覆寫）。
*   **不得**改變巢狀 spread 今天的任何行為——**12 個既有 L2 向量是紅線**
    （`36`–`42`／`57`–`59`／`63`／`81`–`82`）。
*   **不得**動標準根內容、`ComboVal` 欄位、任何位址。
*   **不得**碰 `_:`（O72 ⑥ 已裁它只剩預設分支一個意思；那是規格工作，不是本弧）。
*   **不得**改規格——**規格收尾是驗收方的事**（見 §5 第 4 點）。

**G2 的校準修正（記帳）**：初稿斷言 `(q.a).%cause` 那一行含 `"conflict"`，
**在基線就紅**——但那不是缺陷，是探針的錯：`%cause` 印成多行 cocoon，
