## 0. 判準

*   **一筆寫入的欄位是集合**（`SYNTAX_03` §2 #1）：同一組欄位不論寫的順序，存同一顆根、讀同樣的值、做同樣次數的效應、付同一階的成本。
*   **觀測效應的格存它觀測到的**（D110、D46 ②），而且**演化仍然觀測**（根 1，丙）：效應在演化時做一次，提交不再做。
*   **一個定義讀了什麼、讀到的值帶什麼標記，是求值時記下來的，不是照它的文字預測的。** 引擎用「預測」做決定的地方，預測一失準，兩個順序就存兩顆根；記錄不會失準（Rice：判斷語義性質要在觀測之後）。
*   **不須裁**。D110 括號「效應格照 D46 ② 存答案（預測帶效應、或值帶效應者）」照字面：預測正確時本來就是這樣（§2 r7）。

*   **清單裝著一筆裡面有效應的記錄，提交時效應做兩次**：`a: { c: ~%Io./append_file … }`、`m: [a]`，`a.log` 2 位元組（Inbox，Q-130 偵察旁量）。
*   **讀者先寫撞上 HEAD 的衝突，演化收下、提交才報**：HEAD `h: { k: 0, r: 6 }`，寫 `h.k: g + 1`、`h.z: 1`、`g: 2`——讀者先寫演化 rc=0、提交印 `#conflict at h.k`；名字先寫演化就拒（Inbox）。

*   **成因**〔讀碼，修法驗證〕：演化逐欄當場求值；誰觀測、讀到什麼、帶什麼標記，由 `predict_effect`（D110 的 `derived_read`）與 Q-125 的靜態排序（`observe_last`、`reads_at`、`observes`、`predicts_effect`）事先判。預測失準的那一邊，語義就錯（2026-11-15 偵察：「預測型機制」）。

**Q3。** 試寫包在 `LAZY_PROBE` 裡。迫使一個 thunk 時，若它落在已寫下的節點上、而且 `EFFECTS_SKIPPED` 增加，就設 `LAZY_HIT`。例外是 `SOLIDIFYING` 裡的節點。

**R1-Q1。** 試寫（`NO_EFFECTS` 大於 0）和工作集或 delta 有關、又和正式落地不同的，還有這三處。就地落地比的是這一次算出來的 incoming，對上同一個 incoming 走 `unify_universe` 再 `restamp`。兩邊吃的是同一份，所以試寫改了答什麼，並不讓兩條路分開。
