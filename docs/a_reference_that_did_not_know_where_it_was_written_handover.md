## 1. 缺陷

〔量，`v0.104.0` 標籤建置；eval 在空目錄，提交在新宇宙〕

*   **引用的名字在被觀測的地方找、找不到回根**——D118 改掉的動態作用域，只剩這條路：`{ k: 3, r: <<k>> }.r` ⟹ `_`；巢狀 `{ k: 3, s: { r: <<k>> } }.s.r`、路徑 `<<s.k>>`、交會 `({ r: <<k>> } & { k: 3 }).r`、閉包 `{ k: 3, f: (x -> <<k>>), r: f 0 }.r`、箭頭參數 `(y -> <<y>>) { a: 7 }` 皆 `_`；`{ k: 3, s: { r: <<^.k>> } }.s.r` ⟹ ⊥ `#out_of_horizon`。
*   **提交後讀錯**：`k: 1`、`h: { k: 5, r: <<k>> }` ⟹ `_.h.r` 是 `1`（根上的 `k`）、`_.h.r + 1` 是 `2`；沒有根上的 `k` 時 `_.h.r` 是 `_`、`_.h` 印 `{ k: 5 r: _ }`。
*   **看不到之後的提交**：`h: { k: @int, r: <<k>> }` 再提交 `h: { k: 5 }` ⟹ `_.h.r` 是 `_`。
*   頂層讀對：`t: { a: 1 }`、`c: { r: <<t>> }` ⟹ `c.r.a` 是 `1`；`k: @int`、`h: { r: <<k>> }` 再提交 `k: 2` ⟹ `_.h.r` 是 `2`。
*   〔讀〕`eval.rs` 的 `Structural(Path)` 求成 `Value::Ref(path)`——只有路徑；`lib.rs` `force` 的 `Value::Ref` 臂以 `resolve_path_internal` 解，裸名對 `ctx.scopes`（觀測那一方）找；`store_codec.rs` 把存著的 `<<k>>` 解碼成同一個 `Value::Ref`。

## 2. 依據；位址

*   **D118**（裁定已下）；`SPEC_04` §1.2 已寫明綁定的位置與一般名字相同。

*   **JSON 舊倉**：`Value` 經 serde 寫舊倉格式；`Ref` 的序列化形狀不得變。

## 3. 射程＝不變式（不是機制）

*   **M1 引用的名字解析到寫下處**：兄弟、巢狀、`^`、路徑、經它算術、閉包、呼叫端有同名的名字、一個名字拿著它、箭頭參數（r1）。
*   **M2 寫下處是交會之後的節點**（Q-103）：交會、兩邊都寫、經它算術（r2）。
*   **M3 提交後讀寫下處**：根上也有同名、巢狀、`^`、別名、印整個記錄、就地交會、箭頭本體（r3）。
*   **M4 之後的提交是那個節點上的交會**：引用看得到它——一檔、兩次演化、兩次提交，三者同根（r4）。
*   **另一半——讀根的照舊**：頂層引用；`<<_.k>>` 讀根；寫下處沒有的名字照舊往外找到根（`h: { r: <<k>> }` 讀根上的 `k`，看得到之後提交的 `k`）；管道穿過引用綁輸入、巢在轉換器裡的引用不帶 `$`（L2-126／130／131）；頂層的活引用（g1）；根不動（g2）。
*   若你找到另一處引用的名字在觀測處解、或讀回來的引用丟了寫下處，一併在射程內，在 8.1 列出。

## 6. 明文不在射程內

*   **離開寫下處的引用存進倉**：箭頭回傳到另一個座標（`k: 1`、`h: { k: 5, f: (x -> <<k>>) }`、`z: h.f 0` ⟹ `_.z` 是 `1`）、指向箭頭參數（`f: (y -> <<y>>)`、`g: f { a: 7 }` ⟹ `_.g` 是 `_`）——eval 裡讀對（`5`、`{ a: 7 }`），提交存的是光禿的 `<<k>>`，名字改在存放處解。存什麼（讀到的、帶著框、拒絕）須另裁；g1 鎖住今天的讀數，**不得**順手改（新開 Inbox）。
*   **讀自己字面的欄位，提交成答案後，之後的提交不重讀**：`h: { k: @int, r: k }` 再提交 `h: { k: 5 }` ⟹ `_.h.r` 是 `@int`，一檔是 `5`，兩者不同根（v0.104.0 已然；Q-103「一檔＝兩次演化」只量了第一次提交時名字還不存在的情形）。存答案還是配方的規則（D110 一族），不是名字解析；新開 Inbox。引用不在此列：解參照是讀宇宙，存配方。
*   跨提交「⊥ 被凍進歷史，宇宙長大後不重讀」（Inbox）。
*   規格文字、向量與 `CHANGELOG`：驗收方收尾。
