## 1. 缺陷

〔量，`v0.104.0` 標籤建置；eval 在空目錄，提交在新宇宙〕

*   **引用的名字在被觀測的地方找、找不到回根**——D118 改掉的動態作用域，只剩這條路：`{ k: 3, r: <<k>> }.r` ⟹ `_`；巢狀 `{ k: 3, s: { r: <<k>> } }.s.r`、路徑 `<<s.k>>`、交會 `({ r: <<k>> } & { k: 3 }).r`、閉包 `{ k: 3, f: (x -> <<k>>), r: f 0 }.r`、箭頭參數 `(y -> <<y>>) { a: 7 }` 皆 `_`；`{ k: 3, s: { r: <<^.k>> } }.s.r` ⟹ ⊥ `#out_of_horizon`。
*   **提交後讀錯**：`k: 1`、`h: { k: 5, r: <<k>> }` ⟹ `_.h.r` 是 `1`（根上的 `k`）、`_.h.r + 1` 是 `2`；沒有根上的 `k` 時 `_.h.r` 是 `_`、`_.h` 印 `{ k: 5 r: _ }`。
*   **看不到之後的提交**：`h: { k: @int, r: <<k>> }` 再提交 `h: { k: 5 }` ⟹ `_.h.r` 是 `_`。
*   頂層讀對：`t: { a: 1 }`、`c: { r: <<t>> }` ⟹ `c.r.a` 是 `1`；`k: @int`、`h: { r: <<k>> }` 再提交 `k: 2` ⟹ `_.h.r` 是 `2`。
*   〔讀〕`eval.rs` 的 `Structural(Path)` 求成 `Value::Ref(path)`——只有路徑；`lib.rs` `force` 的 `Value::Ref` 臂以 `resolve_path_internal` 解，裸名對 `ctx.scopes`（觀測那一方）找；`store_codec.rs` 把存著的 `<<k>>` 解碼成同一個 `Value::Ref`。

### 8.1 射程逐項對照

`eval.rs`、`lib.rs`、`store_codec.rs`、`value.rs` 與 `q104-ref ce8bd9e` 逐位元組相同。`oo` 仍是 `0.104.0`，interpreter 仍是 `0.2.2`。新倉 `layout=9`、`encoding=10`。`Ref` 帶著寫下處的框。框不進身分、不進相等、不進序列化。
