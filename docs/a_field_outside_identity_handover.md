# Q-037 —— 一個不進身分的欄位，正在改變 `&` 的答案

> 開單 2026-08-24。基線 `dev f808d8c` ／ `oo 0.32.0`（**開單當下實測，見 §3**）。
> **本弧不新增裁定**——不是「哪個對」的問題，兩邊都同意答案該是兩個鍵。
> 規格收尾由**驗收方**做；交付方若認為需要改規格，**先回報再動**。

## 0. 這一弧要證明的一句話

**兩個 CAID 逐字元相同的值，對同一個運算子必須給同一個答案。**

今天不是。而且它丟掉的**不只是資料，還有一個「不同意」**——
`{ ...{a:1} } & { ...{a:2} }` 答 **`1`**，而兩個對照組都是 `⊥ #conflict`。
⟹ **一個該塌陷而沒有塌陷的答案，讀起來像一個正常的答案。**

---

## 1. 量測（2026-08-24，`oo v0.32.0`，真二進位）

> 二進位使用前先問了已知答案的問題：`~%Math./add (1,2)` → `3` ✓

### 1.1 現象

| 式子 | 結果 | 應為 |
| :--- | :--- | :--- |
| `{ ...{ a: 1 } } & { ...{ b: 2 } }` | **`["a"]`** | `["a","b"]` |
| `{ ...{ b: 2 } } & { ...{ a: 1 } }` | **`["b"]`** | 同上（**不可交換**） |
| `{ ...~%Cond } & { ...~%Math }` | **3 鍵** | **52** |
| `{ ...~%Math } & { ...~%Cond }` | **49 鍵** | **52** |
| **`({ ...{a:1} } & { ...{a:2} }).a`** | **`1`** | **`⊥ #conflict`** |

**對照，全部正常**：`{a:1} & {b:2}` → 兩鍵；`{...{a:1}} & {b:2}` → 兩鍵；
`{a:1} & {...{b:2}}` → 兩鍵；`({a:1} & {a:2}).a` → ⊥；`({a:1, ...{a:2}}).a` → ⊥。
⟹ **只有「兩邊都是 spread 結果」才壞**，三個軸（data／rules／types）同形。

〔量，四個真二進位〕**v0.20.0／v0.26.0／PRE `ebc0a5a`／v0.32.0 全部相同**
⟹ **至少自 v0.20.0 既有**。

### 1.2 判別實驗（Inbox 原列訂的那一個，已跑完）

原列問：那兩個值的 **CAID 是否相同**？

| | 值 |
| :--- | :--- |
| `identify ({ /f: 1 })` | `…f2425155c09f448326` |
| `identify ({ ...{ /f: 1 } })` | `…f2425155c09f448326` |

**逐字元相同。** 且 `=` 為 `#true`、`keys` 相同、印出相同。
⟹ 依原列判準：**它們是同一個值，而 `&` 給兩個答案。**

### 1.3 成因（已定位到「在哪兩行之間」，未定位到「哪一行」）

〔讀 `crates/interpreter/src/value.rs:895–897`〕

```rust
#[serde(skip, default)]
pub pending_spreads: Vec<Value>,
```

〔量〕`bn_serial.rs` **0 命中**、`encode_chs` **0 命中**
⟹ **它不進 CAID**。而 spread 的展開是**延遲的**，故一個 spread 結果會帶著
一個身分看不見的未展開項。

〔crate 探針實測，2026-08-24〕

| | `data` | `pending` |
| :--- | :--- | :--- |
| `{ ...{ a: 1 } }`（進 meet 前） | `[]` | **1** |
| `{ ...{ b: 2 } }`（進 meet 前） | `[]` | **1** |
| **`a & b`** | `[]` | **1 ← 應為 2** |
| `force(a & b)` | `["a"]` | 0 |
| 對照 `{a:1} & {b:2}` | `["a","b"]` | 0 |

〔讀 `crates/interpreter/src/unify.rs`〕`:428–434` 對兩邊各呼叫一次
`expand_combo_pending`；`:436–437` 收集 `a.pending + b.pending`；
`:587` 寫回 `out.pending_spreads`。**那三處的意圖是對的。**
⟹ **遺失發生在 `:436` 之前**，即兩個 `expand_combo_pending` 呼叫之一。

⚠ **`expand_combo_pending` 是 `pub(crate)`**，整合測試碰不到
⟹ **最後一步定位需要 crate 內探針，那是本弧的第一件工作。**

### 1.4 同一個引擎裡就有一份正確的參考實作

〔量〕`x: { ...{ a: 1 } }` 與 `x: { ...{ b: 2 } }` 兩次 `evolve` 到同一座標
⟹ **`{ a: 1, b: 2 }`，正確**（與不用 spread 的對照逐字相同）。

⟹ **座標合併對，`&` 運算子錯**。兩條路徑對同一個「交集」給出不同答案。

## 2. 射程（兩層，**不得只做第一層**）

### S1 —— meet 必須保住兩邊

`{ ...X } & { ...Y }` 的可觀測結果，必須與 `X & Y`（直接書寫）**完全相同**，
包含碰撞時塌陷為 `⊥`。

### S2 —— 一個不進雜湊的欄位，不得改變可觀測行為

`REAL_03` §6.7 逐字禁止「未進入雜湊的欄位」（**判例 `span`**；
同族 M7 的 `legacy_fields`——當時判為「陷阱不是活缺陷，因為沒有人寫它」）。
**這一個有人寫。**

**S2 不指定做法**，只要求那個性質成立。兩條可想見的路：
在任何可觀測邊界前保證 `pending_spreads` 恆為空，或讓它進入身分。
**若交付方認為兩條都不對，回報第三條，不要默默選一條。**

**S1 做完而 S2 沒做 ⟹ 本弧沒有結束**——修好這一個運算子，
不會阻止下一個運算子遇到同一件事。

### 明確不做

*   **不得**動任何值的身分。**G4 是紅線探針**：修完 `identify` 兩式仍須逐字元相同。
    〔量〕最容易走錯的一步就是「讓兩個值變成不同的值」——那樣紅的會變綠而缺陷還在。
*   **不得**改變巢狀 spread 的語義（`SPEC_03` §3.1）；**16 個既有 L2 向量是紅線**
    （`36`–`42`／`57`–`59`／`63`／`81`–`82`／**`105`–`108`／`110`**）。
*   **不得**碰頂層 spread（Q-036，v0.32.0 已出貨）、`_:`、mount、overlay。
*   **不得**改規格——規格收尾是驗收方的事。

## 4. 探針（**已由驗收方在開單當下校準並實跑確認**）

**五支紅全部倒在自己的斷言上，不是倒在 REACH 上**（逐支實跑確認）：

| # | 基線 | 斷言 |
| :-- | :--- | :--- |
| **R1** | 紅（`["a"]`） | 兩個 spread 相 meet 必須留下兩邊的鍵 |
| **R2** | 紅（`["a"]` vs `["b"]`） | 交換兩個運算元必須得同一個答案 |

| **R5** | 紅（`1`） | **被丟掉的運算元不得把它的「不同意」一起帶走**——必須是 `⊥ #conflict` |
| **G2** | **綠** | 只有一邊是 spread 時，兩個方向都必須維持正常 |
| **G3** | **綠** | `~` 私有欄位不得因為經過 `&` 而外洩 |
| **G4** | **綠** | **身分紅線**：`identify` 兩式必須維持逐字元相同 |

**校準記帳（驗收方的錯，逐項指名）**：
