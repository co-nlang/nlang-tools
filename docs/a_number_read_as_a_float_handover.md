## 0. 判準（規格原文）

*   **`SYNTAX_02` §1**：「原子之間的同一性：……數字依數值比較。」`SYNTAX_06` §2 #2：`==` 把兩側塌縮為原子再比值，「數字依值（見 SYNTAX_02）」。
*   **`SPEC_09`「數值大小的唯一合法家」**：數值**大小**一律走 `/lt`／`/lte`／`/gt`／`/gte`，「int／float 依值跨比」。語言層 `<`／`<=`／`>`／`>=` 判子集／子型別（`SYNTAX_06` §2.5，`3 <= 5` → `#false`），**不是大小**——`3 > 2` 答 `#false` 是規格，不是缺陷。
*   **依值＝精確**：`2^53 + 1` 與 `2^53` 是兩個數；`2^53 + 1` 與 `9007199254740992.0` 也是兩個數。先把整數換成 f64 再比，答的是「捨入之後」的問題，不是「依值」。
*   **`REAL_03` §6.7**（Q-113 已引）：值的正準形由內容決定，不由寫入先後決定——一個聯集先寫哪一支，根相同。
*   **比較不須裁**：上面幾條已經定了答案。整數與浮點跨比的語義（`3 == 3.0` → `#true`，`1 = 1.0` → `#false`）照今天，本卡只把「依值」做成精確。
*   **D125（2026-11-01 用戶裁定甲）**：`~%Math./clamp` 越過界時答那個界本身，照寫的樣子；在界內答 `x`。規格原本沒寫 `clamp` 的型別；精確比較之後 `clamp (A, G, Z)` 唯一落在界內的答案是整數 A，不是任何 f64。
