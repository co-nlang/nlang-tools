## 2. 為什麼現在做:一條六步的鏈,終點是歷史消失

〔量,引擎 v0.21.0 與真 v0.20.0 二進位〕每一步的元件都照設計運作,無一步報錯:

```
format-3 的倉缺 .oo/format
  → 唯讀的 oo log 蓋上「1」          （假的）
  → 格式閘被繞過，v0.20.0 打得開
  → 它把健康的根指控為 corrupt       （假的）
  → 它寫得進去，HEAD 移動，標籤變 2
  → 合法的 oo gc 回收原根與原 commit → 歷史消失
```

**第 6 步的 `gc` 是特權且非自動的,不在射程內。要修的是前五步。**

## 3. 三件事

### 3.1 承重理由(不要在交付時重新發明)

〔量〕**位址不是檔案的雜湊**:路徑 `b7741081…`,檔案內容 sha256 `350c42c7…`。
`content_hash()` 走 `bn_serial`(BN/),磁碟上的 JSON 只是容器 ⟹ **編碼與身分正交**。

故 CAS 物件**不能**自陳編碼:進雜湊等於把與位址無關的東西塞進身分;不進雜湊直接違反
REAL_03 §6.7。**界線**:物件**得**指名它所依賴之物(內容,如標準根摘要——由值決定,
仍是位址的函數),**不得**宣告它自己如何被編碼(容器的後設資料)。

## 4. 兩個由裁定推導出來的決定(交付方不得自行更改;若不同意,回報不要自己決定)

### 4.1 `.oo/format` 的內容改為自描述,而佈局號碼第一次真的移動

新增 `.oo/objects.format` **是一次佈局變更**——「`.oo/` 底下有哪些檔」正是佈局的
定義。故佈局 **1 → 2**,而這是該計數器**第一次因為佈局而動**。

判別舊倉需要一個不靠猜的訊號。既有倉的 `.oo/format` 是**裸數字** `1`/`2`/`3`;
新制寫**自描述**內容。⟹

| `.oo/format` 內容 | 讀法 |
| :--- | :--- |
| `layout=2` | 新制。編碼讀 `.oo/objects.format` |
| 裸 `1` / `2` / `3` | **舊制(合併計數器)**:佈局 1,編碼 = 該數字 |
| 缺席 | **拒絕開啟**,訊息須說「無法判斷這個倉的佈局」 |
| 其他 | 拒絕(現況已如此) |

「格式檔自己宣告自己的格式」正是 O23 第 (3) 條在這個檔上的實例。

### 4.2 編碼宣告放 `.oo/objects.format`,**不放 `.oo/objects/` 裡面**

〔量〕**五個既有套件**(`advertise_wire`／`affiliation_claim`／`advert_persistence`／
`every_byte_or_none`／`a_value_not_a_recipe`)的走訪器取 `.oo/objects` 底下的**每個檔**,
會把宣告檔當成 CAS 物件。另十一個套件限定 `sha256/` 之下,不受影響。
`gc` 的 `list_digests` 也限定 `sha256/<2-hex>/` 底下的檔,**不受影響**〔已量〕。

原則上也對:`objects/` 裡只放內容定址物件,一個沒有位址的檔放進去是類別錯誤。
目錄自身的後設資料放在它旁邊,不放在它裡面。

`.oo/objects.format` 內容:`encoding=3`。**沿用既有編號**(1/2/3),不重新編號——
既有倉的 `2`/`3` 直接對應,遷移是機械的。

### 6.1 校準抓到的一件事(記給後人)

R3 首版在基線**錯誤地綠**:它寫入裸 `3` 再確認讀得開——而基線的現行制**就是**裸 `3`,

擋掉「一律拒絕舊倉」這種假滿足)。

## 9.2 D1 — 一個空的 `.oo/` 目錄不是一個倉

〔量,單一變數〕

| | 交付前 | 交付 |
| :--- | :--- | :--- |
| 沒有 `.oo/` | `node serve` 起得來 | 起得來 |
| **空的 `.oo/`** | **起得來** | **`cannot determine this store's layout`** |

`ObjectStore::init` 用 `new_store = !oo.exists()` 當判別式。**`.oo/` 存在不蘊涵
「這是別人寫的倉」**——它可能只是一個被先建出來的空目錄。

實際受害的不只測試夾具:`oo node serve` 在一個只有 `.oo/discovery.n`、從未提交過
任何東西的目錄上是**合法用法**,而它現在開不起來。

**O53 治的是「一個你沒寫過的倉」;一個空目錄根本不是倉。** 判別式應該問**有沒有
東西會被讀錯**——沒有 CAS 物件、沒有 `HEAD` ⟹ 沒有任何形可以被誤解 ⟹ 初始化;
**有物件而沒有宣告 ⟹ 拒絕**(M1,已經對了,不得回退)。

類別與前幾弧同族:**判別式問的是代理量(`.oo` 在不在),不是性質(有沒有內容其形要緊)。**

**受影響:11 支** —— `authority_test::architect_persists_across_init` 與
`automatic_admission` 十支(`c0`／`c1`／`r1`–`r8`)。

## 9.3 順帶:相容別名把編譯錯誤換成了執行期失敗

交付保留 `pub const STORE_FORMAT_VERSION = OBJECT_ENCODING_VERSION`。唯一的外部
呼叫者是 `local_gc` R7,它拿這個常數去比對 `.oo/format` 的**內容**——而該檔現在
裝的是 `layout=2`。**這個名字現在說謊了**:它叫 store format,而 store 的 format
檔裡沒有它。

保留別名讓一個會在編譯期被抓到的問題,變成了一支在執行期紅掉的測試。
**建議移除該別名**;唯一的呼叫者是探針,由驗收方改。
