# 一個提交時被拍成快照的箭頭（Q-107）

## 0. 判準（規格原文）

*   **D120**（2026-10-27 用戶裁定，甲）：一個座標的記錄裡，箭頭的本體讀到這個記錄自己的名字（`h: { k: @int, f: (x -> k) }`）——提交存它的語法、在節點的框裡，與同一個記錄裡讀名字的欄位（`r: k`）同；不強制成帶 `%closure` 快照的態射。與 D110 R-2「提交不得把讀了宇宙的態射配方強制成值」同一條規則，節點代替宇宙。
*   **`SPEC_05` §3.3「`%closure` 僅捕捉自由變數」（MUST）**：管以值存下的算子，以及任何算子被強制之時；存成語法的箭頭沒有 `%closure`。
*   **D118**、`SPEC_10` §2.3.1 Q-105 款：之後的寫入是讀回來那個節點上的交會。**Q-103 的不變式**：一檔、兩次演化、兩次提交同讀數、同根。

## 1. 缺陷

〔量，`v0.107.0` 標籤建置；eval 在空目錄，提交在新宇宙〕

*   `h: { k: @int, f: (x -> k) }` 再提交 `h: { k: 5 }` ⟹ `_.h.f 0` 是 `@int`；一檔與兩次演化 `5`；三個根。`k: 1..` ⟹ `1..#_`；`x + k` ⟹ `_`；別名 `g: f`、`{ v: k }`、`^.k`、`a.k`、私有鍵 `~k`、規則軸 `/f`、私有軸 `~f`（經 `r: f 0` 讀）、`r: f 0`、柯里化 `(x -> (y -> k))`、點號寫 `h.k: 5` 同。
*   三個寫入（`h: { k: @int, f: (x -> k) }`／`h: { j: 1 }`／`h: { k: 5 }`）：一檔與三次演化 `5`，三次提交與兩種混合 `@int`，三個根。
*   提交後 `(_.h & { k: 5 }).f 0` ⟹ `@int`。
*   對照：根上 `f: (x -> k)`、深一層 `h: { s: { k: @int, f: (x -> k) } }`、清單裡 `fs: [(x -> k)]` 都讀 `5`。
*   〔讀〕倉裡讀名字的欄位 `r: k` 存成 thunk，閉包指向記錄自己寫下的框（文件裡共用，D114），Q-105 解碼時認它為節點；第一層的箭頭在 `project_for_commit` 被當成構造強制成態射，`%closure` 存的是 `{ k: @int }` 這個值。

## 2. 依據；位址

*   **裁定 D120**。不取乙（照舊存值、窄化的框記得節點）：要新存形，而從別的字面取來的態射與節點的箭頭窄化後位元組相同。
*   **位址**：帶「讀節點名字的箭頭」的記錄根移動（一檔也動：存形由態射變語法）；其餘不動（g2 釘 v0.107.0 的根）。破壞性，收尾時記 `CHANGELOG`。
*   **代價**〔量〕：只有箭頭讀名字的記錄，倉多存一份記錄寫下的框（200 欄 2,051 B → 16,876 B）；已有讀名字欄位的記錄同價（17,087 B → 17,019 B）。這是用戶裁甲時接受的代價。
*   **v0.107.0 寫的倉**〔驗收方量〕：照讀照寫，舊引擎讀得了新倉；已存下的快照不變（之後寫 `h: { k: 5 }` 仍 `@int`，重寫 `f` 才讀 `5`）——存下的是值，不要去「修」它。

## 3. 射程＝不變式（不是機制）

*   **M1 讀節點名字的箭頭讀交會後的節點**：十四個形，一檔、兩次演化、兩次提交同讀數、同根（r1）；記錄的每一軸都算（資料、`~` 私有、`/` 規則……）。
*   **M2 eval 裡交會一個已提交的記錄**：箭頭、別名、施用結果都讀交會後的節點；沒交會時讀當時的值（r2）。
*   **M3 三個寫入五種分組一個根**（r3）。
*   **M4 規模**：400 支讀節點名字的箭頭，一檔、兩次提交，60 秒內讀對（r4）。
*   **另一半——不讀節點的照舊**：只讀引數的箭頭、讀宇宙的、從別的字面取來的（`{ j: @int, m: (x -> j) }.m` 仍 `@int`）、呼叫造的（`(k -> (x -> k)) 7` 仍 `7`）、不碰那個名字的寫入（`h: { j: 1 }` 之後仍 `@int`）、深一層與根上（g1）；這些的根不動（g2）。
*   **窄化照舊**：讀回來被強制的算子，`%closure` 只捕捉本體的自由變數——存成語法的與存成值的都是（g3）。
*   若你找到另一處第一層的值在提交時被拍成讀節點名字的快照（另一種構造、另一軸、`refine`、`squash`），一併在射程內，在 8.1 列出。
