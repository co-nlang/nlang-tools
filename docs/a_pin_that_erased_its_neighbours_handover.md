## 0. 判準

*   **D128（甲，2026-11-05 用戶裁定）**：**pin 只覆寫它的值寫到的葉；它寫到的葉以外的座標——兄弟欄位——照沒有 `--pin` 時一樣交會。**
*   **`SPEC_10` §2.2.3**：「吸收……以座標為單位……**不得**抹去未被本次 `pin` 指名的座標」。**§2.2.1**：座標到葉，「**不得**只是該次演化所寫入的頂層欄位」。
*   **`SYNTAX_03` §2 #1**「賦值是把約束綁到座標」；**#3** `a.b.c: v` 與 `{a: {b: {c: v}}}` 等價——所以兩種拼法的 pin 答案必須相同，也必須與欄位順序無關（#1「欄位順序無關」）。
*   **`SPEC_10` §2.3.1**：同一筆寫入的兩個欄位寫同一座標是兩筆定義（不帶 pin 時拒）。
*   一句話：**pin 的值是一組葉上的約束；pin 把那些葉換掉，其餘一概不動。**

## 1. 缺陷

〔量，v0.123.0 加 Q-123（tools `dev` `99d274b`）；`acc/q124/recon*.sh`、`cells.sh`〕

*   **路徑鍵 pin 抹掉兄弟**：`h: { k: 5, r: 6 }` 提交，pin `h.k: 7` ⟹ `_.h` 是 `{ k: 7 }`，`h.r` 不見。巢狀寫法 `h: { k: 7 }` 同。兩層：`a: { b: { c: 0, d: 1 }, e: 2 }` pin `a.b.c: 1` ⟹ `{ b: { c: 1 } }`（`a.b.d`、`a.e` 都不見）。配方兄弟（`h: { k: @int, r: k + 1 }` pin `h.k: 5` ⟹ `{ k: 5 }`）。清單元素：`l: [1, 2, 3]` pin `l.1: 9` ⟹ `l` 變成記錄 `{ 1: 9 }`。
*   **Q-123 之後寫同一個值也抹**：pin `h.k: 5`（HEAD 已是 5）落地，`_.h` 是 `{ k: 5 }`。
*   **兩次 pin 互相吸收整個頂層欄位**：pin `h.k: 7` 再 pin `h.r: 9` ⟹ `{ r: 9 }`。
*   **一個 pin 檔裡的路徑鍵依行序互相取代**：`h.k: 7`、`h.r: 8` ⟹ `{ r: 8 }`，而 `h: { k: 7, r: 8 }` ⟹ 兩欄都在；`h.k: 7`、`h.r: 8`、`h.k: 7` ⟹ `{ k: 7 }`；`a.b: 1`、`a.c.d: 2` ⟹ `{ c: { d: 2 } }`。`h.k: 7`、`h.k: 8` ⟹ `8`、`r: 7`、`r: 8` ⟹ `8`——不帶 pin 的同一個檔在演化時拒（`#conflict at h.k`／`at r`）。
*   **起因**：pin 的座標是頂層欄位（`evolved_coords`、`pin_coords`、`absorbs` 都以頂層欄位名記）；演化端 `replace_merge` 逐欄位整個換掉頂層欄位，提交端 `pin_commit_merge` 整個覆寫頂層欄位，吸收（`injections::fold`）整個拿掉被吸收成員的頂層欄位。
*   **對照**：不帶 pin 的 `h.z: 1` 寫在 `h: { k: 5, r: 6 }` 旁 ⟹ `{ k: 5 r: 6 z: 1 }`；不帶 pin 的 `h.k: 7` 拒 `#conflict at h.k`。

## 3. 射程＝不變式（不是機制）

*   **M1 pin 只覆寫它的值寫到的葉**（r1）：路徑鍵、巢狀寫法、兩層深、讀被釘葉的兄弟配方（讀新值）、⊥ 葉旁的欄位、清單元素、清單由元素寫（`l: [7]` 蓋 `[1, 2, 3]` ⟹ `[7, 2, 3]`）、葉上的型別、記錄裡一個欄位寬化。**兩種拼法落地同一個根**；一層深時也與直接寫下結果同根。「葉」：開放記錄（不封閉、沒有展開、沒有關係）不是葉，它的欄位才是；其他一切（純量、型別、區間、⊥、清單元素、封閉記錄、配方）是葉。純的記錄字面還以寫法存著時也是記錄（建它不讀任何東西）。
*   **M2 一筆 pin 寫入是一個集合**（r2）：一個 pin 指令（一個成員）裡的欄位彼此交會，**與順序無關**，再整筆覆寫指令之前的工作集；兩個欄位寫同一座標（同一個檔、或同一指令的兩個檔）在演化時拒、指名座標、不寫成員、根不動——與不帶 pin 同。
*   **M3 後來的 pin 只拿走它寫的葉**（r3）：吸收（D58）以葉為單位——被吸收的成員在別處寫的東西留著（兩次 pin 兩個葉、同一葉、pin 前後的一般寫入、一般寫入同葉之後的 pin）。**先淺後深、先深後淺**照先後的意思：先把 `h.k` 釘成 `3` 再釘 `h.k: { a: 1 }` ⟹ `h.k` 是 `{ a: 1 }`（`b` 不回來）；反過來 ⟹ `3`。**演化當下看到的與提交存下的同一顆**。
*   **M4 留下的兄弟照判**（r4，Q-122）：pin `h.k: 7` 讓兄弟 `r: k & 5` 讀成 ⊥ ⟹ 演化拒 `#conflict at h.r`、根不動；兄弟 `r: k + 1` 讀 `8`。
*   **M5 HEAD 已持有的 pin，任何拼法都是已持有**（r5，Q-123）：路徑鍵同值、少欄位、空記錄、兩層深同值、少元素——`status` 靜止、提交答 `already in HEAD`、根不動、讀數不變。
*   **另一半**（g1）：葉上照覆寫——純量蓋記錄、記錄蓋純量（`h: 3` pin `h.k: 1` ⟹ `{ k: 1 }`）、新座標、新的空記錄、蓋 ⊥；不帶 pin 的寫入不變（葉上衝突照拒、同值照持有）；pin 的提交仍須出示能力。
*   g2：小的根不動。
*   **上一張卡學到的，逐條過**：
    *   不變式在所有路徑都經過之處判：葉的集合要同時用在**演化**（工作集的視圖、Q-122 的 `bottoms_as_read`）、**吸收**（`fold`）、**提交**（`pin_commit_merge`）、**已持有**（Q-123 的 `pin_moves`：`proposals_at` 與 `head_if_it_holds`）；
    *   「已持有」兩邊照提交的方式觀測再比（Q-123）；兩邊經過同樣的葉寫入（巢狀記錄寫入後是交會出的節點，D118）；
    *   另一半配只差寫法的格（Q-113 R-2／Q-123 驗收）：路徑鍵 vs 巢狀、行序、同一行寫兩次；
    *   借用前卡的存形就抄它整組不變式：吸收（D58）、晚到 ⊥（Q-122）、已持有（Q-123）各配一組。
