## 0. 判準

*   **環上有一個觀測效應的格，效應仍只做一次**：在演化、提交、讀取都一樣（D110、D46 ②；Q-127 M4）。
*   **一筆寫入，一顆根**（`SYNTAX_03` §2 #1；Q-127 M1）：環上有效應格時也一樣，行的每一種排列存同一顆根。
*   **環繞回來的那一處，答案放的是純的環在那裡放的東西**：
    *   清單的環上有非純引用的跳（字面量建構也算），走發散判定，截點是 `⊥ #divergent`（`SPEC_12` §1.1 第 2 款、§2.2）。純的 `a: [a]` 存 `[⊥ #divergent]`，所以 `a: [E, a]` 存 `[#true, ⊥ #divergent]`。
    *   記錄是惰性的（`SPEC_12` §3.2），所以存的是指回那個坐標的配方。效應格的答案照 D110 括號存，但要是有限的。
*   **演化收下的寫入，提交得了**：提交不得在做了效應之後拒絕。
*   **不須裁**。截點放什麼由 `SPEC_12` 決定（效應不改變環的形狀，只改變效應那一格的值）。存答案由 D110、D46 ② 決定，惰性欄位由 D129 決定。

## 1. 缺陷

〔量，`v0.130.0` 標籤建置；`acc/q131/recon.py`、`recon2.py`、`recon3.py`、`cnt.sh`；每一形跑過所有行的排列；對照 v0.129.0〕

*   **清單繞回一個效應格，效應做兩次（v0.130.0 回歸）**：
    *   `a: [E, a]`（`E` 是 `~%Io./append_file …`），演化後 `a.log` 2 位元組，存 `[#true, [#true, ⊥ #divergent]]`。v0.129.0 是 1 位元組、`[#true, _]`。
    *   `a: [E, b]`／`b: [a]` 兩序都是 2 位元組；`a: [E1, b]`／`b: [E2, a]` 是 4 位元組。
    *   三節環、環旁一個讀者 `m: [b]`：照順序是 2 或 3 位元組。
*   **清單繞回一個效應格，兩序兩顆根**（兩版都錯）：
    *   十形裡九形有 2 到 4 顆根，截在哪一層取決於誰先被觀測。
    *   例如 `a: [~%Env.get "…", b]`／`b: [a]`，以及 `_.` 拼法、路徑第一段 `b.0`。
*   **記錄繞回自己、環上有 IO，提交被拒**（兩版都錯）：
    *   `a: { e: E, x: b }`／`b: { y: a }`、IO 在 `b`、自我環 `a: { e: E, x: a }`、清單裝著記錄環、記錄與清單混環。
    *   每一種順序演化都收下，提交時效應做一次，然後印 `refusing to store a root this engine cannot read back: … #stack_overflow`。效應做了，卻什麼都沒存。
*   **成因**〔讀碼，修法驗證〕：
    *   觀測一格時，觀測框直接求值它的式子。讀到自己時，拿到的是工作集裡自己的配方，於是又求值一次。
    *   環沒有先後，照來源順序觀測。一個只因讀了別格才碰到效應的格若先被觀測，就在自己裡面把別格的配方求值了一次。
    *   提交時，帶著繼承來的 `#io` 的配方（`x: b`）被深強制，記錄的環一直展開到深度上限，存不回來。
