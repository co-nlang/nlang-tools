# Q-018 前置偵察 — CLI 是不是一個承諾

> **驗收方自量**，基線 `v0.46.0` 標籤建置。
> 目的：把「**CLI 是不是規範性介面**」展開成可裁的候選。
> 這是 2026-09-09 盤點排序的第 1 項（用戶已裁 1 → 2 → 3）。

## 0. 先說結論的形狀

**這一題不是「是」或「否」。量測把它切成兩半，而兩半的證據方向相反。**

| | 規格寫了什麼 | 今天的實況 |
| :-- | :-- | :-- |
| **拼法**（指令名、旗標名） | `REAL_01` §1.1／§1.2 寫下 **10 個** | **存在 3 個，其中一個簽名是假的 ⟹ 2½／10**（§1、§1.1） |
| **行為**（引擎說什麼、怎麼結束） | `REAL_01` §1.3 **四條**（2026-08-09 新設） | **兌現 2／4**，兩個缺口收斂到同一台印表機（§2） |
| **形狀**（介面的文法，不含任何名字） | **沒有人寫過** | **F1 指令 9／18、旗標 18／28 全無說明；F2 同一旗標四有四無**（§6） |

⟹ **寫拼法會腐爛，而且已經爛了；寫行為是承重的，而且正在被用；
而形狀這一軸從來沒有被寫過，卻是三者中唯一「改名不會使它變假」的。**

> **⚠ 本文 2026-09-09 初版只有前兩列，且第二列的分母是錯的**
> （§1.3 是四條不是兩條）。**2026-09-12 補量並就地更正**，
> 更正處逐一標記於 §1.1 與 §2。

## 1. 拼法：10 個裡有 7 個是假的

`REAL_01` §1.1／§1.2 逐字寫著：

```bash
oo run --observe <path> [--commit] [--format json|n] [--load <file>]
oo service [--socket <path>] [--host <h>] [--port <p>] [--privileged-token <t>]
```

〔量 2026-09-09，`v0.46.0` 標籤建置，逐個對真二進位問〕

| 拼法 | 在不在 |
| :-- | :-- |
| `oo run` | ✅ |
| `--observe` | ✅ |
| `--format` | ⚠ **拼法在，簽名是假的**——規格寫 `--format json\|n`，而該旗標**不吃值**（見 §1.1） |
| `--port` | ⚠ 在，但在 `oo node serve` 上，不在 `oo service` 上 |
| **`oo service`** | ❌ **實際拼法是 `oo node serve`** |
| **`--commit`** | ❌ |
| **`--load`** | ❌ |
| **`--host`** | ❌ |
| **`--socket`** | ❌ |
| **`--privileged-token`** | ❌ |

**分母 10，存在 3——而其中一個的簽名是假的，故以簽名計為 2½／10。**

### 1.1 ⚠ 就地作廢：`--format` 驗收方第一次記寬了

〔量 2026-09-12，同一顆標籤建置，有對照組〕

```
oo run good.n                →  rc=0        （對照組：這個形式必須成功）
oo run --format json good.n  →  Error: No such file or directory (os error 2)   rc=1
oo run --format good.n       →  rc=0
```

**`json` 被當成檔名吃掉了 ⟹ `--format` 是一個不收值的布林旗標。**
規格逐字寫的是 `--format json|n`。**拼法存在而簽名不存在，是第三種假**，
上表原本記 ✅ 是過寬，**就地更正**。

⟹ 而它報的 `os error 2` 正是 §1.3 第一條未兌現的那個缺陷，
**且在此處額外說了一句假話**：真相是「這個旗標不收值」，它說的是「檔案不見了」。

`commit.md` §1242 早就把這件事寫成一句話：
「**用介面命名一個語義操作，與 `REAL_01` §1 把 CLI 拼法寫進規範性條文是同一個錯。**」
**今天有數字了：那個錯的成本是 70%。**

## 2. 行為：唯一約束行為的那一節，正在承重

`REAL_01` **§1.3**（**2026-08-09 新設**，Core Requirement）**四條**，
不是兩條——**驗收方 2026-09-09 只量了前兩條就寫下「兌現 1／2」，分母是錯的，就地作廢。**
〔補量 2026-09-12，同一顆標籤建置〕

| | 條文 | 今天 |
| :-- | :-- | :-- |
| **(i)** | 不得洩漏實作表示（MUST NOT） | ❌ |
| **(ii)** | 值的正準文字形必須是全函數（MUST） | ✅ |
| **(iii)** | 印出來的必須讀得回去（MUST） | ❌ |
| **(iv)** | 未觀測不是錯誤（MUST NOT） | ✅（三探針皆 rc=0） |

**兌現 2／4。而 (i) 與 (iii) 是同一台印表機的兩個失敗——`_|_` 的列印形。**

*   **(ii) 已兌現。** `Value::to_nlang` 的 Rust Debug fallback **已經不在**
    〔量〕`format!("{:?}", self)` 全檔 **0 命中**，收尾臂是具名的
    （`Value::Code(expr) => expr.to_nlang(indent)`）。
    **⚠ 驗收方第一次量這一格時把測試寫成恆真式**（`[ -n "$(grep -c …)" ]`，
    而 `grep -c` 印 `0` 也是非空字串）**並據此寫下「未兌現」——就地作廢**。
*   **(i) 未兌現，而且逐字**：`oo eval '1 & 2'` →
    `_|_ (%cause: #conflict)  ;; Incompatible types: Atom(Int(1), EffectTag(0), None) vs …`
    ——`Atom(Int(…), EffectTag(…), None)` 是 Rust 的 `Debug`，
    §1.3 逐字禁止「宿主語言的除錯輸出格式」。
*   **(iii) 未兌現，而且錯的不是註解。** 把 `oo eval` 的輸出加上 `v: ` 前綴餵回
    `oo fmt`（對照組：`v: 1` rc=0；壞形式 rc=1，量測確實碰得到目標）：

    | 值形 | 回讀 |
    | :-- | :-- |
    | 記錄／區間／態射／疊加／`%code` 引述 | ✅ 5／5 |
    | **`_|_`** | ❌ |

    失敗位置是**第 15 欄**，即 `(%cause:` ——**不是後面那段 `;;` 註解**。
    亦即 `_|_ (%cause: #conflict)` **這個形式本身不是合法的 n/**。
    而它會沿著記錄往外傳染：`oo eval '{ a: 1, b: 1 & 2 }'` 印出的**整筆記錄**
    因此都讀不回去。
*   **(iv) 三探針未違反**：有限記錄、內建態射（`~%List./len 3` 印出結構而非求值）、
    含 `_|_` 來源的欄位——三者皆 rc=0、皆未中止。**非窮盡，只記為未觀察到違反。**

⟹ **§1.3 今天的缺口收斂到一個點：`_|_` 的列印形。**
它同時是 (i) 的違反者與 (iii) 的違反者，**也是 §5 兩項排序相遇的那個欄位**。

### 2.1 而這一格被記成「加分不列要求」，比 §1.3 早一個月

`ENGINE_SYNC:2259` 逐字：「`message` 仍是 Rust Debug（`Atom(Int(1), EffectTag(0), None)`）；
**工單列為加分不列要求，未做。**」`STATUS` M4 同族。
**兩處都寫於 2026-08-07 前後，而 §1.3 寫於 2026-08-09。**

⟹ **一條 MUST 出生時，沒有人回頭把已經記成「美觀問題」的那一列重新分類。**
這正是 §2.4 存在的理由（規格寫了 MUST 而引擎未兌現，兩處帳都不住），
而 §2.4 自己是 2026-08-13 才補的——**比這一格晚四天**。

### 2.2 §1.3 今天是三件事的依據

*   **Q-002**（本週）——③ 的 stderr 洩漏宿主原始碼路徑，判為引擎的鍋，援引的是同一條。
*   **Q-016b**（v0.45.0）——裸 `os error 2`，`SPEC_10` §2.2.1，§1.3 是它的通則化。
*   **Inbox「`oo evolve nosuch.n` 回裸 errno」**（本週新開）——同一條。

**降掉 §1.3 等於把三個已經在用的論證抽掉。**

## 4. 待裁：三個候選

> **CLI 是不是一個規範性介面？**

*   **甲（分開兩半）**：**行為規範，拼法不規範。**
    `REAL_01` §1.1／§1.2 的拼法降為 Reference 並就地標記 7／10 已失效；
    §1.3 保留為 Core Requirement，**且明說它拘束的是「面向操作者的輸出」
    這個概念，不是 `oo` 這個程式**。日後行為規則優先住在它所屬的軸
    （`TAG_REGISTRY` §0.2 為先例），`REAL_01` 只收「沒有別的家」的那些。
    **後果**：SIGPIPE 那列變成「一個邊界事件的載體是什麼」——回到 §0.2；
    `init` 的形狀變成弧 D 第 2 項的語義問題，與拼法脫鉤；
    O84 的候選丙**自動出局**（它問的是要不要寫進 CLI 介面契約，而契約不寫拼法）。
*   **乙（整章規範化）**：拼法也入憲。
    **代價已量**：先修那 7 個，且此後每一次 CLI 改名都是破壞性條目。
    〔對照〕`oo node serve` 這個拼法本身就是 2026-07-27 之後改的。
*   **丙（整章降為 Reference）**：連 §1.3 一起降。
    **不推薦**——見 §2.2，它是三個現行論證的依據。

**驗收方推薦甲。** 理由是兩個數字：**拼法 3／10**（寫了會爛，而且爛了）
與 **§1.3 1／2**（寫了有用，而且在用）。甲不是折衷，是**照著證據把一節切開**。

## 5. ⚠ 一件會改變排序性價比的事（不改變排序本身）

**排序第 1 項與第 2 項在同一個欄位上相遇。**

*   第 1 項（本文）量到 §1.3 未兌現的那一半，逐字是 **`_|_` 的 `message`**。
*   第 2 項（`message` 不在自己的 CAID 之內）說的是**同一個 `message`**。

一個說**它的內容洩漏宿主**，一個說**它的位元組不在自己的位址承諾裡**。
⟹ **兩者是同一條免費文字通道的兩面**，而那條通道沒有人設計過它。

**這不推翻已裁的排序**（1 → 2 → 3 仍然成立，且第 1 項本來就該先）。
它說的是：**第 1 項收尾時若順手把 `message` 的形狀定下來，第 2 項會便宜很多**
——而反過來不成立（先動 CAID 是紀元，先定形狀不是）。
**是否合併，開單時再判，本文不預判。**

## 6. 第三軸：形狀（2026-09-12 補，用戶追問後量）

> 用戶追問：「拼法不規範的地方，我再想要不要做點最低限度的規範，
> 而不是完全不管；還是你覺得這比較算行為？」

### 6.1 判別法（可重複使用）

> **一條規則會不會因為改名而變假？**

*   「`oo service` 有 `--socket`」——**改名就變假**。這是**機制**。
*   「同一個旗標在每個指令必須有同一個簽名」——**改名不會變假，只會被違反**。
    這是**不變式**。

⟹ 這是**「射程要寫不變式不是機制」在介面上的形狀**。
**甲 禁止的不是「寫 CLI」，是「寫個案」**；形狀不是個案。
§0 初版把「拼法」整袋丟掉，**丟過頭了**。

### 6.2 兩條今天就能寫、且零拼法的不變式

〔量 2026-09-12，`v0.46.0` 標籤建置。計數以腳本剖析 `--help` 產生，
**兩次獨立計數（手數與腳本）相符**；腳本第一版漏算對齊縮排的長旗標、
第二版把可變引數的 `...` 誤判為說明，兩處皆已修正後複數。〕

| | 不變式 | 今天的分母 |
| :-- | :-- | :-- |
| **F1** | 每個指令、旗標、位置引數**必須**有一句面向操作者的說明 | 〔頂層〕指令 **9／18**（`run` `evolve` `test` `repl` `status` `log` `commit` `refine` `fmt`）、旗標 **18／28**、位置引數 **4／9**<br>**〔走遍整個指令樹，2026-09-12 武裝探針時複量〕指令 9／29、旗標 19／37、位置引數 6／11** |
| **F2** | 同一個概念**必須**只有一個拼法、一個簽名、一份說明——跨指令一致 | 出現於一個以上指令的長旗標 **5 個，4 個不一致**：`--grant` 8 處 4 有 4 無、`--privileged` 7 處 3 有 4 無（無說明者同為 `rollback`／`squash`／`gc`／`migrate`）、`--to` 3 處 2 有 1 無、`--target` 3 處 2 有 1 無 |

**F2 就是「一個概念一種正準拼法」從文法搬到介面。**

**⚠ 武裝探針時量到一件 F2 說不到的事**：`--target` 出現在三個指令上，
而它是**三個不同的概念**（`refine` 的精煉標的／`node discover` 的服務 CAID／
`node find-node` 的 160 位元節點 id）。
F2 的條文是「**同一個概念**必須同一份說明」，**沒有說不同概念不得共用拼法**。
⟹ **探針不得斷言它**——斷言它等於偷偷把條文改強。改列為工單必答題。
**這一格自己就是「射程要寫不變式不是機制」的案例**：
「同一個旗標必須有同一份說明」是機制，會誤判同形異義；
「一個概念一種拼法」是不變式，而**它的反面（一個拼法一個概念）今天沒有人寫過**。

**F1 不是新軸——它是 §1.3。** `--help` 是**面向操作者的輸出**；
一個指令對操作者**什麼都不說**，與它**用 Rust `Debug` 說**，
是同一條誠實性軸上的兩個失敗。故 F1 **不另立家，作為 §1.3 的新增條**。

### 6.3 F3（`oo node serve` 那一條）今天還不能寫

想寫的是：**指令的對象若有顯式身分，對象出現在動作之前。**
〔量〕頂層 18 個 ＝ **12 個動詞 ＋ 5 個名詞葉子**（`repl` `status` `log` `gc` `identity`）
**＋ 1 個對象空間**（`node`，其下 8 個子指令；`node trust` 再下一層，故存在三層分支）。

**那 5 個名詞葉子全部作用於同一個對象——當前工作區——而該對象在拼法裡是隱含的。**
`node` 之所以是唯一顯式者，因為它是唯一有顯式身分的東西。

⟹ **F3 的內容取決於「工作區是不是一個要說出名字的對象」，
而那正是弧 D 第 2 項（`init` 的形狀）。** 現在寫 F3 等於在那一題之前先押注。
**F3 掛在弧 D 第 2 項之後，本次不寫。**

### 6.4 用戶舉的兩個例子分別落在哪

*   **`oo serve` → `oo node serve`**：形狀，屬 F3 ⟹ **同樣在等弧 D 第 2 項**。
    那次改名其實**提前實施了一條還沒裁的規則**。
*   **`oo commit xxx` vs `oo run --commit`**：**不是 CLI 題。**
    兩者作用於同一個隱含對象（工作區），問的是「**工作區有幾個動作**」——語義題。
    〔量〕`oo commit` **已經是頂層指令且存在**；不存在的是 `run --commit` 這個旗標
    ——**引擎早就替這一題投了票，而規格還寫著另一個答案**（§1）。
    ⟹ 用戶說「往下推就跟乙在做一樣的動作」；**量到的是相反方向**：
    往下推會推**出** `REAL_01`，不是推進去（`TAG_REGISTRY` §0.2／D63 先例，§3）。

### 6.5 裁定：甲′（2026-09-12，用戶原話「嗯 甲′」）

**甲，外加一節極小的規範性形狀約束，該節不得出現任何指令名或旗標名。**

1.  §1.1／§1.2 的拼法 → **Reference**，就地標記 **2½／10** 的實況；
2.  §1.3 **保留為 Core Requirement**，**新增一條 ＝ F1**；
3.  **新設 §1.4「介面形狀（規範性）」，今日只收 F2**；
4.  **F3 記為弧 D 第 2 項的相依，本次不寫。**

**甲′ 不是往乙滑。** 乙的成本來自「寫了名字就要維護名字」，
而 **F1／F2 一個名字都沒寫**。
