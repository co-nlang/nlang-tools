## 1. 缺陷

### 1.1 五個旋鈕不做事(兩點法,2026-08-09)

每個旋鈕都用**同一份輸入、兩個旗鼓相當的值**量,看門檻是否移動。
**只設一個值而「沒事發生」不算量測**——那分不出「旋鈕無效」與「輸入沒碰到那道閘」。

| 旋鈕 | 暫存後讀得回 | 生效 | 證據 |
| :-- | :-- | :-- | :-- |
| `fuel` | ✓ | **✓** | `5` → `#fuel_exhausted`;`100000` → `_` |
| `strategy` | ✓ | **✓** | 同輸入:`#strict` → `_\|_`;`#blur` → `#blur` |
| **`timeout`** | ✓ | **✗** | `timeout: 1`(毫秒)之下,一個 **2286 ms** 的運算**正常跑完** |
| **`max_branches`** | ✓ | **✗** | 上限 `2`,分支算術 **11 支全部存活**(這就是 `eval.rs:2043` 那道閘) |
| **`max_unification_depth`** | ✓ | **✗** | 二分臨界**恆為 256**(＝預設值);旋鈕設 8／64／256／4000 **皆不動** |
| `max_lifting_depth` | ✓ | **✗** | **全樹從未被讀**——**O39 已裁:不在本弧**(§3) |
| `max_pattern_nodes` | ✓ | **✗** | 同上 |

### 1.2 七個旋鈕一個都提交不了

```
~%Config.fuel: 7            → evolve ok,commit: Error: Commit failed
~%Config.strategy: #strict  → evolve ok,commit: Error: Commit failed
~%Config.max_branches: 8    → evolve ok,commit: Error: Commit failed
x: 1                        → commit 成功              ← 控制
```

**視界參數只能活在暫存區,活不過一次提交。**

## 2. 裁定(用戶已批 2026-08-09)

### O37｜視界參數**不進歷史**

理由(用戶):**要保存視界參數的唯一條件是 CAID 一致性,而那已經記在 CAID 裡**
——SPEC_08 §3.2.1 明文要求 `#blur` 的 CAID **必須**包含視界參數。
使用者若真要提交,**自己觀測出來再存到別的欄位**。

**落地形式取 (b) 而非 (a)**(驗收方判斷,用戶已批):

* (a) 有 `~%Config` 就整次 commit 失敗
* **(b) commit 照常進行,`~%Config` 留在暫存區不進去,並明說它沒被提交** ← **採此**

理由:一份檔案裡同時有 `~%Config.fuel: 7` 與 `x: 1` 時,(a) 會讓一個普通寫入
**因為跟旋鈕同檔而被連坐**。「不進歷史」說的是它**不是歷史**,不是它**會毀掉歷史**。

**「明說」不可省**——靜默丟棄踩到 D36 那條線的反面:
**沒有義務可以靜默,有東西被丟掉不行。**

### O38｜直接修,不設過渡

用戶已批。**五個旋鈕從未生效過,不可能有人依賴它們的失效。**

### O39｜`max_lifting_depth`／`max_pattern_nodes` 不廢止,掛帳之後實作

用戶理由:廢止前要先論證「當初的設計沒有必要」,而那個論證沒有做;
引擎本來就還有許多未實作項。**⟹ 不在本弧射程。** 已記入 ENGINE_SYNC。

### 11.6 一條被自己的後續量測推翻的驗收結論(2026-08-09,同日更正)

**§11.5 的 (b) 是錯的,在此撤回。**

原文說「磁碟上的 `~%Config` 在新行程不生效」,依據是:暫存 `~%Config.fuel: 7`,

重測(2026-08-09,v0.15.0):

| 量測 | 結果 |
| :-- | :-- |
| 暫存 `~%Config.max_unification_depth: 8`,**新行程** `oo evolve` 一條 200 項的加法鏈 | **`#blur { %cause: #max_depth_exceeded }`** ⟹ **旋鈕跨行程生效** |

**我用一個看不見倉的指令去證明「倉裡的東西不生效」,而那個指令對任何倉裡的東西

〔同型的錯誤本弧已犯過一次:§11.4 的「一個旋鈕一個 fixture」。
