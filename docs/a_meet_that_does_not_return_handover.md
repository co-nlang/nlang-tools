## 0. 判準（規格原文）

*   **`SPEC_07` §5.3 定義 1**：兩個態射合併（$f \sqcap g$），語義是一個同時滿足兩者映射規則的新態射；施用時答兩者回答的交會——`((x -> 1) & (x -> 2)) 0` 是 ⊥，`((x -> x + 1) & (x -> x + 1)) 1` 是 `2`。
*   **D105**：兩個態射交會成一張表（定義合併）。內建是態射（`is_morphism_combo` 認 `%builtin`）。
*   **D117**：同一分支的兩個**值**分支體當下交會（交會一個值不是求值它）；延後的分支體留在集合裡，等分派選中才跑。任何分組與順序都是同一組位元組。
*   **`SPEC_12` §2.1**：`&` 是交會——結合、交換。
*   **Q-103 的不變式**：一檔、兩次演化、兩次提交同讀數、同根。

## 1. 缺陷

〔量，`v0.110.0` 標籤建置；eval 在空目錄，每個行程 1 GB 位址空間上限、逾時即殺；`acc/q110/sweep.py`〕

*   **不終止，吃記憶體**：`(~%Math./add (1)) & (~%Math./add (2))`、`(~%Math./add) & (~%Math./sub)`、`(~%Str./repeat ("a")) & (~%Str./repeat ("b"))` 都不返回；`add` 那格 4 秒長到 136 MB（約 34 MB／秒），沒有上限就把機器吃光（驗收方的背景任務兩度因此被中止）。同形換成箭頭 `(x -> x + 1) & (x -> x + 2)` 立即答一個態射。同一個內建同引數 `(~%Math./add (1)) & (~%Math./add (1))` 立即返回。
*   **登錄表全掃**：每一個內建與另一個內建交會，**154／187** 個拼法不返回；同一個內建兩個不同引數的部分施用交會，**97／186** 不返回。
*   **倉裡崩潰**：`f: ~%Math./add (1)` 再寫 `f: ~%Math./add (2)`——一檔的 `evolve` 與兩次提交的第二次 `commit` 以 Aborted（堆疊溢位）結束；兩次演化的第二次 `evolve` 也崩；記錄 eval 的交會 `({ f: … } & { f: … }).f 3` 答 `#blur` `#fuel_exhausted`。`f: ~%Math./add` 再寫 `f: ~%Math./mul` 同。
*   〔讀〕D105 的 `meet_as_tables`（`dispatch.rs`）把內建轉成一張表，那張表 `_` 分支的**分支體就是那個內建本身**（`as_table_morphism` 的 `%builtin` 臂，以值存）。兩張表交會 ⟹ `join_branches` ⟹ `meet_value_bodies` 照 D117 把兩個值分支體當下交會 ⟹ 又是兩個內建交會 ⟹ 又進 `meet_as_tables`。箭頭的分支體是 `%code`（延後），不會回到這裡。

## 2. 依據；位址

*   **不須裁**：`SPEC_07` §5.3 寫好了答案，箭頭已經照做。內建的分支體在分支被選中時施用（E2：常值規則的 `%val` 是態射就施用到引數上），所以它跟 `%code` 一樣是「選中才跑」的東西——兩個內建交會就是一張兩個分支體都在的表，施用時各自施用、回答交會。
*   **位址**：只有今天不返回或崩潰的格子有新根（它們以前沒有根）；**今天交會得出來的根一顆都不動**（g1 七顆，v0.110.0 釘）。不是破壞性變更；收尾時記 `CHANGELOG` 的「修正」。

## 3. 射程＝不變式（不是機制）

*   **M1 每一個交會都返回**：兩個態射交會，至少一邊是內建——不同的內建、同一內建不同引數、內建與箭頭、內建與表的分支、記錄欄位裡的內建、三個以上——都在有限時間內返回，不崩潰（r1、r4：登錄表裡每一個內建）。
*   **M2 施用答兩者回答的交會**：同答者答那個值（`((~%Math./add) & (~%Math./mul)) (2, 2)` ⟹ `4`），不同答者 ⊥ `#conflict`（r1）。
*   **M3 交會結合、交換**：同樣的態射，每種排列與分組印出同一個值（r2）。
*   **M4 三條路**：寫在同一座標，一檔、兩次演化、兩次提交都返回、同讀數、同根（r3）。
*   **另一半——今天交會得出來的照舊**（g1）：態射與自己交會就是自己（`(~%Math./abs) & (~%Math./abs)` 與 `~%Math./abs` 同印出形）；同一分支的值分支體照舊當下交會（D117：`({ @{ _ }: 5 } & { @{ _ }: 6 }) 0` ⊥）；**箭頭分支體照舊當下交會**（`t: { @{ _ }: (x -> x) } & { @{ _ }: (x -> x + 1) }` 根不動）；內建分支體與值分支體並存時一起回答；態射 × 原子 ⊥；七顆根不動。
*   若你找到另一條會回到同一個交會的路（別的分支體形狀、別的態射種類、`normalize_table` 那條入口），一併在射程內，在 8.1 列出。

## 5. 必答（請在交付報告裡回答，逐題）

*   **Q1 終止**：你怎麼論證每一個交會都返回——是哪一個量在每次遞迴時變小，還是哪一條路不再遞迴。

*   **Q3 施用**：一個分支有幾個分支體時，分派怎麼逐一施用、怎麼交會回答；三個以上的順序會不會影響印出形或衝突訊息。
