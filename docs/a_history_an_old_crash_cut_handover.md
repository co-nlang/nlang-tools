## 1. 缺陷

v0.41.0 … v0.67.0 的每一版提交時都**先移 `HEAD`、後寫提交 ○**〔量，strace，各標籤建置；v0.68.0 起相反〕。D52 之後一筆提交的祖先只記在它的提交 ○ 上，所以在那個窗裡崩潰 ⟹ `HEAD` 停在一筆沒有 ○ 的提交，從 `HEAD` 的走訪在那裡斷掉。〔量，v0.68.0，以「正常操作後拿掉崩潰時尚未寫下的那顆 ○」重構〕：

| | 狀態 | 今天 |
| :-- | :-- | :-- |
| **r1** | 切點在 `HEAD` | `gc` rc=0，**刪掉切點之前的提交**；對照組（不拿掉）0 刪 |
| **r2** | 同上，`--dry-run` | rc=0，把切點之前的歷史報成可回收 |
| **r3** | 殘留之上又提交了（切點埋在中間） | 同 r1：`HEAD` 這筆有 ○，斷在下一筆 |
| **r4** | squash 留下的同一窗 | 同 r1 |
| **r5** | refine 留下的同一窗 | 同 r1 |

## 2. 裁定與依據

*   **D85（用戶，甲）**：從 `HEAD` 沿祖先走，遇到一筆**新式（值定址）提交而沒有任何 ○ 宣告它是提交**，即為歷史被切斷的證據；`#gc` 在刪除任何東西之前**具名拒絕**，並**點名那筆提交**。
*   **為何沒有無辜的讀法**：新式提交自 v0.59.0 起才有，而那之後每一版對每一筆提交（含 squash、refine）都寫提交 ○。
*   **舊式提交不判（已知留白）**：v0.41–v0.58 期間的殘留與 D52 之前的創世提交同形，只能靠內容或時間分開（D81、D55 已排除）；拒絕它們會擋住每一個正當升級的舊倉（g5／g6 守這一邊）。
*   **「被 ○ 宣告而 `HEAD` 到不了」不是證據**：squash 正當地造出它（g2）。
*   **依據同 D79／D81**：丟了的祖先不是沒有祖先；證據是儲存自己寫下的形（提交的定址形式與 ○ 上的提交註記），不是內容。

## 3. 射程＝不變式（不是機制）

*   **I1** **從 `HEAD` 沿祖先走到的任何一筆新式提交，若沒有 ○ 宣告它，`gc` 不刪任何東西**——含 `--dry-run`（它不得把切點之前的歷史報成可回收）；rc≠0；`.oo/` 一個位元組都不變；輸出含那筆提交的摘要（r1–r5）。
*   **I2** **判的是這段歷史，不是整個儲存**：走訪從 `HEAD` 起、沿祖先。被 rollback 越過的分支上的切點不使 `gc` 拒絕，即使回收時為了報告放棄內容而走到它（g4）。
*   **I3** **沒有無辜的倉被拒絕**：完整的倉照常回收（g1）；squash 與 rollback 留下的照常回收（g2、g3）；六個真實舊版倉，原樣、續提交、遷移後再提交，`gc` 皆照常（g5、g6）。
*   **I4** **判準本身不得把讀不到讀成沒有**（`SPEC_08` §6.2.1 既有 MUST）：判斷時讀不到 ○ 目錄或提交物件，具名拒絕，不得當成「沒有 ○ 宣告它」或「它不是新式」。
*   **I5** **不修補**：不得補寫缺掉的 ○、不得推斷切點的祖先（D55：祖先不得由時間或到達順序導出；D81：不得事後補造 ○ 註記）。不新增耐久檔、不改磁碟格式、不推進佈局；值位址與提交位址不動。
