# 工單：展開還沒落地就被讀的表（Q-084）

> 佇列 `nlang-spec/meta/WORK_QUEUE.md` Q-084（原 Inbox「展開來的表放進欄位、提交後不分派——`=` 卻判它等於直接寫的表」）／**不需新裁定**／依據 D101（一張表一個正規形，不論怎麼寫成）、D97（有模式鍵的 Combo 是表；沒有模式鍵的依鍵查找）、`SPEC_03` §3.1（展開）、`SPEC_07` §4（`|>` 右邊是態射就施用、是 Combo 就合併）
> 探針（已預先提交並校準）`crates/oo/tests/a_table_read_before_its_spread_landed_probe_test.rs`
> 基線：dev `2a6427b`／`oo v0.85.0` ⟹ **2 綠 8 紅**；八支紅的都紅在一般斷言，零空洞讀數。

## 1. 缺陷

〔量，v0.85.0；v0.75.0 起逐版相同〕用展開寫成的表，**放進欄位就答錯**；寫在頂層照常：

*   `{ t: { ...{ @{ @int }: 1 }, _: 0 } }.t 7` ⟹ `0`（應 `1`）；頂層 `{ ...{ @{ @int }: 1 }, _: 0 } 7` ⟹ `1`。
*   提交後同：`k: { t: { ...{ @{ @int }: 1 }, _: 0 } }` 的 `_.k.t 7` ⟹ `0`；深度 2、展開來源是兄弟名字（寫在前或後）、提交後的兄弟皆同。
*   沒有模式鍵的表（依鍵查找，D97）：`{ t: { ...{ b: 1 }, _: 0 } }.t "b"` ⟹ `0`；`{ t: { ...{ b: 1 } } }.t "b"` ⟹ `#no_matching_branch`。
*   展開與寫出的模式鍵並列：`{ t: { ...{ @{ @int }: 1 }, @{ @str }: 2 } }.t 7` ⟹ `#no_matching_branch`。
*   分支的值是箭頭：`{ t: { ...{ @{ @int }: (x -> x * 10) }, _: 0 } }.t 7` ⟹ `0`（應 `70`）。
*   **它選錯的那一支會被執行**：`_:` 那一支是 `~%Io./write_file ("p.txt", "x")` 時，`.t 7` 寫出了 `p.txt`。
*   **管道，連頂層都錯**：`7 |> { ...{ @{ @int }: 1 }, _: 0 }` ⟹ ⊥ `#conflict`（直接寫的表 ⟹ `1`）；`7 |> { t: { … } }.t` 同。
*   而 `=`（`.t = { @{ @int }: 1, _: 0 }` ⟹ `#true`）、印出（`{ @{ @int }: 1 _: 0 }`）、導航（`{ t: { ...{ b: 1 } } }.t.b` ⟹ `1`）、`&`、`|`、以聯集為引數——**全對**。**只有施用與管道錯，而且錯得安靜。**

〔讀〕成因是一類，有兩個實例：**在展開落地之前，就讀了這個 Combo 是不是表、是不是態射。**

*   `crates/interpreter/src/lib.rs` `force`：值本身是 Combo 時，帶著待落地的展開（`pending_spreads`）就先 `expand_combo_pending`（它結尾會 `normalize_table`）；**值是 thunk 時，求值後直接回傳**——回傳的 Combo 展開還沒落地。欄位裡的 Combo 以 thunk 存（GUIDE_03 §11.4），所以 `.t` 拿到的是 thunk，施用時 `force` 給出的是一張只有 `_:` 的表。
*   `crates/interpreter/src/eval.rs` `pipe_apply`：右邊只把 thunk 剝掉，**沒有讓展開落地就問 `is_morphism()`**；一個字面上帶展開的表此刻還沒有 `%rules`／`%morphism`，於是被當成 Combo 去合併（`7 & {…}` ⟹ `#conflict`）。

## 2. 裁定與依據

*   **不需新裁定**：D101 已規定一張表一個正規形——怎麼寫成都是同一張表；D97 已規定有模式鍵的是表；`SPEC_07` §4 已規定 `|>` 右邊是態射就施用。`=` 判兩者相等而施用給兩個答案，是**引擎的鍋**：任何照規格寫的實作都不會在展開落地之前讀表。
*   位址：表本身以 thunk（源碼的節點表）存，**不因本卡移動**（g2）。**存下了「施用這種表的結果」的根會移動**——那些根存的答案本來就是錯的（§5 Q2）。

## 3. 射程＝不變式（不是機制）

*   **I1 一張表怎麼寫成、住在哪裡，都答一樣的話**：直接寫、展開一個字面、展開一個名字（在前、在後）；頂層、欄位、欄位的欄位、提交後；有模式鍵的表與依鍵查找的表；分支值是原子或箭頭——對每一個輸入，答案與直接寫在頂層的同一張表相同（r1–r5、r8）。
*   **I2 兩個入口都如此**：施用與 `|>`（r6）。若你找到第三個「讀一個 Combo 是不是表／態射」的入口有同樣的問題（本卡偵察量過 `&`、`|`、`=`、導航、印出、以聯集為引數，皆對），一併在射程內，並在 8.1 列出。**「展開落地之後才讀它的形」是要守的不變式；修那兩處只是一種機制。**
*   **I3 沒被選中的分支不執行**（r7）。
*   **I4 `|>` 右邊是一般 Combo 時照舊合併**（g1）。
*   **I5 表本身的位址不動**（g2）；不改磁碟格式（新倉仍 `layout=9`／`encoding=6`）。
