# 偵察：一個看運氣的位址

> 2026-08-20。起因：v0.27.0 驗收時 `name_points_at_remedy::p2_fuel_blur_caid_holds`
> 間歇紅，判別實驗證實**既有**（弧前樹 12 跑紅 7 次）。
> 本檔記錄它**不是 flaky test**。

---

## 1. 一句話

**一個含 fuel 受限 `#blur` 的程式，提交到不可重現的位址。**

---

## 2. 量測

〔量，v0.27.0，`~%Config.fuel: 5` ＋ `v: <<_.>>`〕

| 觀測 | 結果 |
| :--- | :--- |
| 同一程式、20 個新行程、觀測 blur 的 `%caid` | **兩種**：`de65bce3…` ×11／`41201939…` ×9 |
| 同一程式、20 個**全新倉**、提交後的**根位址** | **兩種**：`40503c60…` ×12／`158ddda8…` ×8 |

⟹ **不決定性進入耐久身分**，不只是觀測面。

### 2.1 兩種輸出差在哪

〔量〕去掉 CAID 後比對，差異是 **blur 落在哪一個欄位上**：

```
run A:   out: #blur { %cause: #fuel_exhausted, … }    v: { … }
run B:   out: { … }                                    v: #blur { %cause: … }
```

**內容不同**（所以位址不同是誠實的），而**內容為何不同才是缺陷**：
fuel 是全域預算，耗盡點取決於**求值順序**，而該順序在行程間不決定。

---

## 3. 這違反的是哪一條

REAL_03 §6.7 第一條 MUST 逐字：

> **位元組為值之函數（MUST）**：……兩次寫入同一個值——同一行程、**不同行程**、
> 不同機器——**必須**產生逐位元組相同的物件。

同節第三條的理由已經指名了同一個病根，只是指向另一個地點：

> **序必須是正準的（MUST）**：任何映射型結構的鍵序**必須**由內容決定，
> **不得**取自**行程內的雜湊表迭代序**、插入序或任何與該值無關的來源。

⟹ 該條治**序列化**的鍵序；本項是**求值**的順序。
**同一個病根、不同的地點**——而 fuel 把它從「看不見的內部細節」放大成「位址」。

### 3.1 與已關閉的三個 §6.7 案例不同族，而且更重

| | 形狀 |
| :--- | :--- |
| span（v0.19.0 判例） | 欄位不進雜湊 ⟹ **同址不同位元組** |
| 標準根併入（v0.21.0） | 內容過多 ⟹ 可重現性受損 |
| `%effect` 兩個家（v0.26.0） | 欄位不進雜湊 ⟹ **同址不同值** |
| **本項** | **同值不同址，且不決定** |

前三者皆為**決定性**的錯（覆蓋不足或內容過多），**修完位址就固定**。
本項是**不決定**——**同一份輸入在同一台機器上今天給 A、明天給 B**。

---

## 4. 為何一直沒被抓到

*   它偽裝成 **flaky test**。該測試被歸入「間歇」桶，與 `advert_persistence`
    那個負載敏感的間歇放在一起——**但成因不同**：本項與負載無關，
    〔量〕隔離重跑 12 次仍紅 4 次。
*   `p2` 的兩個斷言中，**承重的那個**（「同一份程式在每個行程都必須定址到同一個
    blur」）**寫得很清楚**，而它紅的時候看起來只是「又一個 flake」。
*   Q-032 工單 §6.5 曾列一個未量項：「**`#blur` 的 CAID 是否真的含視界參數**
    （SPEC_08 §3.2.1 要求）；若不成立，視界參數在身分裡沒有任何家」
    ——**當時未能構造出 blur**。本項可能就是那一格的另一面。

---

## 5. 量測結果（原「未量」四項，2026-08-20 已做）

### 5.1 不決定性的來源：**多欄位的求值順序**，逐行程隨機

〔量〕

| 條件 | 結果 |
| :--- | :--- |
| **一個**頂層欄位 | **12／12 同一個 CAID——穩定** |
| **兩個**欄位 | 兩種 CAID，約 50／50 |
| **三個**欄位 | **仍只有兩種**（4／14）⟹ 不是 N 個欄位的排列 |
| 兩個獨立行程比對 | 6 次中 3 次不同 ⟹ **逐行程隨機** |

〔讀〕**crate 內無平行**（`Cargo.toml` 無 rayon／crossbeam／dashmap）⟹ 不是執行緒。

**候選源**：Rust 的 `HashMap`／`HashSet` **預設 hasher 逐行程隨機播種**，任何對其迭代
即為逐行程隨機序。求值路徑上至少有
`EvalContext::dep_collector: Option<HashSet<String>>`（`lib.rs:148`，於 `:3381` 被迭代）
以及 `force_memo`／`force_memo_rev`／`unify_memo`（`lib.rs:745–748`）。
**確切行號由施工方定位**——本偵察只把範圍收到「多欄位求值順序」。

⚠ REAL_03 §6.7 第三條 MUST 已為**序列化**鍵序禁止此來源；本項是**求值**順序，同族。

### 5.2 fuel 是放大鏡不是成因

〔量〕一個欄位時即使 fuel 受限也穩定（§5.1）⟹ 順序不決定**本來就在**，
fuel 只是把它從「內部細節」變成「哪一個欄位是 blur」，再變成位址。

### 5.3 `fuel_remaining` 在兩處被說成不同的東西（潛伏，本次未咬人）

〔讀〕`value.rs:1728` `encode_chs` 的註解與實作皆**排除** `fuel_remaining`（正確，O42：
CHS 取條件不取讀數）；`value.rs:791` 亦逐字「NEVER fuel_remaining (a reading)」。
**而 `bn_serial.rs:144` 把它寫進位元組流**，註解自稱「Preserve runtime payload
for reconstruct (**not identity**)」。

〔量〕本次**未觀察到它造成額外變異**——形狀與 CAID 為 **1:1**（11 blur=out ↔ `de65bce3…`，
13 blur=v ↔ `41201939…`）⟹ 只有一個變異源。
**但兩處對「什麼算身分」的說法不一致，須裁**：若該位元組流參與物件位址，
則一個**讀數**進了身分，與 O42 同族。

### 5.4 **提交一個引用根的宇宙會使倉永久不可讀** ← 本偵察最重的發現

〔量〕`v: <<_.>>` 提交後：

```
Commit successful
$ oo status → Error: #object_undecodable: object present for hash:…:40503c60…
              but cannot be decoded (integrity unknown): recursion limit exceeded
$ oo log    → 同上          $ oo evolve/commit → 同上
```

**寫入回報成功，而寫下它的引擎從此讀不了那個倉。** 隔離：

| 源碼 | commit | status |
| :--- | :--- | :--- |
| `v: <<_.>>` ＋ fuel 受限 | ✅ 成功 | ❌ `#object_undecodable` |
| `v: <<_.>>` **無 fuel 限制** | ✅ 成功 | ❌ `#object_undecodable` |
| `v: <<f>>`（非自我引用） | ✅ | ✅ |
| blur 但無自我引用 | ✅ | ✅ |
| 普通提交（控制組） | ✅ | ✅ |

⟹ **成因是「引用根」，與 blur 無關、與 fuel 無關。** 這是與 §2 **獨立的第二個缺陷**，
且更重：**靜默的資料遺失**。

**與本專案反覆出現的那一族同形**：寫入報成功、讀取失敗
——Q-029／Q-031「持有但打不開」、v0.26.1「寫得進身分、讀不回來」。

## 6. 建議

**升 Ready，且排在耐久主線之前。本弧含兩個獨立缺陷，建議同弧但分別看守。**

| | 缺陷 | 嚴重度 |
| :-- | :--- | :--- |
| **A** | **提交引用根的宇宙 ⟹ 倉永久不可讀**（§5.4） | **資料遺失**，靜默，與 fuel／blur 無關 |
| **B** | **多欄位求值順序逐行程隨機 ⟹ 位址不決定**（§2、§5.1） | **身分**，已進耐久儲存，靜默 |

A 更急（毀倉），B 更深（§6.7 第一條 MUST 在最壞方向上不成立——
**不是覆蓋不足，是同一個值今天一個位址、明天另一個**）。
二者皆為「寫入報成功、讀取失敗／不一致」那一族。

**待裁**：§5.3 的 `fuel_remaining` 是否參與物件位址（兩處說法不一致）。

**不得以重試或放寬斷言處理**（`WORK_QUEUE` 對 `advert_persistence` 已賺過這條：
「一個會偶發的閘教讀者去重跑而不是去看」）。
