# A port you did not bind — 工單

> Queue ID **Q-026**。基線：引擎 `v0.23.0`（`aa8a119`）。
> **本弧不需要新裁定**——缺陷已量定，修法方向由量測決定。偵察併入本檔 §1。
>
> **明確不做**：`free_port()` 之外的測試重構；OODP 協定面；`--port` 的預設值（維持 8080）。

---

## 1. 量到的（偵察）

### 1.1 引擎報告的是它**被要求**的埠，不是它**綁到**的埠

〔量 2026-08-15，v0.23.0〕`oo node serve --port 0` **綁得起來**（OS 選一個），
而橫幅印的是：

```
n/ OODP node serving at port 0 (node hash:sha256:v2:…)
```

同一時刻由 `/proc/<pid>/fd` 的 socket inode 反查 `/proc/net/tcp`：**實際綁在 40707**。

`crates/oo/src/main.rs:506` 綁 `0.0.0.0:{port}`，`:509` 印的是**傳進來的 `port`**。
⟹ **唯一告訴你節點在哪的那一行，在 OS 選埠時是假的。**
這與 `.oo/format` 同族：**標記報告的不是它量的東西**。

### 1.2 那行橫幅已經是契約

〔量〕`crates/oo/tests/a_limit_you_cannot_catch_probe_test.rs:216` 已在等
`serving at port` 這個字串才認定節點起來了。**它今天讀到的數字是假的**，
只是它剛好只用來判斷「起來了沒」，沒有用那個數字去連線。

### 1.3 測試因此得自己猜埠，而猜法問錯了問題

14 個測試檔各有一份 `free_port()`：綁 `127.0.0.1:0` 取號、**放掉 listener**、
把裸號碼交給子行程去綁 `0.0.0.0:{port}`。

**〔量〕原本記載的「TOCTOU 空窗」不足以解釋失敗**：把該空窗隔離出來，
14 行程 × 200 次 × 空窗 0.5／5／50 ms 三檔，**2800 次綁定 0 次 EADDRINUSE**
（Linux 的 ephemeral port 是輪替配發的）。實測成立的是另外兩個：

*   **H1**：探測問的是 `127.0.0.1:0`，子行程綁的是 `0.0.0.0:{port}`——**不是同一個問題**。
    〔量〕某行程持有 `127.0.0.1:P` 時，`0.0.0.0:P` 得 `EADDRINUSE`。
    ⟹ **碰撞對手不必是另一支測試**，機器上任何持有該埠的行程都算。
    **這解釋了為何單獨重跑從未重現**（Q-010b 12 次、Q-025 3 次，皆 0 次）。
*   **H2**：`std::net::TcpListener::bind` **不設 `SO_REUSEADDR`**，TIME_WAIT 的埠拒絕重綁〔量〕。

〔量〕該缺陷**已發生兩次，在兩個不同的檔案**（Q-010b `kademlia_table`、
Q-025 `affiliation_claim`），且**會中止整輪全跑**——Q-025 開單前的全跑即停在該處，
只跑到 150 個 suite 並給出一個**看起來完全正常的假計數**（1397/0/0，真值 1919/0/2 / 195 suites）。

### 1.4 14 份不是同一份

〔量〕`free_port()` 14 份、**10 種逐字不同**；`serve()` **11 種形狀**；
一個檔（`peer_fetch_verification`）**根本沒有 `serve()`**；各檔呼叫 `free_port()` 2–4 次。
〔量〕`crates/oo/tests/` 底下**沒有任何共用模組**（無 `common/`、無 `mod` 宣告）。

## 2. 主張

**一個節點必須報告它實際綁到的埠。** 而測試不該猜埠——它該問節點。

---

## 3. 射程（三項）

### 3.1 橫幅必須報告實得埠

`run_serve` 綁完之後由 `listener.local_addr()?.port()` 取實得埠，**印那一個**。
`--port 0` 因此成為有意義的用法：由 OS 選，由橫幅報告。

**不得改動橫幅前綴** `n/ OODP node serving at port `——§1.2 已有消費者。
改的只有那個數字。**`--port` 的預設值不動（8080）。**

### 3.2 測試改為問節點，並收成一份

刪除全部 14 份 `free_port()`。測試以 `--port 0` 啟動，**從 serve log 讀回實得埠**。
埠策略收進**一個**共用助手：`crates/oo/tests/common/mod.rs`（Rust 整合測試的標準做法；
`mod.rs` 形式不會被當成獨立 test target），各檔 `mod common;` 取用。

**理由是修類別不修個案**：10 種逐字不同的同一個錯誤，逐個修完之後仍是 10 份，
下一個埠缺陷會再發生 10 次。

> **⚠ 本項無探針。** 「14 份收成 1 份」不是行為，測不到。
> **完成條件以 grep 驗（§6）**，且驗收方會實跑併發重現（§5.2）。

### 3.3 不得以重試遮蓋

**不得**在測試裡加「綁失敗就換一個埠重試」。〔既有規則〕重試會把一個確定性的缺陷
變成一個機率性的缺陷。本弧的修法是**讓子行程自己綁**，空窗與 H1／H2 一併消失，
沒有需要重試的東西。

## 4. 已校準探針

檔案：`crates/oo/tests/a_port_you_did_not_bind_probe_test.rs`。

**探針修改權在驗收方。** 交付**只得**移除 `#[ignore]`，**不得**改動本檔任何其他位元組。

| 探針 | 斷言 | 基線 |
| :-- | :--- | :--- |
| **C0** | 控制組，**首位**：以明確埠啟動時，橫幅指名該埠且該埠連得上 | 綠（必須維持） |
| **P1** | `--port 0` 時橫幅**不得**指名 `0`（不存在斷言） | **紅**：今天逐字印 `port 0` |
| **P2** | `--port 0` 時橫幅所指名的埠**必須真的連得上**（存在斷言） | **紅**：今天無號可連 |

**P1／P2 必須成對**：P1 單獨可被「印任何一個數字」滿足；P2 把它釘死在**真的那一個**。
這是常設規則「斷言不存在的紅，必須在同一次執行內斷言一個存在」的直接應用。

**C0 為何在首位**：P1／P2 都在斷言「某次啟動的橫幅怎麼樣」。若節點根本起不來，
兩者都真空。C0 是它們的存在半。

### 5.2 併發重現（本弧的主證據）

樹內測不到「不再搶埠」。驗收方會把 14 支用埠的測試二進位**同時**啟動並重複多輪，
比較交付前後的 `Address already in use` 次數。
〔量，交付前基線〕該手法 2 輪 14 支並行：0 次 EADDRINUSE，
但**另有 `seat_order` 兩支因負載過高而自陳前提不成立**（「the burst spanned 3 whole
seconds」）——**那不是缺陷，是一支拒絕真空通過的好探針**，計數時須排除。
