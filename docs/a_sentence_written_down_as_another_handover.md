## 0. 判準（規格原文）

*   **`REAL_01` §1.3 第三款「印出來的必須讀得回去」（MUST）**：所印出的文字必須是合法的 n/；未觀測者應當印出它的**來源**。一段讀回來是另一句話的文字不是它的來源。
*   **`REAL_03` §6.7**：語言分得開的兩個東西，位址必須相異。倉把配方存成它印出的文字（`store_codec.rs` 寫 `to_nlang`、讀時 `parse_expr_only`），身分也雜湊這段文字（`lib.rs` `thunk_cycle:v1:`）——印成同一段文字的兩句話共用一個位址。
*   **Q-103 的不變式**：一檔、兩次演化、兩次提交同讀數、同根；`oo eval` 的交會是同一句話的答案。
*   **一個概念一種拼法**：修印表機（加括號），不加文法（`f <<x>>`、`f @int` 是施用之類的糖不在選項裡）。

## 1. 缺陷

〔量，`v0.108.0` 標籤建置；eval 在空目錄，提交在新宇宙；`acc/q108/recon.sh`〕

*   `g: (y -> { k: y })`、`r: g (@int)` ⟹ 暫存、`oo fmt`、倉裡都寫成 `r: g @int`——**型別註記**（`type_ann_op`）；提交後 `_.r` 是箭頭本身（eval 讀 `{ k: @int }`），與照字寫 `r: g @int` 同根 `e3de7e90…`。
*   `g ([1])` 寫成 `g [1]`（下標，`_.r` ⊥ `#missing_key`）；`g (<<n>>)` 寫成 `g <<n>>`（剖析不了，提交存 `_`；Inbox「施用的引數是結構態時…」）；`g ([1]).0` 同；`g (@int @ @int)` 寫成 `g @int @ @int`。
*   `(!n) @ #false` 寫成 `!n @ #false`（讀回 `!(n @ #false)`，提交讀 `Top`）；`n @ (!n)`、`n == 3 ? (1..n) : 2`、`n == 3 ? (g n) : 2`、`{ ...(!n) }` 寫成剖析不了的文字（提交不寫、`fmt` 的輸出 evolve 不了）。
*   **Inbox「呼叫造的記錄再寫一欄」就是這一件**：`h: (y -> { k: y, f: (x -> k) }) (@int)` 再寫 `h: { k: 5 }` ⟹ 一檔把 ⊥ `#missing_key` 提交進歷史、兩次演化與兩次提交拒、eval 讀 `5`——第一筆存進暫存時就成了註記。
*   **剖析器層**〔量，`acc/q108/q108_recon.rs`，225,503 個由 32 種運算元 × 20 種運算子 × 11 種處境組成、剖析得了的式子〕：3,507 個印出來讀不回去（1,071 個讀成另一棵樹、2,436 個剖析不了）。四類：施用的引數以 `@`（非 `@{`）／單元素清單 `[x]`／`<<`／`...` 起頭；型別註記的一邊是 `!`／`...`（文法上 `@` 比 `!` 緊，印表機的優先序表相反）；三元的 then 分支以施用的引數或區間的端點收尾（後面的 ` :` 讓它被讀成下一個欄位，`field_start`）；`...` 後面是 `!`。
*   〔讀〕`crates/parser/tests/fuzz_roundtrip.rs` 的產生器不產生 `Apply`、型別路徑、單元素清單、下標、記錄——這個洞一直沒被量到。
