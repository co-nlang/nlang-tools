# 偵察工單：一次回報成功的提交，其實是一個 `_|_`

**Queue ID**：**Q-017**（`nlang-spec/meta/WORK_QUEUE.md` §3、Ready 表第 1 列）。
**這是偵察，不是實作**（§8 開弧 3——「要不要固化由操作者決定」在 CLI 上長什麼樣仍未裁）。
**基線**：`v0.41.0`，二進位 `/home/gali/nlang-baselines/v0.41.0-verify/target/release/oo`
（`oo --version` → `oo v0.41.0`；known-answer：`oo run ka.n -o r`，`r: ~%Math./add (1,2)` → **`3`**，
對照 `add (1,"x")` → **`_|_`**）。**你也必須先對你自己的二進位做一次 known-answer 加對照。**
`oo --version` **不知道自己是哪一版**（Inbox 四個實例）⟹ 版本用**行為**確認。

**裁定依賴**：**B1／B2（用戶 2026-08-06，`commit.md` §2.1.3）**——本卡的形已經被裁過一半：

> **收斂遇到 bottom 該停並回報是對的，但要不要固化是使用者能決定的。**（用戶原話）

| | 誰的責任 | 條文該說 |
| :-- | :-- | :-- |
| 收斂撞到 ⊥ | **觀測** | **必須停下並回報**——保留，而且**今天沒做到** |
| 要不要固化 | **操作者** | **不由條文代決** |

並附兩句同樣重要的：**「要修的不是『中止』，是『報告』」**；
**「粒度也錯了——固化的最小單位是 ○，而 ● 是後來、另外的一個動作」**。

**規格依賴**：`SPEC_10` §2.2.1 **[Core Requirement，2026-08-08]** 的回報五款——
必須指出座標／必須到葉／必須含錯誤碼／**不得洩漏實作表示**／**各回報面一致**。

## 1. 驗收方已量到的（不必重量；可推翻，推翻請帶指令）

### 1.1 活案例是單寫者、三個指令——**本卡的封鎖理由是假的**

卡片原記「並發合併真的抵達 commit 後才有穩定活案例」，故本卡曾排在 Q-016 之後。
〔量 2026-08-31〕**不需要任何並行**：

```
c: c + 1
  evolve  →  無任何輸出、rc=0
  status  →  逐字顯示  c: c + 1        ← 看起來完好無損
  commit  →  Commit successful、rc=0
  根      →  c: _|_ (%cause: #divergent)
```

另兩形同病（`evolve` 皆靜默 rc=0、`commit` 皆成功 rc=0）：
`x: 1 & 2` → 根 `x: _|_ (%cause: #conflict)`；
`~%Math./add (1, "x")` → 根 `y: _|_ (%cause: #conflict)`。

⟹ **`SPEC_10` §2.2.1 三條 MUST 同時未兌現**：必須指出座標／必須含錯誤碼／
**各回報面一致**——`status` 說 `c: c + 1`，根說 `_|_`，**同一個倉兩個答案**。

### 1.2 **本卡真正的形狀：不是「commit 不報告」，是「兩條路徑各錯一半」**

〔讀 `crates/oo/src/main.rs:1036`–`:1039`〕`run_commit` **已經有這段**：

```rust
if let Some(d) = &universe.workset_bottom {
    anyhow::bail!("Evolution Conflict: {}", format_conflict_where(d, None));
}
```

`format_conflict_where`（`main.rs:15`）**已經會印座標與錯誤碼**（`{cause} at {coord}`，
座標取自 `BottomDetail.path`）。**§2.2.1 要的格式，這個函式已經有了。**

〔量〕兩條路徑並排：

| 路徑 | 觸發 | `commit` 的行為 | rc | 落地了嗎 |
| :-- | :-- | :-- | --: | :-- |
| **A** 座標上的 ⊥／發散的 thunk | `c: c + 1`、`x: 1 & 2` | **`Commit successful`** | **0** | **落地了**（根裡是 ⊥） |
| **B** 工作集層級的 ⊥（D49 fold） | 兩個並行注入同一個鍵、值相異 | **`Error: Evolution Conflict: #conflict at k`** | **1** | **沒落地**（無 `HEAD`、注入 2 個仍在、○ 2 顆仍在） |

⟹ **A 是「靜靜地落地」，B 是「大聲地中止」，而 B1 兩個都不要。**
B1 要的是**大聲地落地，然後讓操作者決定**。

**⚠ 這是本卡最重要的一句，請不要把它讀成「照 B 抄給 A」**——
**B 自己就違反 B1**（它中止）。把 A 改成 B，只是換一種違反法。

〔讀〕`workset_bottom`（`universe.rs:347`）是**一個 `Option<BottomDetail>`**，
在 `:959` 由 fold 設定、`:921` 清除 ⟹ **它是工作集層級的單一格**，
表達不了「⊥ 落在座標 `x` 上而其餘欄位完好」這件事。**A 走不到那個判斷，不是因為判斷寫錯，
是因為那個資料結構裝不下 A。**

### 1.3 §2.2.1 的「不得洩漏實作表示」在這條路上已經破了

〔量〕`x: 1 & 2` 的 ⊥ 逐字帶著
`message: "Incompatible types: Atom(Int(1), EffectTag(0), None) vs Atom(Int(2), EffectTag(0), None)"`
——**Rust 的 `Debug` 輸出**，而 §2.2.1 逐字禁止「宿主語言的除錯輸出格式」。
它同時出現在 `oo status`、○ 的框裡、以及**提交後的根裡**。
**⚠ 這一列已在 Inbox（`interrupt-candidate`，服務面：該欄位不在自己的 CAID 之內）**
⟹ **不要在本弧修它**，但本弧的回報文字**不得再把它抄一遍**。

### 2.1 缺口的真實形狀

**Q1.** `workset_bottom` 今天由哪些路徑設定？逐一給 `檔案:行號` 與一個會觸發它的最小指令序列。
**A 類的 ⊥ 為什麼到不了它**——是因為 fold 不看座標內部，還是因為 A 的 ⊥ 根本在更晚才出現？

**Q2.** A 類三形（`c: c + 1` 發散／`x: 1 & 2` 直接衝突／`add (1,"x")` 型別）
**各自在管線的哪一步變成 ⊥**？`evolve` 時？`status` 求值時？還是 `commit` 算根時？
**帶指令證明。** 這一題決定「報告」該掛在哪裡。

**Q3.** `status` 對 `c: c + 1` 顯示未化約的原文，對 `x: 1 & 2` 顯示 `_|_`。**為什麼不一致？**
〔讀〕`run_status` 的求值深度與 `commit` 算根的求值深度是不是同一個？
**這一題就是「各回報面一致（MUST）」的成因。**

**Q4.** 一次提交裡**可能有多少個 ⊥ 座標**？今天的資料結構（`workset_bottom` 是單數）
能不能表達「三個座標各自撞了 ⊥」？**報告該說一個還是全部？**（§2.2.1 說「必須到葉」。）

**Q5.** **還有哪些 `%cause` 到得了提交邊界**？除了 `#divergent`／`#conflict`，
`#missing_key`／`#incomplete`／`#unprovided_builtin` 會不會落地成根裡的 ⊥？**逐個試。**

### 2.2 B1 的另一半：粒度

**Q6.** B1 逐字：**「固化的最小單位是 ○，而 ● 是後來、另外的一個動作」**。
今天 ○ 已經是耐久的（D43／D52 之後每次注入與每次提交都鑄）。
**問**：撞到 ⊥ 的那個**觀測／注入**，它的 ○ 上有沒有記下「這裡是 ⊥」？
〔量〕看 `.oo/savepoints/` 的框——ⓞ 的 combo 裡有 `~%__nlang_bottom` 嗎？
**如果有，報告的材料已經在磁碟上了**，這會大幅改變報價。

### 2.3 定價（**不要選邊**）

**Q7.** 「要不要固化由操作者決定」在 CLI 上有三個候選，**逐一報價**
（行數／動到哪些檔／既有測試紅幾支／對 `oo` 之外的呼叫者有何影響）：

| | 候選 | 一句話 |
| :-- | :-- | :-- |
| **甲** | **報告後照樣落地，rc=0** | 印出座標與錯誤碼，提交仍成功。最小改動；但腳本仍看不出差別 |
| **乙** | **報告後照樣落地，但 rc≠0** | 落地與離開碼分家：東西進了歷史，而離開碼說「這次帶著 ⊥」 |
| **丙** | **預設拒絕，需顯式旗標才落地**（如 `--allow-bottom`） | 最接近「操作者決定」的字面；但**與 B1 的「要修的不是中止」正面衝突** |

**⚠ 逐字禁止**：不要自己選。**丙特別要小心**——它讀起來最像「讓操作者決定」，
但 B1 的原話是**中止本身就是要被修掉的那個東西**。若你認為丙其實與 B1 相容，
**寫出理由**，那是回頭請裁的材料。

**Q8.** **B 路徑（今天會中止）要不要一起改成同一個形狀？**
