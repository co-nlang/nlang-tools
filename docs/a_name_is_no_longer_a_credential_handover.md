## 0. 先讀這一節：本弧**不會**關掉那個頭條缺陷

`WORK_QUEUE` 上 Q-035 的一句主張是「使用者資料不得只靠 `%builtin` 名字取得宿主內建能力」。
**本弧做完之後，那句話仍然不成立**，而這是刻意的，不是漏掉。

〔量 2026-08-23，v0.30.0 真二進位〕七個危險名字**全部都在標準根裡**：

| 名字 | 在 registry | 標準根有 project |
| :--- | :--- | :--- |
| `process.exit` / `process.pid` | Y | **Y** |
| `io.read_file` / `io.write_file` / `io.append_file` | Y | **Y** |
| `env.get` / `env.args` | Y | **Y** |

而 O68 Q3.B 的規則是「`%builtin` 之名只有在**這個宇宙的**標準根確實 project 了它時才派送」。
`process.exit` 在標準根裡 ⟹ **閘會放行**，`{{ %builtin: "process.exit" }} 7` 做完本弧仍然 exit 7。

**這不是本弧的失敗，是本弧的射程。** 那條路要關得靠 **Q2a（寫入層）**，而 Q2a 今天無法裁——
〔量，偵察 §3.2〕合法別名 `add: ~%Math./add` 與手寫偽造**逐位元組相同**，parse 層拒絕會有偽陽性；
乾淨解在弧 D 下游（引用式 import 之後，使用者資料裡的 `meta.builtin` 才無歧義是手寫的）。

**⟹ 探針 C3 逐字釘住這一點：偽造的 `process.exit` 必須仍然 exit 7。**
若交付讓 C3 變紅，那是超出射程，不是額外的好。

### 那本弧買到什麼

1.  **三個今天分不開的事實，分成三個具名答覆。**〔量〕今天：

    | 輸入 | 今天的 `%cause` |
    | :--- | :--- |
    | `{{ %builtin: "nonexistent.thing" }} (6,3)`（憑空發明） | `#conflict` |
    | `{{ %builtin: "math.bitAnd" }} (6,3)`（根裡有、registry 沒有） | `#conflict` |
    | 標準根為空的脈絡 | 未量（見 S2） |

    **兩個完全不同的事實用同一個答案** —— 這正是 **Q-031** 關掉的類別，本弧是它的第七個呼叫點。

2.  **把巧合換成機制。**〔量 2026-08-23〕`registry(245) ＼ 標準根(251) = ∅`，
    而 `標準根 ＼ registry = 6`（`math.bitAnd`／`bitNot`／`bitOr`／`bitXor`／`shl`／`shr`）。
    ⟹ **根 ⊇ registry 今天是恰好，不是被誰保證的**。派送查根之後，根才是權威。

3.  **O55 的版本綁定第一次對 `%builtin` 生效。**〔量〕四個歷史標準根
    （`shipped_standard_roots()` 四列）之間，`rename_engine_differential_keys` 與
    `apply_shelf_rulings` **只改鍵、不改值** ⟹ 四者 project 的 `%builtin` 名字集合**相同**
    ⟹ **本弧對任何既存宇宙都不產生行為差異**。它買的是**下一次標準根變動時**
    舊宇宙自動保有舊的名字集合——**而下一次變動就是已排隊的那次紀元（D-2／D-3／Q1）**。
    這是「現在做」的正當理由：紀元弧不必再自己處理名字集合綁定。

## 1. 射程（S1–S4）

### S1 —— 派送閘（O68 Q3.B）

〔讀 `crates/interpreter/src/lib.rs:3064–3066`，v0.30.0〕：

```rust
if let Some(Value::Atom(AtomKind::Str(builtin_id), _, _)) = c.get_field("%builtin") {
    if let Some(func) = self.builtin_registry.get(builtin_id) {
```

**從不查根。** 要求：在 `builtin_registry.get` **之前**，確認 `ctx.standard_root` 確實 project 了
`builtin_id`。憑證來源已經在手上——〔讀 `lib.rs:101`〕`EvalContext` 有 `pub standard_root`，
而該派送點的函式簽名裡就有 `ctx`。

**不得**新增 `ComboVal` 欄位、**不得**新增序列化欄位、**不得**改動標準根內容。

〔量〕根自己指名它的標準根：真宇宙的根物件裡有
`~%__nlang_system_digest: "7038e2504b8ef4d4d267dd23b0989946c84303da34fb7e71d01c5b58caf37911"`，
而那正是標準根 CAS 物件的檔名 ⟹ 憑證是內容定址的，與 **O55／REAL_03 §6.8.1** 對齊。

### S2 —— 空標準根與「根裡沒這個名字」必須是兩個具名答覆（O68 前置 (i)）
### 　　　**本項無探針** —— 逐字標在此處，理由見下

〔讀 `lib.rs:182`〕`standard_root: Arc::new(ComboVal::default())` —— 預設是**空的**。
若閘寫成「不在根裡就拒絕」，任何以預設 context 求值的路徑會整批倒下，
**而且會倒成跟偽造一樣的答案**。

**爆炸半徑已量（2026-08-23）**：

| 量 | 結果 |
| :--- | ---: |
| `EvalContext::new` 呼叫點總數 | 90 |
| 其中在 `src/`（生產路徑） | 4 —— **四個全部有接 `with_standard_root`** |
| 其中在 `tests/` | **86** |
| 86 個之中接了 `with_standard_root` 的 | **0** |
| 這 86 個分布的檔案 | 33 |
| 33 檔中**同時**用到 `~%` 的 | **9**（含 `genesis_test.rs` 30 處、`dispatch_test.rs`、`math_branch_test.rs`） |

⟹ **生產路徑安全，測試路徑是整片的。** 把閘寫成無條件拒絕空根，會讓其中一大批變紅。

**本項無探針的理由**：空標準根**在 CLI 上不可達**（四個生產呼叫點都設了根），
故驗收方無法在開單當下對它校準一支黑箱探針。
**⟹ 交付方必須自行補一支 crate 內測試**，並在報告中指名它。

**要求**：
1.  **先量**——列出那 86 個呼叫點中實際會走到 `%builtin` 派送的，**逐一標註用途**。
    這是 Q-026 學到的規則：要求移除／改動一個到處被呼叫的東西時，
    先列清單再動手，**不得只寫「應該沒有」**。
2.  再把兩件事分成兩個具名 `%cause`：**沒有標準根**（脈絡本身沒裝）與
    **標準根裡沒有這個名字**（脈絡有裝，名字不在）。
3.  這兩者與 S3 的第三種，三者必須**兩兩不同**。

### S3 —— 那 6 個死名（O68 前置 (ii)）

〔量〕`math.bitAnd`／`bitNot`／`bitOr`／`bitXor`／`shl`／`shr` **在標準根裡、不在 registry**。
⟹ 它們會**通過** S1 的閘，然後倒在 registry 查表。

**本輪不得從標準根移除它們**——那會移動標準根 digest ⟹ 是紀元，須與 D-2／D-3／Q1 併。
本輪只要求：**它們倒下的答案必須與「根裡沒這個名字」是兩個不同的具名 `%cause`**。
（補實作也可以，但那是另一件事，不在本射程；若交付選擇補實作須明文報告。）

### S4 —— Q4.C 的可查詢記號

O68 Q4 ＝ C：**讀取路徑不拒**。附帶義務逐字：解出含 `meta.builtin` 的**使用者**物件時
**得（SHOULD）**留下可查詢記號，**不得**因此拒絕開啟或改寫。

〔量 2026-08-23〕今天沒有記號：真宇宙 `f1` 的根 CAID
`hash:sha256:v1:a15a0f00975a9b18…`，`oo inspect` 輸出把偽造的 `%builtin` 與標準根裡的
`%builtin` **顯示成一模一樣的東西**，沒有任何一處可以問出「這一個是使用者寫的」。

要求釘**性質不釘拼法**：做完之後，「這個宇宙裡有沒有使用者自寫的 `%builtin`」
必須是一個**可以問出答案的問題**，且問法要在交付報告裡寫明。
**紅線**：讀取路徑不得因此拒絕、不得改寫、不得移動任何位址。

5.  **C3 必須維持綠**（§0）。
