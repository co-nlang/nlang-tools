## 0. 判準

*   **寫在記錄裡的記錄是一個節點，不論從哪裡讀到**：一次寫下的 `q: { r: { a: g "x" } }`、`k: q.r.a`，提交時 `a` 的效應做一次；三層、經別名、經函式、讀兄弟、在清單或元組裡、呼叫造的、讀者寫在第二次演化，都一樣。
*   **一個值**：`a` 是 `~%Math./random ()` 時，`k = q.r.a` 是 `#true`。
*   **兩個就是兩個**：兩欄寫法相同的記錄（`r1`、`r2`）是兩個座標，`k: q.r1.a` 不讀成 `q.r2.a`。
*   **存下的根、讀數不變**：與 v0.141.0 相同。

`random` 版 `e: k = q.r.a`（一次寫下、三層、經別名、清單裡、讀者在第二次演化）：v0.141.0 `#false`，參考 `#true`。`oo eval` 一次觀測同一個式子只做一次（`acc/q142` 記在 §3 偵察）；`g` 後寫、pin 兩個入口 v0.141.0 已是 1。

**成因**（插樁）：
*   演化把讀巢狀欄位的定義存成那個欄位的配方本身：`k` 存的是 `g "x"` 這個 thunk，閉包是 `[q 的框, r 的框]`（D129：讀到惰性效應欄位的定義留成配方）。
*   讀回時，`q` 的框有讀回的記錄認領（`own_its_frames` 蓋章，節點 2）；`r` 的框沒有——存下的 `q` 裡 `r` 還是做出它的配方 `{ a: g "x" }`，沒有一筆讀回的 `r`。所以這個框沒有節點，只有指標身分（`frame_node` 的 `(false, ptr)`）。
*   提交投影走訪 `k`：`a` 在沒有節點的框裡強制一次（做效應，記在那個指標下）；走訪 `q`：`r` 的配方在節點 2 上強制，造出新記錄（`seal_defining_scope`，節點 3），`a` 在節點 3 再強制一次。**同一個 `q.r` 是兩個身分，效應做兩次。**
*   函式形：thunk 帶著呼叫的輸入，`force_once` 只認有節點的框（`context.is_none() || frame_node(f).0`），沒有節點的框被濾掉，完全沒有鍵。
*   讀者寫在第二次演化：`k` 閉包裡連 `q` 的框都是另一份（序列化在第二個根裡），也沒有節點；它的上一層是根。
