## 0. 判準

*   **寫在記錄裡的記錄是一個節點，不論從哪裡讀到**：一次寫下的 `q: { r: { a: g "x" } }`、`k: q.r.a`，提交時 `a` 的效應做一次；三層、經別名、經函式、讀兄弟、在清單或元組裡、呼叫造的、讀者寫在第二次演化，都一樣。
*   **一個值**：`a` 是 `~%Math./random ()` 時，`k = q.r.a` 是 `#true`。
*   **兩個就是兩個**：兩欄寫法相同的記錄（`r1`、`r2`）是兩個座標，`k: q.r1.a` 不讀成 `q.r2.a`。
*   **存下的根、讀數不變**：與 v0.141.0 相同。

**成因**（插樁）：
*   演化把讀巢狀欄位的定義存成那個欄位的配方本身：`k` 存的是 `g "x"` 這個 thunk，閉包是 `[q 的框, r 的框]`（D129：讀到惰性效應欄位的定義留成配方）。
*   讀回時，`q` 的框有讀回的記錄認領（`own_its_frames` 蓋章，節點 2）；`r` 的框沒有——存下的 `q` 裡 `r` 還是做出它的配方 `{ a: g "x" }`，沒有一筆讀回的 `r`。所以這個框沒有節點，只有指標身分（`frame_node` 的 `(false, ptr)`）。
*   提交投影走訪 `k`：`a` 在沒有節點的框裡強制一次（做效應，記在那個指標下）；走訪 `q`：`r` 的配方在節點 2 上強制，造出新記錄（`seal_defining_scope`，節點 3），`a` 在節點 3 再強制一次。**同一個 `q.r` 是兩個身分，效應做兩次。**
*   函式形：thunk 帶著呼叫的輸入，`force_once` 只認有節點的框（`context.is_none() || frame_node(f).0`），沒有節點的框被濾掉，完全沒有鍵。
*   讀者寫在第二次演化：`k` 閉包裡連 `q` 的框都是另一份（序列化在第二個根裡），也沒有節點；它的上一層是根。

### 8.4 工單指名要你回答的問題

**Q1 認領。** 沒有節點的框，用逐欄比對認出它是哪一筆：名字去掉軸的前綴（`~`、`@`、`%`），式子去掉位置、空白壓平（`written_fields`，709）。巢狀那一步：閉包第 i 個框沒有節點、第 i−1 個是節點 P，在 P 的六軸欄位裡找寫成記錄字面值（欄位本身，或那裡的清單、元組元素）、而且逐欄讀起來就是這個框的地方（`field_written_as`，762）。恰好一處才認。然後經 `force_once` 讀那一欄（Q-126 記著它，再讀是同一筆；讀的時候先拿開讀者的詞法框，讀完放回），在給出的值裡找恰好一筆讀起來是這個框的記錄，把閉包裡的框換成那筆記錄自己的框（`own_frame`，805：記錄裡有個 thunk，閉包含 `node_id` 等於這筆記錄的框）。找不到、或不只一處、或值裡不是恰好一筆：記成 Nothing，不換。每個框的答案記在 `WRITTEN_IN`（598，弱參考，以框的位址為鍵），`forget_kept_records`（581）時清。再讀時仍經 `force_once` 讀那一欄，上次那筆記錄還在才沿用。

**Q2 建構子。** 欄位直接寫成記錄：比那一欄的字面值。清單元素、元組元素：在式子裡往下數（`literals_reading_as`，734）。union 的成員、記錄字面值裡再嵌的記錄，式子裡不看：緊接在節點框後面的框只會是那一欄頂層的字面值，巢狀的有自己的框夾在中間，下一層再認；union 一次寫下在 v0.141.0 已是 1，第二次演化的別名形由根那一步修。呼叫造的記錄：閉包首位是規則的框，記錄的框在後面，仍是「前一個是節點、這一個沒有」那一步。強制那一欄之後，值裡的 union 成員與巢狀記錄會走（`records_reading_as`，783）；式子比對不走。
