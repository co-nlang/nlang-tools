# what forcing leaves behind — Q-010b 偵察(射程用)

**Queue ID**:`WORK_QUEUE` Q-010b(Active,偵察)
**基線**:引擎 `v0.20.0` / 規格 `v0.20.0-draft.1`
**這是什麼**:射程偵察,不是工單。目的是在開紀元弧之前,先知道「強制後存」實際會產生
什麼、以及三條裁定(O35＝A／O49／O50)是否仍如當初理解的那樣互相獨立。
**明確不做**:不改任何程式碼、不改任何測試、不改規格。

## 0. 四句承重的話

1. **印表機不強制。**〔量〕`computed: 1 + 2` 印出來就是 `1 + 2`,`applied: (x -> x+1) 41`
   印出來就是原式。⟹ **Q-001 偵察 §3 的 21,837 B 是「原式重印」的長度,不是任何意義下的
   「語義值形」**(§1,對 Q-001 更正 E5 的再更正)。
2. **強制會把 Thunk 變成態射 Combo,而閉包沒有消失**——它以一等欄位 `%closure` 活在
   `%rules` 裡(§2)。
3. **那個閉包是承重的。**〔量〕捕捉了 `y` 的態射施用後得到 `15`;拿掉它,施用不可能成立(§2.2)。
4. ⟹ **O49 的理由對態射閉包不成立。** 「作用域可由根＋路徑重建」對**普通值的 Thunk**
   為真(而強制本來就會把它整個移除),對**離開了定義處的態射**為假——走過 OODP 或原作用域
   已被精煉掉之後,沒有根、也沒有路徑可以重建(§3)。

## 1. 印表機不強制〔量 2026-08-14〕

一支五種形狀的程式提交後,`oo inspect` 印出:

| 源碼 | 印出來 |
| :--- | :--- |
| `lit: 1` | `1` |
| `computed: 1 + 2` | **`1 + 2`** |
| `applied: (x -> x + 1) 41` | **`(x -> x + 1) 41`** |
| `fn: x -> x + 1` | `x -> x + 1` |

而 `oo eval` 會強制:`1 + 2` → `3`,`(x -> x + 1) 41` → `42`。

**⟹ 對 Q-001 偵察的再更正**:E5 當時只說「印表機沒有證明它分開了所有該分開的值」。
更深一層是——**它根本不是一個強制後的形**。它是原式的重印。故:

- 「存語義值那個選項的實作已經在樹上」**完全不成立**(該句 E5 已標為過強,但理由不夠深);
- 21,837 B 這個數字**不能拿來估計強制後的儲存量**,它量的是別的東西;
- **強制後的儲存體積在本弧開工前仍是未知數**——本次偵察也**無法**量它,因為那需要先做出
  改動。工單必須把它列為**加性關鍵量測**,不得預設它會變小。

## 2. 強制之後剩下什麼

### 2.1 態射變成 Combo,閉包變成欄位

`x -> x + 1` 強制後:

```nlang
{{
  %kind: #logic
  %morphism: #true
  %rules: {{
    x: {{
      %closure: {{ }}
      %code: x + 1
    }}
  }}
}}
```

⟹ **`Thunk { expr, closure }` 沒有被消滅,它被搬家了**:`expr` → `%code`,
`closure` → `%closure`。差別在於後者是**一等的 n/ 值**而非實作結構。

### 2.2 閉包是承重的

〔量〕`{ y: 10, f: x -> x + y }.f` 強制後,`%closure` 的第 0 幀含 `y`;施用該態射
(`(...).f) 5`)得到 **`15`**。⟹ 拿掉閉包,施用不可能成立。

### 2.3 但它裝的是整個作用域,含它自己

〔量〕在一個只用到 `v1` 的態射外面加無關欄位:

| 作用域無關欄位數 | 強制後印出 |
| ---: | ---: |
| 1 | 384 B |
| 3 | 416 B |
| 6 | 464 B |
| 12 | 566 B |

**約 16 B/無關欄位,線性成長。** 且第 0 幀裡**含 `f` 自己**(自我參照,與 M3 對
`k1` 的發現同一個病)。

**好消息**:`system` **沒有**被捲進去〔量〕——含 `y` 的態射整份印出只有 382 B,
內建名零命中。O50 與本項因此不交纏。

## 2.4 規格基礎:`%closure` 是規範的,`%code` 不是(用戶 2026-08-14 指出)

**`%closure` 有明文,而且它的理由正是 O49 想否定的那件事。** SPEC_05 §3.3:

> **`%closure`**:子空間在定義時所糾纏(Entangled)的外部作用域快照。
> **這讓算子具備了跨視角傳輸並保持語義一致的能力。**

亦見 QUICK_REFERENCE(列為 `@combo`)與 GLOSSARY(綁定到 Entanglement)。

⟹ **O49 不只是缺乏量測支持,它與一條既有條文相牴觸**,而該條文存在的理由**就是**我在
§3 舉的 OODP 情境:讓算子帶著意義旅行。

**`%code` 則沒有定義條款。** 全樹唯一一處提及在 REAL_01 的**自陳缺口(2026-08-09)**,
而那一處是一則**警告**:

> 本節第三條要求的是**可剖析**,**不是可重求值**。……要讓「重讀必得同一個值」成立,
> 需要**環境隨行**,那是另一個決定。同理,被引述的程式碼(`%code`)印成其運算式後重讀
> 會**被求值而非被引述**。**本節不宣稱這兩者已解決。**

三個後果:

1. **強制後的態射形依賴一個規格從未定義的欄位。** 若 Q-010b 把它寫進耐久層,那就是
   **把一個未定義的欄位變成跨版本、跨引擎的契約**。
2. **規格自己已經標記了這塊是未解的**,而它點名的兩件事(環境隨行 / `%code` 重讀)
   **正是本弧要碰的兩件事**。
3. **`%closure` 就是那個「環境隨行」機制。** ⟹ 依 O49 刪掉它,等於**移除規格已知缺口的
   唯一現有答案**。

## 2.5 用戶 2026-08-14:`%code` 在做當初以為 `%rules` 要做的事

**觀察成立,而且指出的是規格自身的不一致。**

SPEC_05 §3.3 把 `%rules` 定義成**外延的**:

> **`%rules`**:算子的**矩陣表示或映射表**。**Key 是輸入子空間的譜特徵,Value 是輸出結果。**

而引擎產出的是**內涵的**〔量 2026-08-14〕:

| 源碼 | `%rules` 的 key | value |
| :--- | :--- | :--- |
| `a -> a` | `a` | `{{ %closure, %code }}` |
| `a -> b -> a + b` | `a` | 同上 |
| `(p, q) -> p * q` | `(p,q)` | 同上 |
| `~%Math./add`(內建) | **沒有 `%rules`** | `{{ %builtin: "math.add", %morphism: #true }}` |

**key 是參數樣式,不是譜特徵;value 是本體加環境,不是輸出結果。** 全樹沒有任何一處
`%rules` 是規格描述的那種矩陣。

**但錯的不一定是引擎——規格有兩套說法**:

| 出處 | 說的是 | 與實作 |
| :--- | :--- | :--- |
| **SPEC_05 §3.3** | 矩陣／映射表,key ＝ 譜特徵,value ＝ 輸出結果 | **不合** |
| **QUICK_REFERENCE §62** | 「態射的座標變換規則集(**按 Pattern 規範排序**)」 | **合** |
| **REAL_03 §176** | 「當一個態射具備多個**分支規則**(存儲於 `%rules`)時」 | **合** |

⟹ **是 SPEC_05 §3.3 這一條與另外兩處相左**,不是實作偏離規格。

**且 `%builtin` 的規格命中數是 0。** 它是整張 `system` 表(每個根的 91%)的構成方式。
⟹ Q-010b 若照現況把態射寫進耐久層,會把**兩個**沒有條款的欄位變成跨版本契約,不是一個。

### 一個讓兩邊都對的讀法

SPEC_05 §3.3 的開頭是:「Logic 的核心在於其**么正算子**與**相伴環境**。」——**兩個東西**。
若把它讀成本專案一貫的固化/惰性分面:

| 面 | 欄位 | 是什麼 |
| :--- | :--- | :--- |
| **固化(外延)** | `%rules` 作為矩陣 | 這個算子**已經被確定**的 輸入↦輸出 |
| **惰性(內涵)** | `%code` ＋ `%closure` | **如何再算出更多格**——即「相伴環境」 |

兩者不衝突,而且**必然共存**:定義域無窮的態射**永遠無法被完全列表**,故惰性面不可移除。

**這使問題 3 換了一個層級。** 它不是「要不要補一條 `%code` 條款」,而是:

> **O35＝A 說「耐久形是值,不是求值狀態」。落到態射上,值是哪一面?**

若答固化面,態射的耐久形是它的 `%rules` 矩陣——但那對無窮定義域不可能完備。
若答惰性面,那就是在存求值狀態,與 O35 的字面相衝。

⟹ **態射正是 O35 與 O51 相撞的地方**,而這是 Q-010b 真正的內容,不是它的一個附註。

## 2.6 `%builtin` 不是一個文件缺口,是一道沒有規則的門〔量 2026-08-14〕

查 `%builtin` 的條款時順手測了「使用者自己寫得出來嗎」,答案改變了這個規格弧的性質。

| 測試 | 結果 |
| :--- | :--- |
| 使用者寫 `{{ %builtin: "math.add", %morphism: #true }}` | 接受,印出來就是它 |
| **施用它** | **`3`——與 `~%Math./add (1,2)` 相同** |
| 偽造 `env.get` / `time.now` | **派送成功,帶 `%effect: #io`** |
| 偽造 `process.exec` / `process.run`(不存在的名字) | `⊥ (%cause: #conflict)` ✓ |
| **偽造 `process.exit` 並施用** | **行程終止,退出碼 7——與真的 `~%Process./exit 7` 逐位相同** |
| **把這種值提交** | **`Commit successful`,並落成 CAS 物件** |

⟹ **一個值就是一個能力。** 名字是唯一的憑證:任何能把值放進你的宇宙的東西,都能指名
你的引擎的原生實作,包含 `#io` 類與會終止行程的那一個。而這種值**存得進內容定址儲存**。

**OODP 可達性已補量〔量 2026-08-14〕——對等內容走不到施用。** 線上唯一的**寫入**路徑是
`#advertise`(`#fetch` 是拉取:對等點問我要我持有的東西,施用發生在**它**那邊);而
`serve_advertise` 有一道**先於求值的結構閘** `ensure_literal_body`(其註解逐字記著 v0.2.50
的教訓:「it ran the speaker's payload first」),閘後還要求 8 個簽章欄位:

| 對抗(對線上節點) | 結果 |
| :--- | :--- |
| `%ad: {{ %builtin: "process.exit", %morphism: #true }}`(偽造 combo) | **`#rejected/#malformed`**,節點存活 |
| `%ad: (({{ %builtin: "process.exit" … }}) 7)`(會計算的載荷) | **`#rejected/#malformed`**,節點存活 |
| 兩者是否落進本地 store | **未落地** |
| `oo` 有沒有 client 端 fetch-並-施用命令 | **沒有**(`node` 子命令只有 serve/id/advertise/discover/find-node/…) |

⟹ **`%builtin` 是本地威脅面,不是遠端的。** 能觸及原生的前提是「值進了**你自己**的宇宙」
(local evolve/commit/eval),而線上唯一的寫入口要求**簽章＋欄位完整的廣告**,並在求值前
用字面閘擋下裸的態射 combo。**這把 §2.6 的能力問題縮回到本地信任邊界**,與 O50 自洽。

**與本弧的關係(這是重點)**:`%builtin` 沒有任何條款 ⟹ 規格從未說過它是
**互通契約**、**引擎本地的逃生口**、還是**使用者資料中的違規**。三種讀法對 Q-010b 的
後果完全不同:

- 若是互通契約 ⟹ 第二個引擎必須認得 `"math.add"`,那是一張共享登錄表;
- 若是引擎本地 ⟹ **O50 已經給了它語義**(根只存 `system` 的 digest,名字的意義由那張表
  的摘要固定),而**使用者資料裡出現 `%builtin` 就該是違規**;
- 若不裁 ⟹ Q-010b 會把它照原樣寫進耐久層,**把一道沒有規則的門變成跨版本契約**。

## 3. 對 O49 的後果

O49 的裁定文字是:

> **閉包不是耐久內容**——作用域可由根＋路徑重建。

量測把它拆成兩個不同的東西:

| | 是什麼 | O49 的理由成立嗎 |
| :--- | :--- | :--- |
| **普通值的 Thunk 閉包** | `k1: 1` 存成 `Thunk{expr:1, closure:[整個作用域]}` | **不需要理由**——強制會把整個 Thunk 消滅,閉包隨之消失。**由 O35＝A 免費做掉** |
| **態射的 `%closure`** | 強制後仍在,且施用時需要它 | **不成立**。一個走過 OODP 的態射、或其定義作用域已被精煉掉的態射,**沒有根也沒有路徑**可供重建 |

**⟹ O49 目前的措辭會讓交付方刪掉一個承重的東西。** 這不是「裁定錯了」,是**裁定寫在
量測之前**,而量測顯示它涵蓋了兩個不同的對象。

**真正的缺陷不是「閉包存在」,是「閉包捕捉了它不需要的東西」**——整個作用域而非實際被引用
的那些名字,並且包含自身。那是一個**捕捉分析**,不是一次刪除;代價與難度都與 O49 原本讀起來
的樣子不同。

## 4. 要用戶裁的

1. **O49 拆成兩條**:
   - **(i)** 普通值 Thunk 的閉包 —— 併入 O35＝A,不另立(強制即消滅)。
   - **(ii)** 態射的 `%closure` —— **不得刪除**(SPEC_05 §3.3 明文,且它是 REAL_01
     自陳缺口所要求的「環境隨行」之唯一現有實現)。真正的缺陷是**它捕捉了不需要的東西**,
     故裁定應為:**`%closure` 只保留其本體的自由變數**。

   > **⚠ 我上一版對 (ii) 提的文字「且不得含自身」是錯的,已撤回。**〔量 2026-08-14〕
   > `{ fact: n -> (n <= 1) ? 1 : n * (fact (n-1)) }.fact 5` → **`120`**,而它成立**正是
   > 因為 `fact` 在自己的閉包裡**。遞迴態射的自我參照**是它本體的自由變數**,「只保留自由
   > 變數」這個判準自然保住它,而「不得含自身」會弄壞遞迴。**判準要寫性質,不要寫症狀。**
2. **(ii) 要不要進 Q-010b?** 它是捕捉分析,與「強制後存」是**兩件不同的事**,而且
   **不移動身分之外的東西**——但它**會**移動身分(閉包進雜湊,Q-001 已量),所以若要做,
   **必須與 Q-010b 同一個紀元**,否則就是第二個紀元。
3. **態射的耐久形存哪一面?**(經 §2.5 重寫;原題「要不要補 `%code` 條款」層級太低)

   O35＝A 說耐久形是**值**不是**求值狀態**。落到態射上,固化面是 `%rules` 矩陣、
   惰性面是 `%code`＋`%closure`,而**定義域無窮的態射永遠無法被完全列表** ⟹ 惰性面
   不可移除。**這是 O35 與 O51 在態射上的正面相撞。**

   在裁它之前,有兩件**純規格**的前置,兩件都不動引擎:

   - **(a) SPEC_05 §3.3 的 `%rules` 條款與 QUICK_REFERENCE §62、REAL_03 §176 相左**
     (矩陣／譜特徵 vs Pattern 排序的分支規則),而後兩者與實作一致。**三處必須先對齊**,
     否則本弧會照著三種互斥的說法之一去實作。
   - **(b) `%code` 與 `%builtin` 皆無定義條款**,而 `%builtin` 是整張 `system` 表的
     構成方式(每個根的 91%)。耐久化它們＝把兩個無條款欄位變成跨版本契約。

   **建議**:(a)(b) 合成一次小規格弧,在 Q-010b 開工前做完。純規格、不動引擎、不移動
   任何身分,而且缺口是規格自己標出來的。

**我的看法**:(ii) 併入 Q-010b。理由是它與強制同屬「耐久形是值」這一個主張,而且紀元
只能開一次。但它會讓 Q-010b 從「一個機械變換」變成「一個需要正確性論證的分析」,射程明顯變大——
若你偏好把 Q-010b 壓小先出貨,那 (ii) 就得等下一個紀元,而下一個紀元沒有預定的時間。
