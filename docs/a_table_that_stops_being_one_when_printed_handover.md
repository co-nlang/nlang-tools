# 工單：一張印出來就不再是表的表（Q-086）

> 佇列 `nlang-spec/meta/WORK_QUEUE.md` Q-086（原 Inbox「全部分支皆原子約束的表，印出後讀回不是表」）／**裁定 D108**（2026-10-13 用戶裁定，選甲）：表裡至少有一列印成 `@{ … }:` 時，原子列照 D102／D107 裸印；沒有任何一列會印成 `@{ … }:` 時，每一列都印 `@{ … }:`。依據另有 D97（有模式鍵的 Combo 是表）、D100（選中的分支是箭頭或表，就拿輸入施用它）、`SYNTAX_02` §4 #12（印出必須讀回同一個值）

## 1. 缺陷

〔量，v0.87.0；D102（v0.79.0）起〕表裡沒有一列印成 `@{…}` 時，印出形沒有模式鍵，讀回是依鍵查找的普通 Combo（D97）：

*   `{ @{ 4 }: "f", _: "z" }` 印 `{ 4: "f" _: "z" }`，兩者 `=` 得 `#false`；`{ @{ "j" }: 1 }` 印 `{ j: 1 }`、`{ @{ _ }: 1 }` 印 `{ _: 1 }`、`{ @{ #a }: 1, _: 0 }` 印 `{ #a: 1 _: 0 }`。巢狀在欄位裡、展開組出、`&` 組出、旁邊有 `/h:` 鍵者皆同。
*   **分支值是表或箭頭時，讀回的答案也不同**：表選中的分支是表就拿輸入施用它（D100），依鍵查找則交回那張表本身。`({ @{ 4 }: { @{ 4 }: 1 }, _: 0 }) 4` ⟹ `1`，印出形 `{ 4: { 4: 1 } _: 0 }` 施於 `4` ⟹ `{ 4: 1 }`。分支值是原子時兩形同答。
*   `oo eval`、`oo run --observe`、`oo status` 同。

〔讀〕成因：`crates/interpreter/src/value.rs` `table_display_rows` 逐列決定拼法，原子列照 D102／D107 裸印，**沒有看整張表裡還剩不剩一個模式鍵**。

〔量〕**不在存放**：提交走節點表，不經印出——頂層、巢狀欄位、箭頭本體裡的全原子表提交後答案與 `=` 皆對；`oo fmt` 印源碼，模式鍵一律 `@{…}`。印出不入址。

## 2. 裁定與依據

*   **D108**（甲）：原子列只在「整張表至少有一列印成 `@{ … }:`」時裸印；否則每一列都印 `@{ … }:`——`{ @{ 4 }: "f", @{ _ }: "z" }`、`{ @{ "j" }: 1 }`、`{ @{ #a }: 1, @{ _ }: 0 }`。這是 D107「只在讀回相同時裸印」由一個鍵推廣到整張表。混合表照 D102／D107 不變。
*   **不取乙**（只挑一列）：要定「哪一列」，而 `%rules` 序（模式位址序）對讀者是任意的。**不取丙**（原子列一律 `@{…}`）：放棄 D102 要保的 `j: 5` 可讀性。
*   **位址**：不動任何根（印出不入址）。〔量〕`k: { @{ 4 }: "f", _: "z" }` `43480b6b…`、`k: { t: { @{ 4 }: { @{ 5 }: 1 }, _: 0 } }` `5f109572…`，參考實作上同。

## 3. 射程＝不變式（不是機制）

*   **I1 印出的表讀回是同一張表**：每一張分支值是原子或表的表，印出、讀回，`=` 判 `#true`——不論全原子、混合、巢狀、展開、`&`、旁有非表鍵（r1）。
*   **I2 讀回的答案相同**：印出形施於任何引數，答案與原表相同（r1b）。
*   **I3 哪幾列保留 `@{ … }`，由 D108 一條決定**：沒有一列會保留時全部保留；有一列保留時其餘照 D102／D107；依鍵查找的普通 Combo 不是表，照舊（r2）。
*   **I4 每一個印出值的介面都如此**：`oo eval`、`oo run --observe`、`oo status`（r3）。**若你找到另一個印出值的介面（包括錯誤訊息或報告裡內嵌的值），一併在射程內，並在 8.1 列出。**「印出的表讀回是表」是要守的不變式；改 `table_display_rows` 只是一種機制。
*   **I5 不動位址、不改磁碟格式**：新倉仍 `layout=9`／`encoding=6`。
