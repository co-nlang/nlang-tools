# A fallback that wins — 工單

> Queue ID **Q-027**。基線：引擎 `v0.23.1`（`1333340`）／規格 `v0.23.0-draft.1`。
> 偵察併入本檔 §1。裁定 **A／B** 已由用戶給出（§2），開單前無其他待裁。
>
> **明確不做**：`unwrap_or` 這個寫法本身（全樹 53 處），只治**決策位**的四處；
> `capacity` 與 `hops`（實測不進任何決策）；`.oo/` 以外的耐久路徑。

## 1. 量到的（偵察）

### 1.1 同一個寫法，在同一個檔案裡往兩個相反方向倒

〔量 2026-08-16，v0.23.1〕`crates/interpreter/src/peers.rs` 的耐久記錄解析中，
每一個欄位都用同一個慣用寫法 `…and_then(as_T).unwrap_or(X)`。逐項追它的後果：

| 欄位（位置） | 取不到時退回 | 後果 | 方向 |
| :--- | :--- | :--- | :--- |
| `ttl`（`:201`） | `0` | 〔量〕`oodp.rs:1074` `ttl == 0` ⟹ **不轉發** | **輸** ✅ |
| `services`（`:190`） | 空陣列 | 不匹配任何服務查詢 | **輸** ✅ |
| `observed_host`（`:205`） | `""` | `addr` 成為空字串 ⟹ 不可撥 | **輸** ✅ |
| `listen_port`（`:198`） | `0` | `addr` 成為 `host:0` ⟹ 不可撥 | **輸** ✅ |
| `provenance`（`:223`） | `Unknown` | **帶註解**「never promote to direct」 | **輸** ✅ |
| `capacity`（`:199`） | `0` | 〔量〕未進任何排序（§4.2.4 明文 MUST NOT 加權） | 中性 |
| `hops`（`:209`） | `0` | 〔量〕只被儲存與回顯，不進任何決策 | 中性 **⚠ 見下** |
| **`ts`（`:200`）** | `0` | 餵給 `received_at`；`0` ＝ epoch ⟹ **排最前** | **贏** ❌ |
| **`received_at`（`:210`）** | `ts` | 它是 `cmp_admission_order` 的**主鍵**（`:62`） | **贏** ❌ |
| **`admission_seq`（`:230`）** | `0` | **次鍵**（`:63`）；`0` 在一切真實序號之前 | **贏** ❌ |

> **⚠ `hops` 是潛伏的一項，本弧不動但必須記下。** `PeerAdvert::hops` 的文件逐字寫著
> 「`0` for a direct `#advertise`」——**那個退回值有語義**。今天〔量〕它不驅動任何決策
> （direct／relayed 由 `provenance` 承載，而那一處已刻意退回 `Unknown`），故歸為中性；
> 但**一旦有人開始讀 `hops`，它就會從「中性」變成「贏」**——一筆解析失敗的記錄會看起來像是直達的。
> **本弧不改它**（改了就要動身分以外的語義），但收弧時須入 Inbox。

**沒有人選擇過方向。** `provenance` 那一處是**唯一**被刻意選過的——它有一句註解說明
為什麼往「輸」的方向倒。其餘是同一個寫法碰上不同欄位的語義，**結果由巧合決定**。
這正是「**意外的性質不是性質**」（REAL_02 §4.3.5.1 自己的話）。

### 1.2 兩處已對現版重現

**〔量，行為級〕`admission_seq`**：5 個候選、3 個席位（`AUTOMATIC_REMOTE_CAP`）、
`received_at` 全部相同，只以 `admission_seq` 區分——一筆**缺席**、一筆**不可解析**
（`"abc"`）、三筆真實序號 6／7／8。**seated = [0, 1, 2]** ⟹
**那筆不可解析的記錄拿到席位，排在帶真實序號 7 與 8 的記錄之前。**
違反 REAL_02 §5.1.2「缺席與不可解析不是同一件事（MUST）／不得以同一個退回值涵蓋兩者」。

**〔量，碼級＋模擬〕熵失敗**：`oodp.rs:1143` 逐字為
`if rng.fill(&mut buf).is_err() { return 0; }`，註解寫著 `treat as 0`。
把 `sample_uniform_cap`（`:1115`）逐行轉寫後模擬：回 0 ⟹ `j = i + 0 = i` ⟹
`swap(i,i)` 對每個 `i` 皆為 no-op ⟹ `truncate(k)` 得**目錄序的前 k 個**
（模擬：20 筆目錄回 `peer0…peer7`）。違反 §4.3.5.1「不得靜默退回固定序（MUST NOT）」。

**且比它所修的舊缺陷更糟**：舊缺陷是**雜湊表迭代序**（逐行程種子，重啟即換）；
現行退回的是**耐久到達序，跨重啟穩定** ⟹ 落入該節自己的論證
「決定性的規則，是攻擊者也能離線算的規則」。
**可達性未證實**（Linux `getrandom` 開機後幾乎不失敗）——但該 MUST NOT 講的是
**不得這樣做**，碼裡就這樣做了；可達性是另一軸。

## 2. 主張與裁定

**主張：當引擎說不出一筆資料是什麼時，那筆資料不得因此獲勝。**

**裁定 A（用戶，2026-08-16）**：排序欄位**存在但不可解析** ⟹ **降到最後，記錄仍保留**。
理由：§5.1.2 把這件事框在**排序**而非**有效性**上；且已簽名的那一半可能完全完好，
壞的只是收方自己的斷言半邊——對等點不該因為我們自己的紀錄壞掉而消失。

**裁定 B（用戶，2026-08-16）**：熵取不到 ⟹ **查詢失敗並具名回報**，不回任何樣本。
理由：§4.3.5.1 自己的論證是「把某一次任意截斷擺得像正準答案，那才是偽造」——
回一個假的樣本比不回答更糟。

## 3. 射程（四處，已逐一分類）

> **本節逐項列出呼叫點，是 Q-026 賺到的規則**：工單若要求改動一個被到處使用的寫法，
> **必須自己先列出呼叫點並標註用途**，不得寫「把所有 `unwrap_or` 都修掉」。
> §1.1 的表即為完整清單；**表中標「輸」與「中性」者一律不動**。

### 3.1 缺席與不可解析必須可分（`peers.rs`，三處）

`ts`（`:200`）、`received_at`（`:210`）、`admission_seq`（`:230`）。

*   **缺席**：維持今日行為（舊引擎寫的記錄，得排在前）。
*   **不可解析**：**排在所有可解析記錄之後**（裁定 A），**且記錄仍載入、仍可被撥號**。
*   **不得以值域內的一個合法值代表「不可解析」**（例如 `u64::MAX`）——那是把一個
    哨兵塞進資料值域，與 `.oo/format` 的裸數字、CAS 物件自陳編碼同族。
    **應以獨立的欄位或型別承載該事實**（拼法不限）。
*   `cmp_admission_order`（`:61`）須據此排序；**它是 `pub`，簽章可改**。

### 3.2 熵失敗必須具名失敗（`oodp.rs`，一處）

`random_below`（`:1133`）取不到隨機性時**不得回 0**；`sample_uniform_cap`（`:1115`）
須能把該失敗往上傳，`#discover` 的處理（`:1090`）據此**回一個非 `#success` 的回應**。

*   **`%reason` 不得重用 `#malformed` 或 `#rejected`**——〔量〕現有詞彙為
    `#conflict／#malformed／#rejected／#stack_overflow／#success`，前兩者都是
    **請求方錯誤**，而這是**實作說「我做不到」**，屬 `#stack_overflow` 那一族
    （ERROR_CODES §2.7.3 已立此分野）。**須新增一個標籤**；
    **最終拼法於規格收尾定案，探針只釘性質不釘字面**。
*   **不得**在此路徑上退回任何樣本，亦**不得**回一個空的 `#success`
    ——那會與「目錄真的是空的」無法區分。

### 3.3 隨機來源必須可注入（否則 §3.2 無法被測）

〔量〕`SystemRandom::fill` 在 Linux 上幾乎不會失敗，**故該失敗路徑今天沒有任何測試
到得了**。本弧**必須**讓 `sample_uniform_cap`／`random_below` 的隨機來源成為參數
（trait 或閉包皆可），使一個**必定失敗的來源**可由測試注入。

> **⚠ §3.2 與 §3.3 在本弧的探針檔中無探針。** 整合層到不了熵失敗路徑。
> **交付方須自行附上一支單元測試**（注入必定失敗的來源，斷言查詢具名失敗且不回樣本），
> 放在 `crates/interpreter/` 內；驗收方會檢查它存在、且**移除該來源注入後它會紅**。
> **不要因為探針檔裡沒有它就跳過 §3.2／§3.3。**
