# 一個只走了一跳的標記（Q-129）

探針：`crates/oo/tests/a_label_that_went_one_reader_deep_probe_test.rs`（不得修改）。
佇列：`nlang-spec/meta/WORK_QUEUE.md` §3「2026-11-16 — 開 Q-129」。

## 0. 判準

*   **一筆寫入的欄位是集合**（`SYNTAX_03` §2 #1）：同一組欄位不論以什麼順序寫、分幾個檔、分幾次 `evolve`，存出同一顆根。
*   **後到的名字把它的標記給讀它的坐標**（Q-128 M2）——**讀者的讀者也是讀者，不論隔幾跳**。一個坐標的標記是它讀到的值的標記；它讀的值的標記因為一個後到的名字而變了，它的標記也跟著變。
*   **不須裁**：Q-128 M2 已寫，本卡把它兌現到任意跳數。

## 1. 缺陷

〔量，`v0.127.0` 標籤建置；`acc/q129/recon.sh`、`pins.sh`、`revroots.sh`；讀碼〕

*   **三跳以上，順序不同，根不同**：`a: [b]`、`b: [c]`、`c: [d]`、`d: [p]`、`p: ~%Env.get …` 寫在同一次 `evolve`。讀者先寫，`status` 裡 `a`、`b` 沒有 `#io`（`c`、`d` 有），提交存的根與名字先寫的不同；三種順序三顆根（`0e459372…`／`6f02383e…`／`67fad1fd…`）。清單、記錄、清單與記錄交錯、local、型別軸與規則在中間、`+`、`_.` 路徑、聯集、路徑進記錄，都一樣（§3 的十三形）。
*   **成因一**〔讀碼＋原型驗證〕：`restamp`（完整交會之後）與 Q-128 的就地落地，都對讀者跑一次 `refresh_thunk_effects`，標記由 `predict_effect` 給，而 `predict_effect` 讀的是**工作集裡那個值存著的標記**——重新蓋章之前的那一份。所以一次只傳一跳。兩跳看起來對，是因為提交那個行程載入工作集時（`load_staged`）又多蓋了一跳；`status` 不寫回，跑幾次都一樣。
*   **成因二**〔讀碼＋修法驗證〕：**記錄自己的標記**（`ComboVal.effect`，印成 `} ;; %effect: #io`）在重新蓋章時從不更新——只更新欄位裡 thunk 的標記。記錄建出來時，它的標記是欄位標記的聯集（`eval.rs` 記錄字面那段）；名字先寫，`b: { y: p }` 建出來就帶 `#io`，讀者先寫則永遠是純的，讀它的 `a: { x: b }` 讀到純的。所以記錄連兩跳就兩顆根。
*   **為什麼現在要修**：Q-127 的參考把一筆寫入關掉效應試算到不動點，假設每一趟與順序無關；IO 鏈每一趟有 4 格在兩種順序之間擺動、永遠不收斂，跑滿 N+1 趟（N=100 28 秒，v0.127.0 1.26 秒）。原型修好本卡的事之後 2 趟收斂（2.37 秒）。

## 2. 依據；位址

*   **不須裁**（§0）。
*   **位址**：**名字先寫（完全反序：名字最前，每個讀者在它讀的東西之後）的根一顆都不動**——r1 十三形釘的就是 v0.127.0 那一顆；g1 的一跳、兩跳、一跳的記錄、函式鏈、純名字寫在最後、十層純鏈，根同 v0.127.0。**移動的是其他順序的根**：讀者寫在名字之前、隔三跳以上（記錄是兩跳以上），根變成名字先寫的那一顆。**是破壞性條目**（收尾時寫進 `CHANGELOG`）。
*   **Q-128 r2 有一格的工作集文字會變**：讀者先寫時 `b: { q: p ;; %effect: #io }` 會多一個記錄自己的 `;; %effect: #io`，與名字先寫時相同。那一格比的根本來就相同，根不動。驗收方預先修訂（§7）。

完整交會之後的 `restamp`：先把六個軸上每個值的標記簽名記下來，再對整份工作集跑一輪 `refresh_combo_thunks`。這一輪讀的是蓋章之前的那一份（`ctx.staged` 是刷新前的複本）：thunk 的標記被 `predict_effect` 換掉，記錄自己的標記只併上 data 與 local。寫回之後，簽名變了的鍵就是這一輪的源。`settle_labels` 用整份工作集掃出來的讀者表，把這些源的讀者、以及那些讀者的讀者收進閉包，先把閉包裡每個 thunk 的標記清成純的，再一輪一輪只加不減。每一輪的 `ctx.staged` 是上一輪寫回去之後的那一份（第一輪則是清成純的之後）。一輪裡沒有值的簽名變，就停。`restamp` 尾端原本那次整份 `refresh_combo_thunks` 拿掉了，否則會再讀一次舊標記、把多跳蓋回去。

就地落地：新值在放進工作集之前先 `refresh_thunk_effects` 一次（它不讀這批新名字，放之前與放之後相同）。放進去之後，索引裡直接讀到新名字的坐標再 `refresh_thunk_effects` 一次，讀的是名字已經在工作集裡的那一份。然後以這些直接讀者為源呼叫 `settle_labels`，讀者表先問 Q-128 的索引；索引答不出來（名字在 `opaque`）就改用整份工作集的讀者表，再跑一次 `settle_labels`。所以第一跳讀的是落地之後的工作集，往後每一跳讀的是上一輪留下的那一份。

`load_staged` 仍呼叫 `restamp_thunk_effects`。那條路現在也跑到沒有標記再變為止，不再只多蓋一跳。

**Q2。** 「變了」比的是 `effect_sig` 走出來的那一串 `EffectTag`，順序固定。

*   `Thunk`：它自己的 `effect`。走，會改。
*   `Combo`：自己的 `effect`，再加上 data、rules、types、meta、system、local、`pending_spreads` 裡每個值。走。沒封閉時，自己的標記再併上 data 與 local 的 `effect()`（繭 `closed` 不動，GUIDE_03 §4.2.1）。型別、規則、meta、system 裡的 thunk 會重蓋，不併進這顆記錄自己的標記。

**Q3。** 受影響的讀者先一次清成純的。之後每一輪只做併集（`EffectTag` 是四個位元的集合併，只有加）。一個值的簽名是有限長的一串標記，每一格最多升到四個位元都在，不能無限升。閉包是工作集裡有限個鍵，同一個鍵只進一次。一輪只有簽名真的變長的值才會把它的讀者排進下一輪；一個值不變，就不再把環上的下一個推進去。所以環（`a: [b, p]`、`b: [a]`）會停，沒有輪數上限、也沒有跳數上限。多條路讀到同一個讀者時，那個讀者在閉包裡只有一格，每條路讓它再升一次，升完就不再排。
