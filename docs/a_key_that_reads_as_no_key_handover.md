# 工單：一把讀不到的金鑰被讀成沒有金鑰（Q-054）

> 佇列 `nlang-spec/meta/WORK_QUEUE.md` Q-054／裁定 `meta/oo/STATUS.md` **O91**
> 探針（已預先提交並校準）`crates/interpreter/tests/a_key_that_reads_as_no_key_probe_test.rs`
> 基線：dev `cbfd95d`／`oo v0.56.0` ⟹ **5 綠 4 紅**，三輪一致、零空洞讀數。

## 1. 缺陷

`node_id_if_present()`（`lib.rs:1103`）與 `Ouroboros::init` 裡的兩個讀取（`lib.rs:948`／`957`）
都用 `Identity::load(..).ok()`。**三個狀態塌成兩個**：

```
不存在                → None
存在但讀不到          → None      ← 缺陷
存在且讀得到          → Some(id)
```

而下游 `peers::load` 把 `None` 讀成「還沒有節點金鑰」，並且
`restore_asserted = this_node_id.map(|id| id == owner).unwrap_or(false)`（`peers.rs:319`）
⟹ **一把讀不到的金鑰不只是換個順序，它把每一筆記錄的觀測半邊整個丟掉**：
`addr` 清空、`provenance` → Unknown、**`admission_seq` → 0**，且路由表未播種、為空。

## 2. 為什麼這比「順序不同」嚴重

`local_seat_rank` 用**讀者自己的** node id 加鹽。它的理由逐字記在
`crates/oo/tests/seat_order_probe_test.rs` 表頭：一個與受害者無關的繫結破法，
讓攻擊者 grind 一把金鑰（SPEC_15 §7.1 量到 3,500 keys/s）就能
「在每一個曾在同一秒聽見你的節點上都佔一個席位」。

**讀者的 id 缺席時，那個雜湊只剩 `sha256("oodp-seat-order:v1:" + "|" + peer_id)`
——只由同儕自己的身分決定。**

那就是 `seat_order` 那一弧的 **C′**，它被立為 MUST NOT 而**刻意沒有探針**，
理由是「一旦到達順序是全序，它就不可達」。**它可達**：
一把讀不到的金鑰把每一筆的 `admission_seq` 歸零，
⟹ **它自己製造出那個繫結，然後用只由同儕身分決定的方式去破它**，
而且**在任何目錄上都成立，不限 legacy**。

## 3. 已量（驗收方，2026-09-22，`oo v0.56.0`）

*   **寫入視窗是真的且還開著**：200 次真實鑄造，0 位元組可見視窗 **120／200**，
    部分寫入 **0／200**（永遠不會讀到半把金鑰，只會讀到空的）。
*   **`oo status` 對金鑰的四種狀態完全無差別**（完好／0 B／20 B 垃圾／不存在）：
    同 rc、同輸出；而**同一把垃圾金鑰 `oo node id` 拒絕 rc=1**「not a valid PKCS#8」。
    ⟹ **拒絕已經存在，准入那條路沒去問。**
*   **一個讀者會等，三個不會**：`load_after_race` 只被 `load_or_mint` 用（`value.rs:2653/2658`），
    而 `948`／`957`／`1117` 是裸 `Identity::load`；**且 948／957 對同一把金鑰載入兩次**。
*   `Ouroboros::init` 耗時 **14–18 ms**，而金鑰讀取在它尾端（這是探針 `WINDOW=60ms` 的依據）。

## 4. 射程＝不變式（不是機制）

*   **I1（丁）** 任何一般讀取路徑，**不得**在磁碟上存在一把完整身分、且在 **Q-051 已裁的

    ⚠ **那個不變式在 Q-051 就已經以強形式被接受**——「等過**任何**暫時不完整的身分檔」
    ——而它今天只落在**四個讀取點的一個**。本項是補完，不是新裁定。
*   **I2（甲）** 當身分檔存在、且**等過之後仍讀不到**時，其結果**不得與「根本沒有身分」
    在觀測上相同**。⚠ **本工單不指定形式**：具名拒絕、回報降級、三態型別皆可，
    **探針 R3 對機制無知**。你選，並在報告裡寫為什麼。
*   **I3** 一把**永久**無效的金鑰**必須**仍然是錯誤，且其位元組**逐字未變**（Q-051 G2／D2）。
    **等待不得變成接受。**

## 9. 交付回報（交付方填；本行以上一字不得動）

### 9.1 射程

**I1**　`Identity::load_if_present`：檔案不在 → `Ok(None)`；在 → `load_after_race`（100×1ms）。
`Ouroboros::init` 與 `node_id_if_present` 的磁碟讀取都走它。不鑄造。

**I2**　等完仍讀不到 → `init` 回傳那個 `Err`（訊息含 `not a valid PKCS#8`），
**不**把引擎建起來再當成沒有節點。R3／R4 因此與「不存在」不同（一個 `Err`、一個 `Ok`）。
`node_id_if_present` 的回傳型別沒改（見 Q2）。

**I3**　`Identity::load` 本身不重試、不覆寫。G1 綠。永久 0 B／20 B 的 `oo status` rc=1，位元組未變。

**I4**　G2 綠。`load_if_present` 不呼叫 `create_new`。

### 9.2 順手改動

無。未動 `bn_serial`、未動探針、未 `rustfmt`。

### 9.3 工單哪裡是錯的

無。R1／R2 的時鐘見 9.5，不是工單寫錯。

### 9.4 Q1–Q4

**Q1**　等待加在 `load_if_present`，呼叫點是 `init`（原 948 與 957）和 `node_id_if_present` 的磁碟回讀。
948／957 **併成一次**：同一把 `Identity` 填 `this_node_id` 與 `node_identity_cell`。

永久損壞金鑰，每次 `oo status`（n=5）：

| 狀態 | rc | 耗時 min／p50／max | 相對完好 |
| :-- | --: | :-- | :-- |
| 不存在 | 0 | 12.4／12.9／13.4 ms | — |
| 完好 | 0 | 12.2／13.3／13.8 ms | 0 |
| 0 B | 1 | 113.1／113.8／118.7 ms | **約 +100 ms** |
| 20 B | 1 | 113.8／116.3／119.2 ms | **約 +103 ms** |

是**一次** 100 ms 預算，不是三點各一次。位元組未變。訊息：`not a valid PKCS#8 … file left unchanged`。

**Q2**　形式是 **`init` 具名拒絕**。理由：下游把 `None` 讀成「還沒有節點」；只要 `init` 成功，R3 的觀測就會再塌回去。拒絕讓工作區根本開不起來，觀測上不同於「開得起來且沒有節點」。

`node_id_if_present` 仍回 `Option`。改成 `Result` 會擴散到 `reconstruct_automatic_remotes`、`peers::verify_loaded`。那些呼叫發生在 `init` 已經成功之後；永久讀不到的情況在 `init` 就停了，到不了它們。
冷回讀（cell 空、檔後來壞了）仍把 `Err` 收成 `None`——`Option` 說不出第三態。這是留下的縫，不是 R3 的路徑。

**Q3**　裸 `.ok()`／`unwrap_or` 讀節點金鑰：修補前是 `init` 兩處和 `node_id_if_present`。現在 `node_id_if_present` 的回讀仍 `.ok().flatten()`（見 Q2）。
`oodp` 只讀 affiliation 檔，不讀節點私鑰。
`node_key_path` → `resolve_node_home` 失敗（相對 `OO_NODE_HOME`、無 `HOME`）在 `init` 仍走 `Err(_) => None`。那是永久設定錯誤，等待碰不到，今天仍變成「沒有節點」。未改。

**Q4**　不決定。R4 現在兩側都是 `init` 拒絕，所以「兩個讀不到的節點默默算出同一個順序」這條路斷了。`seat_order_probe_test.rs` 要不要再長一支 C′ 探針，是規格問題；本弧沒加。

### 9.5 探針

一字未改。C1／C2／G1／G2／G3／R3／R4 綠。

**R1／R2：`VOID READING`，不是失敗也不是通過。** 兩支 panic 印出的 `Saw` 都是 `Some(<那把金鑰的 CAID>)`——等是等到了。
但讀完時刻晚於寫入戳記約 **11 ms**（R1）／**25 ms**（R2）：`load_after_race` 在寫入之後才返回，後面還有 `init` 的尾巴，探針因此作廢這次讀數。
三輪全樹皆同。未改 `WINDOW`、未改宣稱。
