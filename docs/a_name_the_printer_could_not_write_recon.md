# 偵察：一個 printer 寫不出來的名字

> 開單 2026-08-20。基線 `nlang-tools dev`（v0.26.1）、`nlang-spec local`（v0.26.1-draft.1）。
> **裁定已在先**：`nlang-spec/meta/oo/quoted_names.md` §4——Q1「引號內即純名字，
> 前綴不例外」、Q3「印出端的引法與 Q1 同批」、Q2「分開」。
> **本單只偵察，不改規格、不改引擎。**

---

## 1. 一句話

規格規定了**輸入端**何時必須引用鍵（SYNTAX_03 §104 #6、§106 #8），
**沒有任何條款規定輸出端** ⟹ 一個名字叫 `a.b` 的**單一座標**印出為 `a.b: 1`，
讀回去是**兩個座標**，**不報錯**。

---

## 2. 缺陷的兩個面

〔量，v0.26.1〕

| 源碼 | 印出 | 讀回去 | 嚴重度 |
| :--- | :--- | :--- | :--- |
| `{ "a b": 1 }` | `a b: 1` | parse error | 吵著失敗 |
| `{ "a.b": 1 }` | `a.b: 1` | `refl.keys` ＝ `["a"]`，`x.a` ＝ `{ b: 1 }` | **靜默換值** |

而 SYNTAX_03 §106 #8 明文說二者語義不同（「前者單一座標、後者巢狀」），
〔量〕CAID 亦不同、`=` 為 `#false`。

---

## 3. 射程：四類點，數量已量

| 類 | 位置 | 數量 |
| :--- | :--- | ---: |
| **引號性遺失處** | `crates/interpreter/src/universe.rs:35`——`FieldKey::Quoted(name) => vec![name.trim().to_string()]` | **1** |
| **對引用鍵測前綴處** | `universe.rs:182`——`FieldKey::Quoted(name) if name.trim().starts_with("~%")` | **1** |
| **前綴→軸 的路由** | `value.rs` 的 `key_trimmed.starts_with(…)`（`insert_field` 等） | **20** |
| **軸→前綴 的顯示** | `value.rs:1064–1079` 一族 `format!("/{}", k)` | **12** |

**承重的結構事實**：〔讀〕**前綴不是被儲存的鍵的一部分**——它由「這個鍵住在哪個軸的
map」在顯示時重建。⟹ 一旦 Q1 使「資料軸上名叫 `@t` 的鍵」成為可能，
**顯示就不再是單射**，除非 Q3 的引法同時落地。**Q3 不是配套，是 Q1 的可行性條件。**

**好消息**：〔讀〕AST **保住了** `FieldKey::Quoted` 與 `FieldKey::Named { name, prefix }`
的區分。引號性是在 AST→值的那**一個**邊界上被丟掉的，不是在 parser 裡。

---

## 4. Q2 的隱含依賴（本偵察的主要發現）

〔量〕標準根共 **238** 個相異的（軸,鍵），新規則下**需要引號者恰為 3 個**：

```
rules / "%differential.1"    rules / "%differential.2"    rules / "%differential.3"
```

〔量〕它們今天顯示為 `/%differential.1`——**rules 軸（`/`），而名字本身是
`%differential.1`**（既以 `%` 起首，又含 `.`）。

⟹ Q3 之下這三個鍵**印不出來**，除非二選一：

| | 做法 | 代價 |
| :--- | :--- | :--- |
| **A** | 實作 Q2（`prefix ~ quoted`），印為 `/"%differential.1"` | 新文法形式；而 Q2 已裁為「分開處理」 |
| **B** | **改名這三個鍵**，使標準根無任何鍵需要引號 | **移動標準根 digest** |

**建議 B**，三個理由：

1.  〔量〕**它們是 238 分之 3**，且是唯一的三個 ⟹ 為三個內部鍵引進一個新文法形式，
    代價不對稱。
2.  Q-033 審計 §5 已判定它們是**引擎內部 arity 多載編碼漏進使用者可見座標**
    ——**本來就該改**，不是為了本弧才改。
3.  **digest 移動已經排隊了**：`~%Str` 改名、`/add` 移除、`~%Official` 移除三項
    皆動標準根內容（`d2_what_gets_constitutional_status_brief.md` §4）。
    照 `WORK_QUEUE` §9.0「身分只該搬一次」，**第四項搭同一班車成本為零**。

⟹ **採 B 則 Q2 維持真正獨立**（是 nice-to-have，不是擋路的）。

---

## 5. 改動的爆炸半徑：Q1 為零

〔量 2026-08-19〕**沒有任何一份 n/ 程式碼寫過帶前綴的引用鍵**：
`conformance/` 286 向量 **0** 處；`spec/zh_TW/*.md` 全部範例 **0** 處；
引擎測試 2 處命中皆為**線上協定的 JSON payload**，非 n/ 源碼。

⟹ **語義上是 Layer 1 的改動，經驗上沒有任何既存位址會移動。**
**切版時的軸別判定需另行裁定**（規則變了但無人受影響——與過往的身分軸破壞不同形），
不在本偵察射程。

---

## 6. 規格側缺的那一條

**歸屬是規格的鍋**〔讀〕：§104 #6 與 §106 #8 只規範輸入端。
任何符合規格的實作都會撞上 ⟹ **先補規格的 MUST，再由引擎兌現**。

**建議的正準形（待寫成條文）**：**非純識別碼即加引號**
——單純、可機械檢查，且與 §104 #6「純識別碼鍵不應多餘加引號」互為逆。

**須同時裁的一格**：`quoted_key` 〔讀，SYNTAX_02 §106 #11〕**無跳脫序列**
⟹ 名字含 `"` 字元者**寫不出來也印不出來**。目前無人踩到，但一旦規定
「印出端必須引用」，**印出端就會遇到一個它無法表達的名字**。
選項：禁止此類名字（輸入端加 MUST NOT）／為 `quoted_key` 引進跳脫／用多行字串形式。
