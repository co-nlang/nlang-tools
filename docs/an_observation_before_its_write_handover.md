## 0. 判準

*   **一筆寫入的欄位是一個集合**：`SYNTAX_03` §2 #1「欄位順序無關」；`SPEC_10` §2.2.3（Q-124）「同一筆 pin 寫入裡的欄位彼此交會、與順序無關」；`SPEC_03` 同時性：`oo run` 的所有檔、所有欄位是一個快照。一筆寫入＝一個演化指令（含它的每一個檔）；`oo run`／`oo test` 的一個程式、`repl` 的一行同理。
*   **觀測效應的格存它觀測到的答案**（D110「效應格照 D46 ② 存答案」，D46 ②）；提交存的是那一格的值（`SPEC_10` §2.3.1「提交**必須**捕獲其強制求值後的值」）。所以那個答案必須是那一格在它所屬那筆寫入落地之後的宇宙裡的答案——不是寫到那一行時看得到的綁定。
*   **`_.` 與裸名字讀同一個宇宙**：D110 把 `_.` 算作「讀到宇宙」，與名字同列；演化時名字讀 HEAD 與工作集。
*   一句話：**一個在演化時觀測的欄位，觀測的是它那筆寫入寫完之後的宇宙；它寫在第幾行、哪個檔、名字怎麼拼，答案都一樣，效應只做一次。**

## 1. 缺陷

〔量，v0.124.0（tools `dev` `314f9a4`）；`acc/q125/cells.sh`、`probe2.sh`–`probe5.sh`；行程設 `Q125_A=alpha`〕

*   **pin 改寫一個名字，同一筆寫入裡讀它的觀測欄位讀到舊的**：`g: (n -> ~%Env.get "HOME")`、`k: g 1` 提交後，一個 pin 檔 `k: g 1`、`g: (n -> n)` ⟹ 提交成功，根裡 `k` 存成 HOME 的值（`#cached`）；同一個檔寫成 `g: (n -> n)`、`k: g 1` ⟹ `_.k` 讀 `1`。經工作集（先 pin `g` 成 IO 再 pin 回來）、分成兩個檔、換成另一個 IO 函式、經記錄欄位 `h.f`、經另一個觀測欄位（`k: [q, 1]`，`q` 讀 IO）同。
*   **一般寫入收窄或帶來那個名字**：`p: "HOME" | "USER"` 提交後寫 `k: ~%Env.get p`、`p: "HOME"` ⟹ `k` 存兩個值的聯集；`p: @string` 之後同形 ⟹ `k` 存**內建函式本身**；`p` 是這筆寫入新寫的 ⟹ 同，**效應一次都沒做**（`~%Io./append_file (p, "x")` 寫在 `p` 前面：檔案 0 位元組）。反序都對。
*   **pin 的效應落在錯的地方**：HEAD `p` 指檔 A，一個 pin 檔 `k: ~%Io./append_file (p, "x")`、`p: <檔 B>` ⟹ 寫進的是 **A**。
*   **`_.p` 在演化時只讀 HEAD**：`p: "HOME"` 演化之後，下一次演化 `k: ~%Env.get _.p` ⟹ `k` 存內建函式；寫成 `~%Env.get p` ⟹ HOME 的值。同一筆寫入兩種順序都錯。純的 `_.x + 1` 存配方、讀時才解，所以沒事。
*   **`oo run`、`oo test`、`repl` 同**：`oo run` 一個檔 `k: ~%Env.get p`、`p: "Q125_A"` ⟹ 印內建函式；`oo test` 同形 ⟹ `test_k: k & "alpha"` FAIL（`Conflict`）；`repl` 一行 `k: ~%Env.get p, p: "Q125_A"` 同。
*   **起因**：演化逐欄求值；`evolve_field` 對讀了宇宙的**純**答案換回配方（D110），**效應**答案當場留下——用的是寫到那一行時的語境（前幾行、工作集、HEAD）。`_.` 的起點是 `ctx.root`（HEAD），不看 `ctx.staged`。名字還不存在時，算術與呼叫答 `_`（延後成配方），而 `~%Env.get _` 答內建函式本身（既有，Inbox「內建對 `_` 給 ⊥」那一族），所以不延後。
*   **對照**：純欄位兩種順序同根（`p: 1 | 2` 之後 `k: p + 10`、`p: 1` ⟹ `1c3d594f…`）；觀測欄位讀的名字不是這筆寫入寫的 ⟹ 與 v0.124.0 同。

## 2. 依據；位址

*   §0 各款。不須裁：寫入是集合（`SYNTAX_03` §2 #1、Q-124 開卡時已兌現的一半）、觀測格存答案（D110／D46 ②，觀測時點不變——仍在演化時）。
*   **位址**：純的寫入、觀測欄位讀的名字不是這筆寫入寫的——根都不動（g1 兩顆根逐位元組寫死）。錯的那個順序的根改成對的那個順序的根（破壞性，收尾記 `CHANGELOG`）。
*   跨演化不在本卡（§6）：觀測之後，**後來另一筆寫入**改了它讀的名字——那是「觀測在什麼時候」的問題，要裁。

## 3. 射程＝不變式（不是機制）

*   **M1 一筆寫入裡的觀測欄位，讀這筆寫入寫的名字**（r1 pin、r2 一般寫入）：不論它寫在那個名字之前或之後、在同一個檔或同一指令的另一個檔、名字是新的、被收窄的、或被 pin 換掉的；觀測欄位讀另一個觀測欄位時，讀它這一筆的答案。**兩種順序同根、同讀數**；讀數是對的那一種。
*   **M2 `_.n` 在觀測的欄位裡讀 `n` 讀的東西**（r3、r1 `_.g`）：演化時是 HEAD 與工作集——之前的演化、同一筆寫入。私有名字 `_.~h` 照舊拒（g1）。
*   **M3 效應做一次、做在寫入說的地方**（r4）：`~%Io./append_file` 在演化時做一次；`status`、`eval`、提交不再做；pin 換掉路徑時寫進新的那個檔，舊的那個不動。
*   **M4 所有逐欄演化一個程式的路徑**（r5）：`oo evolve`（含 `--pin`、多檔）、`oo run`（多檔）、`oo test`、`repl` 的一行。
*   **另一半**（g1）：純欄位的根不動（兩種順序同一顆、與 v0.124.0 同）；觀測欄位讀的名字不是這筆寫入寫的 ⟹ 照原位求值、根不動；pin HEAD 已持有的 ⟹ 已持有；衝突照指名座標；`_.~h` 照拒。
*   **上一張卡學到的，逐條過**：
    *   不變式在所有路徑都經過的那一處判：逐欄演化一個程式的有五處（`evolve_files`、`run_one_shot`、`run_test`、`run_repl`、`run_eval`——最後一個只有一欄）；
    *   必答題裡點名的路徑，驗收方先自己量過（`oo test`、`repl` 已量，見 §1）；
    *   「做 Y」配「不做 Y」：重排只動觀測且讀這筆寫入名字的欄位；純欄位、不讀這筆寫入的觀測欄位不動（g1 根寫死）；
    *   效應次數（Q-112）：以 `append_file` 的位元組數量，演化、`status`、`eval`、提交各量一次。

## 5. 必答（請在交付報告裡回答，逐題）

*   **Q1 誰等**：你怎麼判一個欄位「觀測效應」（預測、求值後、別的）；用哪個視角預測（工作集、HEAD、兩者）——量一格兩個視角不一致的（HEAD 的 `g` 是 IO、工作集的 `g` 是純的，`k: _.g 1`）。
*   **Q2 等待者之間**：兩個觀測欄位互讀（`k` 讀 `q`、`q` 讀這筆寫入的 `p`）怎麼排；成環時怎麼辦——量一格環（`a: [b]`、`b: [~%Env.get a]` 之類），列讀數。
*   **Q3 `_.`**：你讓 `_.` 在哪些求值裡讀工作集；為什麼 `<<_.m>>`（`a_reference_that_bound_what_it_read` r5）與 `_.~h` 不受影響。
*   **Q4 錯誤的歸屬**：等待的欄位撞衝突時，`Evolution Conflict in "<檔>"` 的檔名、指名的座標是哪一個——量一格兩個檔。
*   **Q5 成本**：§7 的四個形狀各量兩個 N，對照 v0.124.0。

## 6. 明文不在射程內

*   **跨演化**：`k: ~%Env.get p` 演化之後，下一次演化才把 `p: "HOME" | "USER"` 收窄成 `"HOME"` ⟹ `k` 留著兩個值的聯集（兩次演化反序則對）。觀測之後，後來的寫入改了它讀的名字——觀測在演化時（D110）還是提交時（`SPEC_10` §2.3.1）要裁。Inbox。
*   **pin 把 IO 的值換成純的之後，根照帶 `#io`**：每個讀數（連無關的 `_.x`）帶 `#io`，根與直接寫同一個值不同（v0.123.0 起）。效應標記沒有隨覆寫重算，不是觀測讀錯綁定。Inbox。
*   **`=` 把效應算進比較**：`(~%Env.get "HOME") = "/home/gali"` 答 `#false`。Inbox。
*   **內建對還不是值的運算元答內建本身**（`~%Env.get _`、`~%Env.get @string`）——D119 說值語境答 `_`；本卡讓它不再被存下，內建本身的答案不改。併入 Inbox「內建對 `_` 給 ⊥，`+` 給 `_`」。
