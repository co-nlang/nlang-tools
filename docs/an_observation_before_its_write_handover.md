## 0. 判準

*   **一筆寫入的欄位是一個集合**：`SYNTAX_03` §2 #1「欄位順序無關」；`SPEC_10` §2.2.3（Q-124）「同一筆 pin 寫入裡的欄位彼此交會、與順序無關」；`SPEC_03` 同時性：`oo run` 的所有檔、所有欄位是一個快照。一筆寫入＝一個演化指令（含它的每一個檔）；`oo run`／`oo test` 的一個程式、`repl` 的一行同理。
*   **觀測效應的格存它觀測到的答案**（D110「效應格照 D46 ② 存答案」，D46 ②）；提交存的是那一格的值（`SPEC_10` §2.3.1「提交**必須**捕獲其強制求值後的值」）。所以那個答案必須是那一格在它所屬那筆寫入落地之後的宇宙裡的答案——不是寫到那一行時看得到的綁定。
*   **`_.` 與裸名字讀同一個宇宙**：D110 把 `_.` 算作「讀到宇宙」，與名字同列；演化時名字讀 HEAD 與工作集。
*   一句話：**一個在演化時觀測的欄位，觀測的是它那筆寫入寫完之後的宇宙；它寫在第幾行、哪個檔、名字怎麼拼，答案都一樣，效應只做一次。**

## 1. 缺陷

〔量，v0.124.0（tools `dev` `314f9a4`）；`acc/q125/cells.sh`、`probe2.sh`–`probe5.sh`；行程設 `Q125_A=alpha`〕

*   **pin 改寫一個名字，同一筆寫入裡讀它的觀測欄位讀到舊的**：`g: (n -> ~%Env.get "HOME")`、`k: g 1` 提交後，一個 pin 檔 `k: g 1`、`g: (n -> n)` ⟹ 提交成功，根裡 `k` 存成 HOME 的值（`#cached`）；同一個檔寫成 `g: (n -> n)`、`k: g 1` ⟹ `_.k` 讀 `1`。經工作集（先 pin `g` 成 IO 再 pin 回來）、分成兩個檔、換成另一個 IO 函式、經記錄欄位 `h.f`、經另一個觀測欄位（`k: [q, 1]`，`q` 讀 IO）同。
*   **一般寫入收窄或帶來那個名字**：`p: "HOME" | "USER"` 提交後寫 `k: ~%Env.get p`、`p: "HOME"` ⟹ `k` 存兩個值的聯集；`p: @string` 之後同形 ⟹ `k` 存**內建函式本身**；`p` 是這筆寫入新寫的 ⟹ 同，**效應一次都沒做**（`~%Io./append_file (p, "x")` 寫在 `p` 前面：檔案 0 位元組）。反序都對。
*   **pin 的效應落在錯的地方**：HEAD `p` 指檔 A，一個 pin 檔 `k: ~%Io./append_file (p, "x")`、`p: <檔 B>` ⟹ 寫進的是 **A**。
*   **`_.p` 在演化時只讀 HEAD**：`p: "HOME"` 演化之後，下一次演化 `k: ~%Env.get _.p` ⟹ `k` 存內建函式；寫成 `~%Env.get p` ⟹ HOME 的值。同一筆寫入兩種順序都錯。純的 `_.x + 1` 存配方、讀時才解，所以沒事。
*   **`oo run`、`oo test`、`repl` 同**：`oo run` 一個檔 `k: ~%Env.get p`、`p: "Q125_A"` ⟹ 印內建函式；`oo test` 同形 ⟹ `test_k: k & "alpha"` FAIL（`Conflict`）；`repl` 一行 `k: ~%Env.get p, p: "Q125_A"` 同。
*   **起因**：演化逐欄求值；`evolve_field` 對讀了宇宙的**純**答案換回配方（D110），**效應**答案當場留下——用的是寫到那一行時的語境（前幾行、工作集、HEAD）。`_.` 的起點是 `ctx.root`（HEAD），不看 `ctx.staged`。名字還不存在時，算術與呼叫答 `_`（延後成配方），而 `~%Env.get _` 答內建函式本身（既有，Inbox「內建對 `_` 給 ⊥」那一族），所以不延後。
*   **對照**：純欄位兩種順序同根（`p: 1 | 2` 之後 `k: p + 10`、`p: 1` ⟹ `1c3d594f…`）；觀測欄位讀的名字不是這筆寫入寫的 ⟹ 與 v0.124.0 同。

### 8.4 工單指名要你回答的問題
