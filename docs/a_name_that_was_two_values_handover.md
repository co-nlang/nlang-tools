## 0. 判準

*   **提交存效應格觀測到的值**（`SPEC_10` §2.3.1，MUST；「判準是 `%effect`，而且只有 `%effect`」，`%effect` 指有效值，O61）：一個定義被求值時做了效應，存的就是它觀測到的答案，不論靜態預測怎麼說。只留定義，那次觀測就永久遺失，而且之後每讀一次都再做一次。
*   **觀測坍縮之後，活動標籤固化**（`SPEC_08` §4.2.4）：觀測過的不再做。
*   **一個名字在一次觀測裡是一個值**（`SPEC_04` §6 沿路徑坍縮；`SPEC_06` 等值）：一個座標（任一層記錄欄位，各軸）在一次觀測裡被讀幾次、經名字、經路徑 `q.a`、經別名 `b: a`、經另一個欄位 `k: q.a`，都是同一個值；它的效應做一次。`a = a` 是 `#true`。
*   **一次觀測**：一個 `oo eval`；`oo evolve`（含全部檔與 `--pin`）到 `oo commit` 的一筆寫入；`oo run`、`oo test` 的一個程式；`repl` 的一行。
*   **D129（乙，2026-11-09）**：工作集是惰性的。一個定義在 `oo evolve` 時若會強制一個惰性欄位、而那個欄位做效應，這個定義也留成配方，提交時與那個欄位在同一次觀測裡觀測（一個值、效應一次）。`oo run`、`oo test`、`repl`、`oo eval` 一個行程就是一次觀測，不延後。
*   **寫兩次的是兩個座標**：`[random (), random ()]`、`a: f 1, b: f 1`、兩個寫法相同的記錄 `q`／`q2`，各做一次，不得併。**施用不是座標**：`_.f 1` 每讀一次是一次施用；表的分支本體在選中前是程式碼（D109），選中兩次是兩次。用鍵讀記錄（`{ a: … } "a"`）是讀座標。
*   一句話：**一個寫下的效應，一次觀測做一次；觀測過的進歷史，之後不論怎麼讀都不再做；一個名字在一次觀測裡是一個值。**

## 1. 缺陷

〔量，v0.125.0（tools `dev` `67711b1`）；`acc/q126/recon1.sh`–`recon6.sh`；`h` 每呼叫一次在 `a.log` 寫 1 位元組並讀 `Q126`；提交時 `Q126=one`、之後讀 `Q126=two`〕

*   **歷史存配方，之後每讀一次做一次**：

    | 寫入（加上 `h`） | 提交後 | 再讀兩次後 | 讀到 |
    | :-- | --: | --: | :-- |
    | `q: { a: (s -> h s) "Q126" }` | 3 | 5 | `"two"` |
    | `q: { f: (s -> h s), a: f "Q126" }` | 3 | 5 | `"two"` |
    | `q: { a: h "Q126", b: a }`（讀 `b`） | 4 | 6 | `"two"` |
    | `q: { a: ~%List./map (h, ["Q126"]) }` | 3 | 5 | `["two"]` |
    | `q: { ~a: …, b: a }`、`{ /a: …, b: a }` | 6 | 8 | `"two"` |
    | 聯集成員、展開、cocoon、元組、三層巢狀、內層讀外層 | 3–6 | 5–8 | `"two"` |
    | pin `q: { a: (s -> h s) "Q126", b: a }` | 10 | 12 | `"two"` |

    `inspect` 根：`a: (s -> h s) "Q126"` 存的是語法。對照：`q: { a: h "Q126" }` 存 `"one" ;; %effect: #cached`、提交後 1、讀不再做。
*   **一個名字兩個值（歷史裡也是）**：`q: { a: ~%Math./random (), b: [a, a], e: a = a }` 提交後 `_.q.a` 穩定（`a` 被捕獲），`_.q.b` 每讀一次是兩個新的不同的數、`_.q.e` 是 `#false`；`q: { a: random () }`、`m: [q.a, q.a]`、`e: q.a = q.a` 存進根的是兩個不同的數與 `#false`。單次 `oo eval`：`{ a: (x -> ~%Math./random ()) 1, b: a = a }.b` ⟹ `#false`。
*   **讀惰性欄位的定義與那個欄位**：`q: { a: (x -> ~%Math./random ()) 1 }`、`k: q.a + 0` 提交後 `_.k` 與 `_.q.a` 不同（`k` 在演化時觀測了一次，`q.a` 提交時又一次）；兩次演化、或 `q` 先提交，同。
*   **單次 `oo eval` 的次數**：`{ r: (x -> A) 1 }.r` 3；`{ f: (x -> A), a: f 1 }.a` 3；兩欄 `a: f 1, b: f 1` 7；記錄欄位裡的 `~%List./map` 每元素 3；`A |> (_ -> _)` 2（`A` 是 `append_file`）。`oo test`、`repl` 一行各 2。
*   **起因**（讀碼與插樁，`acc/q126/trace_patch.py`）：
    *   `predict_effect` 是靜態的：箭頭一律 `#pure`、元組引數不看。這些欄位的 thunk 標成純的。
    *   Q-122 的 ⊥ 檢查（`late_bottom` → `read_bottoms` → `force_each_cell`）只跳過「預測不純」的 thunk，於是強制了它們：演化做一次。
    *   `project_for_commit` 對預測純的 thunk 強制只為判 ⊥、然後留配方：提交做一次、歷史存配方；`read_bottoms_of` 再一次。
    *   `oo eval`：答案經 `evolve_field`（`force_each_cell` 讀宇宙探測、`made_in_a_call`、`answer_syntax`）再 `observe_field_apart`。
    *   名字讀兄弟欄位時在框裡重新強制定義，一次觀測裡沒有共享。
    *   force memo 以不含位置的語法為鍵、收下帶 `#io` 的答案：`t 1` 選中同一分支兩次只做一次（D109 說是兩次施用）。

## 3. 射程＝不變式（不是機制）

*   **M1 提交存觀測到的**（r1）：提交或演化求值時做了效應的定義，存它的答案。判斷看效應有沒有發生，不看預測。每一種存形、每一個軸：記錄欄位（data、`~`、`/`）、巢狀、清單裡的記錄、元組成員、聯集成員、展開、cocoon（標記被遮蔽也一樣）、pin 的記錄。
*   **M2 簿記不觀測**（r1、r3、r4）：引擎為自己判斷所做的強制——⊥ 檢查（演化、提交）、讀不讀宇宙、是不是呼叫造的、印不印得回去——不做效應。列出每一處（§5 Q2）。
*   **M3 一個名字一次觀測一個值**（r2、r3）：同一個座標讀幾次、經名字、經路徑、經別名、經另一個欄位，都是同一個值，效應一次。同一個節點在一個行程裡可能有幾份讀回（演化時讀回的成員、提交投影的交會、讀者經名字找到的那份），都是同一個座標。
*   **M4 D129**（r5）：`oo evolve` 時，一個定義若會強制一個做效應的惰性欄位（同一筆寫入、較早的成員、HEAD 之外的記錄），這個定義留成配方；提交時兩者一次觀測。演化時不做；提交後總共一次；之後讀不再做。
*   **M5 所有路徑**（r4）：`oo eval`、`oo evolve`（含 `--pin`、多檔）、`status`、`commit`、`oo run`、`oo test`、`repl`。
*   **另一半**（g1）：
    *   寫法相同的兩個座標（同一節點的兩欄、兩個節點）永遠不是一次效應；`[A, A]` 兩次；內建高階函式每元素一次。
    *   讀 HEAD 的純配方照舊是配方、跟著 HEAD 走（D110）。
    *   讀一個**純**欄位、自己做效應的定義照舊在演化時觀測（D129 只管做效應的惰性欄位）。
    *   根不動：頂層效應格、v0.125.0 已捕獲的記錄欄位、純記錄。
    *   force memo 不跨座標、跨施用共用做過效應的答案。
*   **上一張卡學到的，逐條過**：
    *   存形×軸逐一判（Q-125 R-6）：§1 表是逐一量的，§6 列不在射程的形。
    *   所有路徑：M2 的簿記處 grep 每一個 `force*` 的呼叫者；M5 七條路徑探針各有一格。
    *   「另一半」每格配「之後再寫」（Q-105 R-3）：之後的寫入讀到已觀測的欄位——量了，見 §6 第一列。
    *   為列舉而重跑不得重做工作（Q-112）：表的分支、聯集分配各量一格。
