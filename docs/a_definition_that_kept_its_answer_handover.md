## 0. 判準（規格原文與裁定）

*   **D110（`nlang-spec/meta/oo/STATUS.md`）**：讀了宇宙的純衍生定義存配方，不存答案。「讀了宇宙」＝求值時讀到暫存或已提交的座標（或在那裡找不到）、`_.`、經名字到達的活引用或存起來的開放項。不讀宇宙的閉合式照舊存答案；構造（記錄、箭頭、表的字面量——即使模式鍵讀名字）不是衍生；`~%` 軸的名字是引擎鑄的，不算宇宙；效應格照 D46 ② 存答案。
*   **D46 ①（`SPEC_10` §2.3.1）**：`#pure` 的一格，強制後的值相對於 thunk 不是新資訊——**Commit 不得以答案取代定義**。D110 是它對「讀了宇宙」那些格的字面適用。
*   **`SPEC_07` §4.2.1 P3 與判例**：存起來的開放項就是它的定義；讀它就是在讀它的地方求它，在那個框架的 `$` 底下。
*   **`SPEC_12` §1.1 #2**：靜止環判定看的是**閉環中每一跳**是否純引用；環外的變換不在環上。
*   **`SPEC_10` 觀測 Savepoint（D91）**：一次性觀測「只讀到已存的非 thunk 資料 ⟹ **不得**產生」。

## 1. 缺陷

〔量，v0.92.0 標籤建置〕

*   **答案凍住**：先提交 `r: <<_.y>>`、`q10: r = 5`、`j1: _.z = 5`、`l: [_.z, 2]`、`s: ~%Str./len (_.u)`，再提交 `y: 5`、`z: 5`、`u: "ab"`：`q10`、`j1` 仍 `#false`，`l` 仍 `[_, 2]`，`s` 仍是讀到 `_` 時的部分施用——而就地 `_.r = 5`、`_.z = 5` 已 `#true`、`[_.z, 2]` 已 `[5, 2]`。`a: @int`、`b: a`、`c: a = 5` 提交後再提交 `a: 5`：`b` 仍 `@int`、`c` 仍 `#false`。
*   **程式內有書寫順序依賴**：`j1: z = 5` 寫在 `z: 5` 之前 ⟹ `#false`，之後 ⟹ `#true`；`[z]` ⟹ `[_]`／`[5]`。
*   **提交把引用上的計算存成 ⊥**：`n: 1`、`r: <<n>>`、`q: r + 1` 提交後 `q` ⟹ ⊥ `#conflict`（`run` 得 `2`）；`q7: (x -> x + 1) r`（`y` 未定義時）同。

*   **環的成因看讀者**：`c: { a2: b2, b2: a2 }` 的程式裡 `(c.a2).%cause` ⟹ `#static_cycle` 而 `(_.c.a2).%cause` ⟹ `#divergent`。

## 3. 射程＝不變式（不是機制）

*   **K1 讀了宇宙的定義，讀它就是重讀**：存起來的定義，讀它得到的與「同一句話在讀的當下就地寫」相同——跨提交（座標之後才補上、或之後被收窄）、程式內（書寫順序不影響答案）皆然（r1、r2；L2-133、134）。
*   **K2 提交不把讀數判成 ⊥**：判斷一個配方「是不是 ⊥」時讀到的，要是讀者會讀到的；真的 ⊥（`r & 2` 撞值、`c: c + 1`）照舊存 ⊥ 連同成因（r3）。

*   **K4 環的成因屬於環**：讀者在環外的變換不使純引用環變成 `#divergent`；環上有變換照舊 `#divergent`（r5；L2-136）。
*   **另一半——不讀宇宙的不動**：閉合式、構造、效應格（含讀了效應座標的定義，L2-83）的存形與根不變（g1）。
*   **另一半——一次性問題不是定義**：`oo eval` 的問題在問的地方作答，D110 不適用；讀到存著的非 thunk 資料不得留觀測 Savepoint，化約了 thunk 的照舊留一個——兩者逐格與 v0.92.0 相同（g2）。
