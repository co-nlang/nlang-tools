## 1. 主張

**引擎必須依根所指名的摘要選用標準根，而不是拿它自己那一份去比對。**

今天這兩件事分不出來，因為引擎只有一份。〔量 2026-08-15〕`root_with_system()` 在
`v0.20.0 → v0.21.0 → v0.22.0` 之間逐位元組未動，摘要恆為
`65f52e2da48baa550d7340c0fdc214fd1f9925577a96ffec59bc34f8b2bcbe72`。

分不出來的代價是〔量，三個引擎實測〕：標準根多**一筆**，
v0.22.0 與 v0.22.0＋一筆**雙向互相讀不了對方的倉**——
`refusing root: standard root digest … is unavailable`。
牆本身照 §6.8 是對的；缺的是門。

## 2. 射程（四項）

### 2.1 解析由「等於我的」改為「在我持有的集合裡」

`hydrate_system_table` 今天的判準是 `digest != expected` 即拒絕，
`expected` 來自單一的 `root_with_system()`。改為：以摘要在引擎持有的**版本集合**中查找，
查不到才拒絕。

**釘的是性質，不是拼法**——A（保留歷代建構函式）與 B（內嵌歷代正準位元組）皆可，
但**必須滿足**：新增一版**不需要改動解析邏輯**。若新增一版要去改 `if/else`，
那不是一張表，是兩個特例。

> **⚠ 本項的「集合大小 > 1」在樹內無探針。** 理由與 Q-011 的 O54 相同：
> 它需要**兩個標準根不同的引擎**，而任何樹內測試都只能建出這一版。
> **驗收時以三個真二進位實測（§5.2）。** 交付方請勿以為 §3 全綠即代表本項成立
> ——Q-011 第二輪正是九支探針全綠而 O54 `grep -c hydrate` = 0。

### 2.2 拒絕訊息不得宣稱單數

今天：

```
refusing root: standard root digest {digest} is unavailable (this engine has {expected})
```

`this engine has {單數}` 在引擎持有一份以上的那一刻起就是**假的**。
訊息**必須**繼續指名**所缺者**（§6.8 第三條 MUST），**不得**再宣稱一個單數的「我有的那個」。

〔量，本弧開單前實際 grep——**第一版工單此處寫錯，記在這裡**〕
`grep -rn "this engine has" crates/ --include=*.rs` 命中 **3 處，不是 1 處**：
訊息本身在 `crates/interpreter/src/storage.rs:498`，另兩處**與本弧無關**——
`crates/interpreter/src/lib.rs:1035` 是一句 doc comment，
`crates/oo/tests/cas_integrity_probe_test.rs:100` 是一支**探針檔裡的註解**。

⟹ **原本寫的完成條件「該 grep 應為 0 命中」是不可能被滿足的**：
它會逼交付方去改一個無關的註解，以及**一個它無權改動的探針檔**。
現行完成條件改用精確到訊息的形式：
`grep -rn "is unavailable (this engine has" crates/ --include=*.rs` ⟹ 今天 **1**，交付後 **0**。

### 2.3 `oo status` 說得出這個倉依賴哪一份，以及本引擎有沒有

新增可觀測面，理由不是方便：**§6.8.2 第二條 MUST 是一句關於引擎的宣稱，
而一句無法被觀測的宣稱不能被符合性檢查。** 今天使用者要知道
「這隻引擎開不開得了這個倉」，唯一辦法是去開它然後看報錯。

**放 `oo status` 不放 `--version` 的理由**：`oo --version` 的輸出被切版協議的
末步檢查綁著（`oo --version` 對 git tag）。**不動它**。

> **⚠ 本項後半「以及本引擎有沒有」在樹內無探針。** P1 只斷言 `status` 印出**本倉依賴的
> 那個摘要**；「本引擎持有哪些」需要一個持有量 > 1 的引擎才測得到，與 §2.1 同一個限制。
> **驗收時在 §5.2 的 PLUS+H 上看。** 你仍須實作它——**不要因為沒有探針就只做前半**。

### 2.4 O54 不得回歸

pre-sentinel 的根（`v0.20.0` 及更早，根自足、無摘要）**必須**完全不被碰。
本弧改的是「摘要怎麼解析」，不是「哪些根要解析」。

## 3. 已校準探針

檔案：`crates/oo/tests/a_library_you_no_longer_ship_probe_test.rs`。

**探針修改權在驗收方。** 交付**只得**移除 `#[ignore]`，**不得**改動本檔任何其他位元組。

| 探針 | 斷言 | 基線 |
| :-- | :--- | :--- |
| **C0** | 控制組，**首位**：新倉提交後，根確實帶著摘要哨兵且 `oo log` 讀得回 | 綠（必須維持） |
| **C1** | 控制組：摘要被竄改 ⟹ 拒絕，且訊息**指名所缺者** —— §6.8 第三條 MUST 不得被本弧弄丟 | 綠（必須維持） |
| **P1** | `oo status` 印出本倉所依賴的標準根摘要，且該值**等於**根物件裡實際那一個 | **紅**：今天 `status` 無此輸出 |
| **P2** | 拒絕訊息**仍指名所缺者**（存在斷言），且**不再**宣稱 `this engine has <單數>`（不存在斷言） | **紅**：今天逐字含該子句 |

**C0 為何在首位**：P1／P2 都在斷言「關於某個倉的某件事」。若倉根本沒建起來，
那些斷言全部真空。C0 是它們的存在半。

**P2 為何同時斷言存在與不存在**：常設規則——**斷言「不存在」的紅，必須在同一次執行內
斷言一個「存在」**。否則「訊息整個不見了」也會讓它變綠。

## 5. 驗收（驗收方執行，交付方不必做）

### 5.1 樹內

四支探針、全工作區五次重跑、conformance、genesis。

> **⚠ 全跑一律加 `--no-fail-fast`**〔量 2026-08-15，本工單開單前的基線全跑〕：
> 不加的話，`cargo test --workspace` 會在第一個失敗的 suite 停下——本次即停在
> `affiliation_claim_probe_test`（埠綁定偶發失敗，Inbox；單獨重跑 3 次全綠），
> **只跑到 150 個 suite，計數因而失真**。
> 一個會中止全跑的偶發缺陷，會讓「五次重跑全同」這個判準本身失去意義。
>
> **該偶發缺陷的成因〔量 2026-08-15，同日更正〕不是原記的 TOCTOU**：隔離該空窗實測
> 2800 次綁定 0 次 EADDRINUSE。成立的是 **(H1)** `free_port()` 探測 `127.0.0.1:0`
> 而 `oo node serve` 綁 `0.0.0.0:{port}`——**碰撞對手不必是另一支測試**，機器上任何
> 持有該埠的行程都算；**(H2)** `std::net::TcpListener::bind` 不設 `SO_REUSEADDR`。
> ⟹ **它在交付方的控制範圍之外**。全跑若**只**掛在 `Address already in use`，
> 據實記下並重跑該 suite，**不計為交付缺陷**（除非交付動了那些檔案）。
> 這不是「用重試遮掉」——被遮掉的缺陷會是交付的，這一個不是，且它有自己的 Inbox 列。

### 5.2 三個真二進位（本弧的主證據）
