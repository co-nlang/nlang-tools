## 1. 這一弧是什麼

`@list` 看起來是一個名字，行為像兩個東西，**而你拿到哪一個取決於你怎麼拼這個式子，不是取決於那個值**。

〔量 2026-09-16，v0.50.0 標籤建置〕

```
@list.%fmap       {{ %builtin: "list.map" … }}      ← 標準根的節點
(@list).%fmap     _
t: @list ⟹ t.%fmap        _                        ← 綁起來就沒了
m: { t: @list } ⟹ m.t.%fmap  _                     ← 放進 combo 也沒了
```

⟹ **門是純詞法的**：`@name.` 在投影期對標準根解析，而 **`@name` 這個值永遠是約束 marker**。
**沒有任何可綁定的東西帶著那顆節點。**

**而那個詞法形遮蔽 marker，不是擴充它**——對三個有節點的名字它走得更遠，
**對其餘每一個它什麼都拿不到，連 marker 明明有的欄位也拿不到**：

| | `@X.%name` | `(@X).%name` |
| :-- | :-- | :-- |
| `list`／`option`／`result` | ✅ | ✅ |
| `int`／`num`／`str`／`bool`／`any`／`float`／`combo`／`record`／`zzz` | **全部 `_`** | ✅ |

**佐證**：`SPEC_05` §3.2 自己的例子逐字寫的是 **`(@int).%name` → `"int"`**——**規格寫的是那個會動的拼法。**

## 2. 射程 ＝ 兩條不變式

### I1 一個名字一個答案

**`@X.f` 與 `(@X).f` 必須給出同一個答案，對每一個型別名字。**
`@X.f` 是對 `@X` 這個值的**普通取欄位**，**不得**是一條會遮蔽 marker 的名字查找。

### I2 型別是一個帶得走的值

**把 `@X` 綁到名字、放進 combo、傳遞之後，它仍然是同一個值。**
〔今天〕`t: @list` 之後 `t.%fmap` 為 `_`。

**⟹ 兩條合起來就是 D68 的「單一值」**：`@X` 同時承載 marker 的欄位與標準根節點的欄位。

## 3. 明確不做

1. **`%super` 的語義**。它依 `SPEC_05` §3.2 與裁定 R1 行事，**G2 是這條紅線**。
2. **`@zzz` 的開放性**。D68 讀乙 為「沒有節點的名字仍是型別值，只是沒有 `%fmap`」
   ——**那是推論不是另裁**。本弧維持開放；**若你發現它站不住，在 §N.3 說，不要自己改**。
3. **D3′（manifest 的規範形）與 D4（runner 契約）**。兩者皆未裁；
   **且 D3′ 有它自己的前置**——`REAL_03` §6.2 的值編碼表缺五個標記
   （`0x17` Thunk／`0x18` Range／`0xFD` `#blur`／`0xFE` `_|_`／`0xFF` `_`），
   **而標準根自己需要 `0xFF`**。與本弧無關，記在此處免得誤併。
4. **不公佈任何 CAID；不重算標準根；不動 `SPEC_09` §2.1／§2.5 那兩張表**
   （`SPEC_09` §2.5 註解逐字要求在該題裁定前不要動它們——**而 D68 正是那一題**，
   故**改那兩張表是驗收方的規格結案，不是你的**）。

## 4. 紅線

**R1 非紀元。** 標準根 `7038e250…`、`x: 0` 根 `31745ef0…`、物件 **3**、`layout=5`、`encoding=5`
皆不動；conformance **162／162**。**G3 是這條紅線。**
〔依據〕`%super` 是**衍生反映欄**，〔量〕標準根裡出現 **0 次** ⟹ 合成單一值**不需要存它**。

**R2 已經會動的那一側不得變壞。** `(@X).f` 今天對十二個名字全部有答案（**G1**）。

**R3 `%super` 不得被搬家或改語義**（G2）：`(@int).%super.%name` → `"num"`、
`(@any).%super` → `_`、**手造的 `{ %kind: #type, %name: "int" }` 仍須拿不到 `%super`**。

**R4 探針不得改動，也不得被 `rustfmt` 掃到。** 認為探針寫錯 ⟹ §N.3 說明並保持它紅。

**R5 離開碼不得在管線之後取。**
