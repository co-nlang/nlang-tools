## 背景:兩家族(這是本工單的全部語義框架)

SYNTAX_06 把比較運算分成**兩家族**,行為相反:

| 家族 | 運算子 | ⊥/⊤ 政策 | 依據 |
| :--- | :--- | :--- | :--- |
| 原子(塌縮) | `==` `!=` | **吸收**:任一側 ⊥ → 整式 ⊥;`_ == _` → `_` | §4.1(已實作,2026-07-10 `9727f1a`+`26b31fb` 定案,探針守住) |
| 集合(不塌縮) | `<` `<=` `>` `>=`(及 `=`,已修) | **乾淨布林**:⊥ 是空集運算元、⊤ 是全集運算元,永不吸收 | §4.1「集合關係不塌縮不吸收」+ §4.2 極值表 |

規格 §4.2 原文釘死的極值:`_|_ <= x` 恆 `#true`(Bottom 是萬物子集);
`x <= _` 恆 `#true`(萬物是 Top 子集);`_ <= _|_` → `#false`。

## 根因錨點(已讀碼定位,勿重查)

`crates/interpreter/src/eval.rs` `eval_binary_cmp`(~L729–801)**一個函數同時
服務兩家族**,⊥/⊤ 政策全走原子家族的吸收邏輯:

- L732/L734:force 後任一側 `Value::Bottom` 直接早退回傳(吸收)——對 `==`/`!=`
  正確,對 `<` 家族錯誤。注意 L732 在 **b 還沒求值前**就早退。
- L739:`ca.is_top() || cb.is_top() → Value::Top`(資訊不足)——對 `==` 正確
  (`_ == _` → `_`),對 `<` 家族錯誤(`5 <= _` 應 `#true` 不是 `_`)。
- L740–741:collapse 後的第二道 ⊥ 吸收,同款。
- 其後的數值比較(L752–766)、`==`/`!=` 結構後備(L768–772)、tag `%rank`
  (L774–781)、型別約束子型別(L783–798)都只處理有限值,**不在本工單範圍**。

## 修法(預裁決)

在 `eval_binary_cmp` 內按 `op` 分流 ⊥/⊤ 政策——**先求值/force 兩側**(集合家
族不短路;效應照 `max` 傳播),然後:

- **原子家族(`Eq`/`Ne`)**:現行行為一字不動(吸收序:⊥ 先於 ⊤;探針已綠)。
- **集合家族(`Lt`/`Gt`/`Lte`/`Gte`)**:對 collapse 後的極值先行判定,再落入
  現行有限值路徑:
  - `Lte(x, y)`:x 為 ⊥ → `#true`;y 為 ⊤ → `#true`;y 為 ⊥ → `#true` iff x 為 ⊥,否則 `#false`;x 為 ⊤ → `#true` iff y 為 ⊤,否則 `#false`。
  - `Gte(x, y)` ≡ `Lte(y, x)`(鏡像,勿另寫一份真值表)。
  - `Lt` = 嚴格子集 = `Lte` ∧ 非同極值:`⊥ < y` ⟺ y 非 ⊥;`x < ⊤` ⟺ x 非 ⊤;`⊤ < y` 恆 `#false`;`x < ⊥` 恆 `#false`。`Gt` 鏡像。
- 回傳一律 `#true`/`#false` tag(乾淨布林),效應 `res_e`,**永不回傳 `_` 或 ⊥**
  (集合家族不吸收——⊥ 運算元是合法輸入不是錯誤)。
- 極值判定用 **collapse 後**的值(與現行 L739 一致);`Value::Bottom` 與
  `Atom(AtomKind::Bottom)` 理論上後者已被 `9727f1a` 正規化,若在此處仍遇到
  `Atom(Bottom)`/`Atom(Top)` 形態,視同極值處理並**回函記錄來源路徑**(不擴修)。
