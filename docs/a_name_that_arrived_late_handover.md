## 0. 判準

*   **`SPEC_10` §2.3.1 D110 款**：「存語法不得讓衝突晚到：與既有定義相撞的寫入，照舊在演化時以兩邊的答案判、拒絕。」**Q-105 款**：「它做出的相撞在演化時拒……寫成一檔、兩次演化、兩次提交，任何分組，讀數相同。」**§2.2.1**：$Staged_{old} \sqcap Definition = \bot$ 時演化不得發生，回報指出 ⊥ 落在哪一個葉坐標。

## 1. 缺陷

〔量，`v0.122.0` 標籤建置；`acc/q122/recon.py`、`shapes.py`、`report.py`〕

*   **名字晚到，收下並把 ⊥ 存進歷史**：`r: 7`、`r: n + 1`（存語法，D110）之後寫 `n: 5`：三步都收，提交出 `r` 是 ⊥（回報 `#conflict at r`）。反過來（`n: 5`、`r: 7`、再 `r: n + 1`）最後一筆被拒。十三形同：兩筆定義、別名（`b: a`、`b: 3` 再 `a: 4`）、`_.x`、經過另一個名字（`r: m + 1`、`m: n`）、型別再精煉（`n: @int`）、區間再精煉、記錄裡讀節點名字（`h: { k: @int, r: k + 1 }`、`h: { r: 7 }` 再 `h: { k: 5 }`）、記錄欄位讀根、清單元素、箭頭本體、比較、一行 `r: 7 & (n + 1)`、單一配方 `r: n & 7`——**三種分法（兩次提交、兩次演化、一個檔）都收**。同一個檔 `r: 7; r: n + 1; n: 5` 收、`n: 5; r: 7; r: n + 1` 拒。
*   **⊥ 進了提交卻沒有回報**：記錄欄位兩筆定義讀根（`h: { r: n + 1 }`、`h: { r: 7 }` 再 `n: 5`）、清單元素（`l: [n]`、`l: [7]` 再 `n: 5`）——提交只印 `Commit successful`；一筆寫入自己做出的 `n: 5; l: [n & 7]` 同（字面 `l: [5 & 7]` 有回報）。提交的回報只收「存成 ⊥ 的值」，存成語法的配方要讀才是 ⊥。
*   **對照**：名字到了但不相撞（`n: 6`）收；配方最後到照拒；一筆定義自己讀出 ⊥（`n: 5; r: n & 7`）收並回報。

## 3. 射程＝不變式（不是機制）

*   **M1 晚到的名字讓既有定義讀成 ⊥，就拒**（r1，13 形 × 3 分法，一行 `&` 與單一配方各 2 分法）：被拒的那一步退出碼 1、回報 `#conflict at <葉>`；被拒的寫入不進根，之後讀那個坐標不是 ⊥。
*   **M2 一筆寫入自己做出的 ⊥ 記下並回報，每一種形**（r2，8 格）：頂層、記錄欄位讀根、記錄讀節點名字、清單元素讀名字、記錄字面、清單字面、一行 `&` 與名字同檔、單一配方與名字同檔——提交成功、回報 `#conflict at <葉>`、讀 ⊥。
*   **另一半**：名字到了但不相撞照收；配方最後到照拒（g1，13 形）；已經是 ⊥ 的坐標不讓之後無關的寫入被拒（g2）；之後的演化不再執行一次效應（g3）；小的根不動（g4）。
*   **它自己寫的照舊**：同一筆寫入寫的坐標（含它記錄字面裡的每個欄位）由既有的關卡判；同一筆寫入有兩個欄位寫同一個坐標而交成 ⊥，是兩筆定義相撞（與同檔 `r: 5`、`r: 7` 同）；展開與表的列照它們自己的規則（D111／D112、D117 Q2：寫 `t.b: 3` 就是寫進表 `t` 的 `"b"` 那一支）。
*   **上一張卡學到的，逐條過**：不變式要在所有路徑都經過的那一處判（Q-092）——會把工作集寫回倉的只有 `oo evolve`（`evolve_at`、`evolve_where_absent`，都經 `evolve_files`）；REPL、`run`、`eval`、`test` 不寫回。借用既有函式前 grep 它別的呼叫點旁邊做了什麼（Q-121 R-1）——D118 的 `rebind_in` 以共用的 `views` 避開 N²。存活變異的理由寫「為什麼走不到」。
