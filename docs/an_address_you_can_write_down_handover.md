## 1. 一句話

這個語言只有一種握把：名字。而每個名字都要有一個綁定處，唯一永遠都在的綁定處
就是根——**67 KB 的標準根是這件事的後果，不是原因**（`commit.md` 承重第 9 句）。

本弧給它第二種握把：`_{sha256:<64 hex>}.` 是一個 **anchor**，與 `_.`／`^.` 同族。
`_.` 是**這個**宇宙的根，`_{位址}.` 是**那個**宇宙的根。

## 2. 已裁，不在本單重議

| | 裁定 |
| :--- | :--- |
| **O67** | 界定符是 `_{…}`。`_"…"` 出局——引號專指純粹的名字，而位址不是名字 |
| **§3** | 位置是 **anchor 家族**，文法上是 `anchored_path` 多一個分支；**前綴本體論一個字不改** |
| **§4.1** | **只寫摘要，但演算法必須留**：`sha256:<hex>`。無 `hash:` 前綴、無版本、無 sketch、無 masa |
| **§4.2** | 缺**位址**＝**具名拒絕**。**不得**靜默回 `_` |
| **§4.3** | **解析是純的**。可得性不是效果 |
| **§4.4** | **只在 RHS**。定義的左手邊是這個宇宙的座標 |
| **O70 ④** | **外層的效果來自被取回之值本身**，不來自取的動作 |

**§4.1 的理由不是風格，不要簡化掉演算法**：〔讀〕REAL_03 §30 逐字
`<algo> ::= "blake3" | "sha256" | <ext_algo>`——演算法自始就不固定；
BLAKE3 預設輸出也是 256 bit ＝ 64 個 hex，**與 sha256 逐字元同形**
⟹ 裸摘要在 blake3 落地那天就是歧義的。〔量〕blake3 今天未實作，
所以歧義是未來的——**但字面一旦定版就是相容性承諾**。

## 3. 射程（六項，逐項對應探針）

| # | 要做的 | 探針 |
| :-- | :--- | :--- |
| **S1** | `_{sha256:<hex>}.` 成為 `anchored_path` 的第三個分支，**compound-atomic**（pest `${}`），內文詞法惰性 | R1 |
| **S2** | 尾隨的 `.` 屬於 anchor：`_{位址}.` 無路徑段時就是整個值 | R2 |
| **S3** | 解析走**本地 store**；取不到 ⟹ **具名拒絕，訊息須含該位址** | R3 |
| **S4** | 解析**不貢獻效果**：以位址取一個純值，取用者的位址不得移動 | R4 |
| **S5** | 但**值自己的效果照舊**：取一個 `#nondet` 的東西，讀回來仍是 `#nondet` | R5 |
| **S6** | **印表機**必須把字面印回原形（SYNTAX_02 §5 #12：印出必為合法源碼） | R6 |

**S1 是不是純增補？不是，而射程已量。** 〔量〕`_{sha256:<hex>}.x` 今天**合法**
（讀成 `_` 施用於一個 combo，答 `_`）；新文法之下它變成 anchor。
**爆炸半徑實測為零**：202 個 `.n` 檔中，`_` 與 combo 並置出現 **0 次**。

## 4. 不做，也不要順手做

*   **`_: X` 回退格（O69）**——另一弧。它移動使用者宇宙的位址。
*   **`~%Discovery./fetch` 的效果標籤（O70 ⑤）**——另一弧，而且**它是紀元**：
    〔量 2026-08-22〕`%effect: #io` **寫在標準根內容裡**
    （`"fetch":{"Combo":{…"meta":{"builtin":…"disc.fetch"…,"effect":{"Atom":[{"Tag":"io"}…`），
    標準根裡 `"io"` 共 **20 處** ⟹ 改它就移動標準根 digest，就移動每一個宇宙。
    **本弧一個位元組都不要碰它。**
*   **遠端解析。** 本弧只讀本地 store。
*   **預取／依賴掃描工具。** C2（靜態可見）由 AST 節點的存在保證，不必在本弧兌現工具。
*   **不要為了讓 `_{…}` 優先而重寫 `anchored_path`**——§3 明文是**多一個分支**。

## 5. 基線逐條（本單開單當下實測，`dev ea05acb`）

**綠 4（控制組，全程必須保持綠）**

| | 量到的 |
| :--- | :--- |
| **C1** `_.` 仍是這個宇宙的根 | `{}` |

**紅 6（每一支的基線理由）**

| | 基線 | 為什麼是對的理由 |
| :--- | :--- | :--- |
| **R1** 位址取得到值 | `_` | 讀成 `_` 施用於 combo，再 `.k` |
| **R2** 無路徑段時是整個值 | `Parse error --> 1:76` | 尾隨的 `.` 今天不屬於任何規則 |
| **R3** 缺位址是具名拒絕 | `_` | **靜默**，正是 §4.2 禁的 |
| **R4** 取純值不移動取用者 | 前置條件即失敗（位址取不到） | — |
| **R5** 值保有自己的效果 | 前置條件即失敗 | — |
| **R6** 印回原形 | `out: _ {` | 印成**帶空白的並置**，round-trip 後不再是同一個東西 |

R4／R5 因為**什麼都沒取到，所以沒有東西能升起效果**。三支現在都先斷言「取到了」。
**只見證「沒有報錯」的斷言什麼都沒有見證。**
