# 裁定簡報 D2：哪些內容取得規範地位

> 2026-08-19，Q-033 D2 開題。基線 `nlang-tools dev 289096f`（v0.26.1）、
> `nlang-spec local`（v0.26.1-draft.1）。**本檔只量與提問，不改規格、不改引擎。**

---

## 1. 偵察給的是現值盤點，裁定需要的是交叉

〔量〕26 個系統模組，三把尺**互相不同意**：

| 模組 | 規格提及 | 符合性向量使用 | 態射 | 非純效果 |
| :--- | ---: | ---: | ---: | :--- |
| `Config` | 36 | 1 | 0 | |
| `Engine` | 36 | 2 | 11 | `#state` 5, `#io` 2 |
| `Math` | 24 | 8 | 48 | `#nondet` 1 |
| `Discovery` | 14 | 0 | 6 | **`#io` 6（全部）** |
| `List` | 14 | 0 | 40 | |
| `Official` | 10 | 0 | **0** | |
| `Cond` | 7 | 0 | 3 | |
| `Effect` | 3 | 1 | 1 | |
| `Csv` | 1 | 0 | 4 | `#io` 1 |
| `Env` | 1 | 0 | 3 | `#io` 3 |
| `Process` | 1 | 0 | 2 | `#io` 2 |
| `Time` | 1 | **8** | 9 | `#io` 1 |
| `Bytes` `Complex` `Diff` `Io` `Json` `Path` `Query` `Reflection` `Regex` `Set` `Stat` `String` `Toml` `Url` | **0** | 0 | 111 | `#io` 5 |

*   **14 個模組在整份規格裡零提及**，合計 111 個態射。
*   **21／26 個模組不被任何符合性向量碰到**（286 個向量只用到 5 個模組）。
*   四個「提及 1 次」的模組，**該次全部不是規範條款**〔量〕：
    `Csv` 是命名慣例的舉例、`Env` 是一則量測註、`Process` 是一則違規回報、
    `Time` 是 SPEC_15 的**反面範例**。

### 1.1 兩張「規範清單」的代理彼此矛盾

| 來源 | 名單 |
| :--- | :--- |
| SPEC_09 §5.1「核心系統組件清單」 | `Logic` `List` `Str` `Option` `Result` `Cond`（**引擎只兌現 2**） |
| 提及次數 ≥3（去掉 `Official`） | `Cond` `Config` `Discovery` `Effect` `Engine` `List` `Math` |

交集只有 `List` 與 `Cond`。**規格今天沒有一張可被引用的權威清單**，而 §6.8.2
的第一條 MUST 要求標準根是「由核心規格定義的具體值」。

## 2. 決定 B／C 可不可行的那一項：以位址取值的機制

〔量〕**語言層沒有 CAID 字面**——`PathAnchor` 只有 `Root`／`Current`／`Parent`／`Bare`，
`@"hash:sha256:…"` 在 parser 即被拒。`~%Engine./resolve(CAID)` 回**字串**，不是值。

**但 `~%Discovery./fetch(CAID)` 真的取回值**〔量：取回另一個宇宙的整個根，含其
使用者欄位〕。所以「模組住在位址上、被指名取用」**今天就做得到**。

### 2.1 代價：匯入使匯入者變成 `#io`，而效果自 v0.26.0 起進位址

〔量〕

```nlang
app: {
  imported: ~%Discovery./fetch("…").mymod./double
  builtin_control: ~%Math./add        ;; 純
}                                      ;; ⟹ 整個 app 帶 %effect: #io
```

v0.26.0 剛把**傳染的效果**搬進進雜湊的 `%effect` 欄位（O61／O62）。
⟹ **把一個模組移出標準根，會把它的每一個使用者從純變成 `#io`，且該變化進入身分。**

**這條把「純」變成一把可用的尺**：今天已經是 `#io` 的模組（`Io` `Process` `Env`
`Csv` `Query`，以及全 `#io` 的 `Discovery`），其使用者本來就帶效果，**移出去的邊際
代價為零**；純模組移出去則是**淨損失**。

## 3. 為什麼 A／B／C 照原樣裁會裁錯

*   **A（凍結 v0.26.0 全量）不是偵察說的「最便宜」**。它必須同時
    （i）重寫 SPEC_09 §5.1（六列只兌現二列）、
    （ii）把違反 SPEC_13 §135 的 `~%Official` 空殼**寫進憲法**、
    （iii）為 14 個零提及模組、111 個態射補寫規範地位。
*   **B（最小核心根）** 的成本是一次 digest 移動——而**多重具備的機具已經建好並在
    v0.26.0 真的用過**（`shipped_standard_roots` 的歷史列）。這是本專案**已經付過
    工程費**的那一種成本。
*   **C（核心＋外部擴充）** 機制存在（§2），但**必須先裁 §2.1 的效果代價**，
    否則等於宣布「用標準庫就不再是純的」。

⟹ **真正待裁的不是「選哪一個清單」，是「用哪一把尺畫線」。** 清單是尺的推論。

## 4. 待裁

### D2-a — 畫線的尺（可複選，但必須有序）

1.  **規範性**：規格正文以規範條款要求其存在者入根。〔量〕≥3 提及且去掉 `Official`
    ＝ 7 個；但與 SPEC_09 §5.1 只交集 2 個 ⟹ **選此尺須同時裁哪張表是權威**。
2.  **純度**：只有純態射入根；帶效果者移出（其使用者本來就帶效果，邊際代價為零）。
    〔量〕會移出 `Io` `Process` `Env` `Csv` `Query` `Discovery`，
    並**逼問 `Engine`**（`#state` 5／`#io` 2，但它是反映面）。
3.  **自舉**：只收「不在根裡就無法命名其他東西」者。〔量〕`Discovery` 由此**必須留**
    ——它是 §2 那個取值機制本身，移出去就沒有東西能把它取回來。
4.  **經驗地板**：符合性向量實際用到者入根。〔量〕僅 5 個，且含只在反面範例出現的 `Time`。

**尺 2 與尺 3 直接衝突於 `Discovery`**（全 `#io`，卻是自舉點）。**這一格必須先裁。**

### D2-b — 四個逐案項

| | 現況 | 備註 |
| :--- | :--- | :--- |
| `~%Official` | 空殼 `{{ }}`，**違反 SPEC_13 §135** | 已裁過，只需決定**搭哪一次 digest 移動**移除 |
| `~%Str` ↔ `~%String` | 規格 1 處寫 `Str`，引擎叫 `String` | 拼法二選一；**釘性質不釘拼法**不適用（這就是拼法本身） |
| `/add` 在頂層規則軸 | v0.26.1 起可遮蔽 | 仍是**唯一**在頂層的算術態射，其餘同族在 `~%Math` |
| 14 個零提及模組 | 111 個態射 | 不得以「都先保留」代替裁定 |

### D2-c — 順序

**D1 是 D2 的下游**（審計 §11.4）：重疊集合恰為「保留名 ∩ 標準根 types 軸」＝
`list`／`option`／`result` 三名。D2 對 types 軸的裁定會直接決定 D1 還存不存在。
