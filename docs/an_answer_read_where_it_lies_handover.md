*   成因（讀碼並插樁確認）：
    1.  這一趟每經過一筆記錄就 `force_cell(v.clone())`。`ComboVal` 的 clone 是深拷貝（`data` 是 `IndexMap<String, Value>`），而且把快取的框雜湊清掉；可是強制一筆已經算好的記錄，傳回的就是它自己（`force_recursive_metered` 開頭）。
    2.  每個欄位為了 `rebind_in` 又 clone 一次；`rebind_in` 只改 thunk，其他的原樣傳回。
    3.  要知道一筆記錄算好了沒，`solid_combo_expansion_cost` 把它底下每個值各 clone 一份推進待看清單。
*   **不是**格數的問題：格數 N²／2 就是存下的大小（值沒有結構共享，Inbox）；參考把這一趟從 5.4 秒降到 47 毫秒，格數不變。
*   `I-318` 原先記的成因（「存成答案的值讀回來認不出是呼叫造的，r1 用不上；帶 `#io` 的不進存放」）是推測，量下來不是：時間不在強制求值，在複製。
