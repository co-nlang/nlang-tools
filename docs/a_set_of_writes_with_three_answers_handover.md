## 0. 判準（規格原文）

*   **D117**：一個欄位寫了兩個衝突的值，衝突留在那個欄位——不把整個記錄變 ⊥。表與非表同一規則；**任何分組與先後同一組位元組**（正規形由本工單定，見 §2）；演化邊界照舊：沒有表時同一欄位兩個衝突的寫入照舊以 `#conflict at x` 拒，有表時是分支、收。
*   **`SPEC_06` §2**：「`n/` 允許節點局部處於 `_|_` 而不導致全域崩潰。」只有封閉結構（Cocoon）或 `#strict` 下，局部欄位的衝突才使整個容器坍縮。
*   **`SPEC_07` §1.1.2（D100–D102、D109）**：同一個約束出現多次是同一個分支，所有本體相交——不論寫在同一個字面、經 `&`、還是經後續的演化聚在一起；本體只在分派選中該分支時才求值；衝突只屬於該分支，別的引數照常作答。D101：字面、`&`（兩向）、`|>`、展開、根的逐次演化產生同一組位元組——同一個格元素一個位址。判例（Q-098）：同一組寫入不論分成幾次演化、寫在一檔或分檔，工作集與根相同。
*   **`SPEC_00` 不變式 1**：收斂決定性。
*   **D65**：⊥ 的成因是纖維，不入位址（`0xFE`，無酬載）。

## 1. 缺陷

〔量，`v0.101.0` 標籤建置；`WORK_QUEUE` §3「開 Q-101」〕

*   `injections::fold` 依檔名（16 位元組亂數）排序後逐一交會；24 次中兩筆 `x` 都排在表之前就拒（9／9），否則收（15／15）；30 次拒 13。
*   同一組 `{ @{ @int }: 0 }`、`{ x: 3 }`、`{ x: 4 }`：`({ x: 3 } & { x: 4 }) & 表` ⟹ 整個 ⊥；`(表 & { x: 3 }) & { x: 4 }` ⟹ 分支本體集合 {3, 4}；字面 ⟹ 分支本體 ⊥。巢狀提交三個根（`fce31809…`、`13d8fecb…`、`864da675…`）。
*   沒有表時也是兩種：`{ x: 3 } & { x: 4 }` 整個 ⊥、`({ a: 1, b: 2 } & { a: 2 }).b` ⊥；字面 `{ a: 1, b: 2, a: 2 }.b` ⟹ `2`。
*   〔讀〕`unify.rs` `merge_axis`：兩邊都不是 Top 的欄位交會出 ⊥ ⟹ `return Err`（整個記錄 ⊥），不分開放與封閉。演化與提交的邊界以「交會整個是 ⊥」判衝突（`universe.rs` 十餘處、`injections::fold`）。

## 2. 依據；正規形；位址

*   **D117**（裁定已下）。
*   **正規形（本工單定）**：
    *   開放記錄裡兩個值在同一欄位衝突 ⟹ **該欄位是 ⊥**，其他欄位照常；Cocoon 或 `#strict` 照舊整個 ⊥。
    *   表的同一分支：**值本體**（`is_deferred_body` 為假——不帶效應、不施用、沒有開放 `$`；箭頭是值）**當下交會成一個本體**——交會一個值不是求值，與一般欄位同一件事；**延後的本體**照舊留在以位址為鍵的集合裡，選中時才求值。
    *   因為 ⊥ 不帶酬載（D65），「哪兩個值撞在一起」不入位址 ⟹ 任何分組與先後落在同一組位元組（成因訊息可以不同：「3 vs 4」或「4 vs 3」）。
*   **衝突的裁決在整體上判**：一次交會的衝突＝結果裡的 ⊥ 葉、在那個座標上至少兩邊都有值、而且不在表的分支（`%rules`）裡。演化：寫入與當下工作集交會後判；提交：所有成員交會成工作集後判一次，不逐步判；點名座標序最小的那一個。
*   **位址**：不含衝突的值不動（g2）。會移動的：開放記錄裡交會出的欄位衝突（先前是整個 ⊥）；表的同一分支有兩個以上值本體（先前存集合，現在存交會）——例：`t: { @{ 1.. }: (x -> x), @{ 1.. }: (x -> 2) }` 根 `add730d5…` → `b6a66d23…`，施用的讀數不變。

## 3. 射程＝不變式（不是機制）

*   **M1 衝突留在欄位**：開放記錄的交會，衝突的欄位是 ⊥，其他欄位讀得到，巢狀的衝突留在它自己那一層（r1）。
*   **M2 任何分組與先後同一組位元組**：字面、`&` 兩向、有表無表、模式鍵與資料鍵，同一組寫入一個根（r2）。
*   **M3 演化先後不改根**：表收下的寫入，不論先後、分檔或一檔，一個根；讀那個分支是 ⊥，別的引數照答（r3）。
*   **M4 提交的裁決只看整個工作集**：互不相見的成員（兩次並行演化留下的），不論檔名如何排序——有表一律收、一個根；沒有表一律拒、點名 `x`（r4）。
*   **M5 挑選把交會出的衝突當成不相交**：聯集逐支、`|>` 進聯集、分派、補的成員判定，只留不衝突的；`=` 不看 ⊥ 的成因（D65）（r5）。
*   **另一半——邊界照舊、不含衝突的不動**：沒有表時第二筆衝突寫入以鍵拒（巢狀亦然、已提交之後亦然、配方之後亦然、寫在既有的 ⊥ 上亦然、表在之後才來亦然、一檔表在最後亦然），寫在別處照收（g1）；不含衝突的根逐位元組同、Cocoon 照舊整個 ⊥、兩個箭頭的定義合併照舊只在施用時衝突（g2）。
*   若你找到另一處「以交會整個是 ⊥ 判衝突」或「逐步而不是整體判工作集」的邊界，一併在射程內，在 8.1 列出。

## 6. 明文不在射程內

*   開放記錄的型別不合是欄位 ⊥（`{ name: "Bob", age: 15 } & @Adult` ⟹ `{ age: ⊥, name: "Bob" }`）：D117 的後果，不是缺陷。
*   `<=` 與聯集吸收：`{ a: ⊥ }` 是空的，落在任何東西裡——不要把交會出的衝突在這裡當成不相交。
*   提交時回報表分支裡的 ⊥，座標印成 `%rules.{摘要}.%val`（v0.101.0 對 `x: 1 & 2` 的分支已然；驗收方另開 Inbox）。
*   `=` 比較兩個含 ⊥ 欄位的值時連成因訊息一起比（`{ x: ⊥(3 vs 4) } = { x: ⊥(4 vs 3) }` ⟹ `#false`，位址相同）：既有的比較規則。
*   回報層裡「兩組獨立衝突同時累積時，回報哪一個」：本卡讓提交點名座標序最小的那一個；`status` 的回報不在本卡。
*   規格文字、向量與 `CHANGELOG`：驗收方收尾。
