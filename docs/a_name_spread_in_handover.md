# 工單：一個展開進來卻看不到的名字（Q-078）

> 佇列 `nlang-spec/meta/WORK_QUEUE.md` Q-078／**不需新裁定**：依據 `SPEC_03` §3.1（展開把欄位「攤平至當前 Combo」；碰撞合併＝交集；前向引用與收斂時序：源在檔內的定義位置不得影響結果；循環展開 ⟹ ⊥ `#divergent`；異質展開）、`SPEC_04` §2.1（裸名先在當前容器的欄位裡找，再逐層向外）、§3.1 #1（`~` 欄位向內可見）、`SYNTAX_05` §4 #6（匯入就是展開）
> 探針（已預先提交並校準）`crates/oo/tests/a_name_spread_in_probe_test.rs`
> 基線：dev `50b6a4e`／`oo v0.79.0` ⟹ **5 綠 10 紅**；十支紅的都紅在一般斷言，零空洞讀數。

## 1. 缺陷

〔量，v0.79.0；v0.27.0、v0.40.0、v0.60.0、v0.77.0、v0.78.0 逐格相同〕`...X` 寫在一個容器裡，X 的欄位就是這個容器的欄位。Combo 裡這件事只對了一半：`.j` 讀得到展開進來的欄位，**其餘地方都讀不到**。

*   **兄弟讀不到展開進來的名字**：`{ ...{ j: 5 }, q: j }.q` 得 `_`；`{ ...~%Math, r: add (1, 2) }.r` 得 `_`（Combo 裡的匯入不兌現）；`{ j: 100, t: { ...{ j: 5 }, q: j } }.t.q` 得 **100**（外層搶先）；`{ ...{ j: 5 }, j: 7, q: j }.q` 得 **7**，而 `.j` 是 ⊥ `#conflict`——**兄弟讀到的是碰撞的一半**。開放、封閉、表、態射本體、巢狀、`|>` 每一種容器都一樣。
*   **展開源看不到它所在的容器**：`{ s: { j: 5 }, ...s }.j` 得 `_`——**這次展開根本沒有發生**；`{ n: 1, ...{ k: n } }.k`、`{ ~h: 3, ...{ k: h } }.k` 得 `_`；`{ g: (n -> … { ...(g (n - 1)), k: 1 } : { z: 0 }), r: g 3 }.r` 得 `{ k: 1 }`（遞迴呼叫的展開被丟掉）。
*   **展開一個本身帶展開的容器，丟掉它展開進來的欄位**：`{ a: { ...{ j: 5 } }, ...a }.j` 得 `_`。
*   **容器展開自己得 `{}`**：`{ s: { ...s } }.s` 得 `{}`；頂層 `s: { ...s }` 得 ⊥ `#divergent`。
*   **提交後一樣**：`t: { ...{ j: 5 }, q: j }` 提交後 `_.t.q` 得 `_`。
*   **頂層**：兄弟看得到展開名。但展開源寫在定義之前就被丟掉：`...s` 再 `s: { j: 1 }`，`_.j` 得 `_`，反過來寫得 1。碰撞依位置而變：`...{ j: 5 }` 再 `j: 7` 在 evolve 被具名拒絕；`j: 7` 再 `...{ j: 5, k: 1 }` 卻 evolve 照收，提交時只說 `#conflict at j`，`k` 就此遺失；根上已有 `j: 7` 時，evolve `...{ j: 5, k: 1 }` 照收，提交才回「Commit failed」。

## 2. 依據（不需新裁定）

*   `SPEC_03` §3.1：展開「將目標的所有欄位攤平至當前 Combo」。碰撞的鍵是交集，例：`{ a: 1, ...{a: @int} }` 等價於 `{ a: 1 & @int }`。展開源可以是前向引用，展開在觀測收斂時擴張，「源在檔內的定義位置**不得**影響結果」。「嚴禁一個 Combo 展開其自身或其祖先節點……判定為 `_|_`，標記 `%cause: #divergent`」。原子以 `{ %val: v }` 展開。
*   `SPEC_04` §2.1：`resolve_bare_name` 先看 `fields(H)`，H 是當前容器，再逐層向外。展開進來的欄位就是 H 的欄位。§3.1 #1：`~` 欄位在定義它的 Combo 及其所有子節點中可見。展開源是一個寫在容器裡的式子，所以它也看得到。
*   `SYNTAX_05` §4 #6：匯入就是展開，「把 `~%` 標準庫物件以 `...` 展開進當前容器」。

## 3. 射程＝不變式（不是機制）

*   **I1 展開進來的名字就是容器的欄位** 從這個容器與它的子孫以裸名讀得到。適用每一種容器：開放、封閉、表（D100 的作用域框）、態射本體、巢狀、`|>`。適用每一個位置：展開寫在前或後。適用每一個觀測面：導航、施用、印出、提交後讀回、`run --observe`。對應 r1、r2、r7。
*   **I2 兄弟讀到的是交集**：一個鍵既寫在容器裡又被展開進來，兄弟讀到的是兩者的交集，不是其中一半（r3）。
*   **I3 展開源在它所在的容器裡解析名字**：兄弟欄位、私有欄位、別的展開帶進來的名字、遞迴呼叫，不論寫在哪個位置（r4、r9）。
*   **I4 展開一個本身帶展開的容器，帶著它展開進來的欄位**（r5）。
*   **I5 容器展開自己或祖先 ⟹ ⊥ `#divergent`，而且答得出來**：不懸掛、不崩潰（r6）。頂層的 `s: { ...s }` 照舊（g4）。反過來，**一個在本體裡展開自己遞迴呼叫的態射不是循環**（r9）。
*   **I6 頂層的展開，就是把它的欄位寫在那裡**：
    *   展開源與展開的位置不改變值，也不改變根（r8）。
    *   碰撞得到的拒絕，和直接寫 `j: 7` 再 `j: 5` 相同，不論展開寫在前或後、源寫在前或後。對已提交的根也一樣（r8）。
    *   被拒絕的 evolve 不落地任何東西。
    *   從未定義的源仍是空操作；同值照舊落地（g4）。
*   **I7 詞法作用域仍是詞法的**（g1、g2）：
    *   `^` 數的是容器，展開只帶進欄位，不帶進容器。
    *   展開進來的欄位保有它被寫下的那個作用域：`{ k: 2, ...{ k: 1, q: k } }.q` 是 1。
    *   展開源的私有欄位不外洩（`SPEC_03` §3.1 安全邊界）。
    *   `&` 不共享作用域。
    *   近處沒定義時仍找到外層。
    *   互相引用照舊。
*   **I8 效應**：展開進來的效應在被讀時才執行，只執行一次，不論誰讀（r10、g5）。
*   **I9 代價**：展開的代價不得隨深度指數成長。〔量，驗收方參考實作第一版〕每一層重新強制展開源，遞迴深度 8 就燃料耗盡；r9 要求深度 40 照常作答。
*   **I10 身分**：不改磁碟格式，不推進佈局或編碼。**意義不變的值，根不動**：沒有展開的值、欄位已是實值的展開、源只讀自己的展開（g3 七根）；「展開進一個新容器就是同一個值，所以同一個位址」——Q-037 的 G4（`a_field_outside_identity_probe_test.rs` g4、`a_field_outside_identity_crate_test.rs`）。〔量，驗收方參考實作第二版〕把所在的容器交給**每一個**展開源，`{ ...{ f: 1 } }` 就和 `{ f: 1 }` 分家，另有兩根答案不變而移動——那一版被這兩支既有測試擋下。意義改變的值會移動位址，那是破壞性變更，驗收方記帳，請在 Q3 逐根列出。
*   **I11 evolve 期間的封閉容器**：源尚未定義的展開，在 evolve 期間依既有的展開法重新排隊（`SPEC_03` §3.1 時序款），而且**終止**。〔量，驗收方參考實作第二版〕排回去的源若不是原樣，`q: {{ ...never, b: 1 }}` 就燃料耗盡——由既有的 `forward_spread_probe_test.rs` 擋下。
