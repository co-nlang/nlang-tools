# Q-038 —— 一次成功回報的 `commit`，可以讓一個倉兩個引擎都打不開

> 開單 2026-08-25。基線 `dev ae85c8c` ／ `oo v0.33.0`（**開單當下實測，見 §4**）。
> **裁定已下（O73，2026-08-25，用戶）**，見 §1。規格收尾由**驗收方**做；

## 0. 這一弧要證明的一句話

**一次回報成功的 `commit`，不得使一個倉不可開啟。**

今天不是。而且不是被誰讀壞的——是**寫**的那一步，一個動作，兩根不同的軸，
把新舊兩個引擎**同時**鎖在門外。

〔量〕`/home/gali/nlang/.oo` **是一個活的 pre-sentinel 倉**（2026-08-14 的真提交，
今天兩個引擎都讀得到）。**在那裡跑一次 `oo commit` 就會中彈。** 這不是理論題。

## 1. 裁定（O73，2026-08-25，用戶）——本弧不必再問

| # | 裁定 |
| :-- | :--- |
| **①** | **`commit` 不得改動任何形式宣告。** 規則是「**不得改動你找到的東西**」，不是「永不寫宣告」——建倉時當然要寫（`G1` 看守這一邊）。 |
| **②** | **寫進 pre-sentinel 倉的根，必須維持自足**，不指名任何 digest ⟹ **幽靈 digest 從此不會被寫下，而不是被補上一個空表**。 |
| **③** | **遷移須明示**，永遠不得是 `commit` 的副作用。 |
| **④** | **遷移只推進容器的佈局宣告，不動任何根** ⟹ `REAL_03` §6.8「以單一摘要指名（MUST）」不適用於未進 sentinel 形式的根，故**不需要儲存任何空表**。 |

**為何不選「把空表存成 CAS 物件」**（開單前的另一個候選）：那讓每個舊倉永久帶一個
無意義的空依賴，而且單向鎖仍然是 `commit` 的副作用——而本弧要治的正是那件事。

## 2. 量測（2026-08-25，`oo v0.33.0` ＋ `oo v0.20.0` 兩個真二進位）

> 兩個二進位使用前都先問了已知答案的問題：`~%Math./add (1,2)` → `3` ✓✓
> **全程在複本上做**；原倉 `.oo/HEAD` 與 `.oo/format` 量測前後逐字相同。

### 2.1 現象

對一個 `v0.20.0` 所造的倉跑一次 `evolve` ＋ `commit`：

| | 結果 |
| :--- | :--- |
| `commit` | **回報成功，`exit=0`** |
| 其後 `status` / `log` / `evolve`（新引擎） | `refusing root: standard root digest 47dc540c… is unavailable` |
| 其後 `status`（**造這個倉的 v0.20.0**） | `store format version layout=2 is not supported by this engine` |

### 2.2 兩個獨立成因，一個動作

**(A) 幽靈標準根。** 新根**指名** `47dc540c94ceb704a23875c11273e16bb0b8a87aed84de911f2133568115f254`
而**從不儲存它**。

*   〔量〕`objects/sha256/47/dc540c…` **不存在**；整個倉裡唯一含這個字串的檔案，
    是新根 `0fefb59b…` 自己。
*   〔量〕**它是常數**：兩個內容完全無關的舊倉（`app: { k1: 1 }` 與
    `other: { zz: 99, yy: "text" }`）磚化後得到**同一個 digest**
    ⟹ 它是**空標準表**的雜湊，即 `standard_for_root` 對 format 1/2 所回傳者
    （該處註解逐字寫著 self-contained）。
*   `REAL_03` §6.8 第三條 MUST 於是**強制每一個讀者拒絕**——引擎打不開自己剛寫的東西，
    而且它拒絕得**完全正確**。錯的是寫。

**(B) 靜默的形式遷移。** 同一次 `commit` 把 `.oo/format` 由 `2` 改寫成 `layout=2`
**並**新增 `.oo/objects.format`（`encoding=2`）。

*   〔量，把兩個檔切開來測〕**鎖住舊引擎的只有 `format` 那一行**：
    留著 `objects.format`、只把 `format` 改回 `2` ⟹ **舊引擎照讀**；
    只刪 `objects.format`、留著 `layout=2` ⟹ **舊引擎仍然拒絕**。
*   〔量〕**新引擎讀裸整數 `2` 完全正常**。

### 2.3 承重量測——鎖住舊引擎的是宣告，不是內容

只把 `.oo/format` 改回 `2`，**`HEAD` 留在新引擎寫的那個提交**：

```
OLD log -> commit hash:sha256:v1:d3d8f22ea658cf8c5a2fc68b7cd0e0dcec72ec7d43e68f459231098c384e706b
           message: new engine writes
```

⟹ **新引擎寫的位元組本來就是舊引擎讀得懂的。** 這一弧要拿掉的是一行宣告，
不是一個相容層。

### 2.4 O53 未被違反

〔量〕`status`／`log`／`evolve` 三者**都不動任何檔**（`format`、`objects.format`、
`HEAD` 逐字不變），**只有 `commit`**。⟹ **不得**把修法做到讀取路徑上（見 §3 紅線）。

### 2.5 一件今天量不到、要由交付方回答的事

**提交之後的 pre-sentinel 倉，還用不用得了內建？**
〔量〕舊倉裡 `oo run main.n --observe sum`（`~%Math./add (2,3)`）新舊引擎皆得 **5**；
但那條路徑不經過提交後的根。要量它就必須先 commit，而 commit 正是把倉弄壞的那一步。
⟹ **本弧修好 (A) 之後，這件事第一次可量。請在交付報告裡回答它**（一個 pre-sentinel
倉在 commit 之後，`~%Math./add` 解不解析得到），**不論答案是什麼都照實寫**。

## 3. 射程

### S1 —— `commit` 不得改動既有的形式宣告

`.oo/format` 與 `.oo/objects.format`：**找到什麼樣就留什麼樣**。
建倉（宣告不存在）時照常寫，**那不是改動**。

### S2 —— 寫進 pre-sentinel 倉的根，維持自足

不指名任何 digest。**幽靈被移除，不是被餵飽**——`R3` 逐字看守「不得改為把空表存進去」。

### S3 —— `oo migrate`，且必須被明示地要求

本倉**已有**「你必須開口」的正準拼法：`rollback`／`squash`／`gc` 皆需
`--grant <verb>`。**沿用它**，不要發明第二種（`--yes`／`--force`／互動提示皆不採）。

*   無 grant ⟹ **拒絕且不改動任何東西**（`R4`）。
*   有 grant ⟹ 推進**容器**：`format` → `layout=2`、寫入 `objects.format`
    （編碼須為**驗證過的**值，不得猜——O53 的同一條理由）。
*   **不動任何根**：`HEAD` 不移動，歷史照讀（`R5`）。
*   輸出**應**說明此後舊引擎打不開該倉。**措辭不入探針**（釘性質不釘拼法）。

### 明確不做

*   **不得**修復**已經**中彈的倉。那些倉的根確實指名了一個不存在的表，
    §6.8 第三條 MUST 要求拒絕，而**那個拒絕是對的**。
    〔量，可救性〕手動把 `HEAD` 退回 parent ⟹ 新引擎讀得回（代價是丟掉那次寫入）；
    **再**把 `format` 改回 `2` 並刪掉 `objects.format` ⟹ 舊引擎也讀得回。
    **本弧治的是「不再製造這種倉」。** 若你認為錯誤訊息應該指出這條救法，
    **回報，不要順手加**。
*   **不得**把任何防禦加到讀取路徑（`REAL_03` §6.8.1 的可讀性紅線在讀取端；
    O53 限制修法）。`G2` 是紅線探針。
*   **不得**改變任何值的身分或任何根的位址（`G3` 是紅線探針）。
*   **不得**改規格——規格收尾是驗收方的事。
