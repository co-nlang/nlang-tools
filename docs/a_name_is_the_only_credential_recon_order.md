## 1. 一句話

## 2. 開單當下已量到的 —— 不要重做這些

〔全部量於 `dev e7b84dd`，真二進位 `target/debug/oo`〕

### 2.1 現版重現（`WORK_QUEUE` §2.2 第 4 條要求）

```
oo eval '{{ %builtin: "process.exit", %morphism: #true }} 7'   →  exit=7
```

**成立。** 舊帳所記的 v0.20.0 症狀在 v0.28.0 逐字重現。

### 2.2 形狀矩陣

| 形 | 結果 |
| :--- | :--- |
| `{{ %builtin: "math.add", %morphism: #true }} (1,2)` | `3` |
| `{{ %builtin: "math.add" }} (1,2)`（**無** `%morphism`） | `3` |
| `{{ %kind: #morphism, %builtin: "math.add", %morphism: #true }} (1,2)` | `3` |
| `~%Math./add (1,2)`（真態射對照） | `3` |
| `{ %builtin: "math.add", %kind: #morphism } (1,2)`（單括號） | `⊥ #conflict` |

⚠ **最後一列不是守衛，別把它當成半個閘。** 對照組：`{ %kind: #morphism } (1,2)`
（**完全沒有 `%builtin`**）同樣得 `⊥ #conflict` ⟹ 那個 ⊥ 出自單括號形不可施用，
與 `%builtin` 無關。**`%morphism: #true` 也不是必要條件。**

### 2.3 四層的可觀測後果（`WORK_QUEUE` 完成條件所要的那四格，初測）

| 層 | 觀測 |
| :--- | :--- |
| **parse** | `oo fmt` 正常格式化並印回 `%builtin` 欄 |
| **evolve** | `exit=0`，無訊息 |
| **commit** | `exit=0`，`Commit successful: …` |
| **apply** | 見 §2.2；`math.add` 回 `3`，`process.exit` 終止行程 |

**耐久落地已證實**：提交後 `.oo/objects/` 下有一個物件**以明文含 `math.add`**
（標準根物件為 hex 編碼，不會誤中）⟹ **使用者的 `%builtin` 成為內容定址物件的一部分**。

### 2.4 兩個容易誤讀成「已經有閘」的觀測

*   `oo eval 'evil (1,2)'`（`evil` 已提交進宇宙）回 `_`。**這不是拒絕**，是
    `eval` 看不見倉——即 Q-018（`run`／`eval`／`observe` 的倉庫可見性）。
    量它的時候要先確認你在測哪一個。
*   `oo run` 對只有繫結沒有觀測的檔案無輸出。**這是惰性**，不是攔截。

## 3. 本單要量的（未量）

1.  **派送點在哪一行。** 〔線索，非結論〕`crates/interpreter/src/lib.rs` 有大量
    `"%builtin".to_string()` 的**建構**點（引擎自己投影標準庫），`value.rs:2793`／`:2802`
    與 `builtins/reflection.rs:123` 有 `contains_key("%builtin")` 的**判讀**點。
    要找的是**施用時真正拿這個字串去查 `builtin_registry` 的那一處**，並回答：
    它有沒有辦法分辨「引擎自己放的」與「使用者寫的」？

2.  **今天有沒有任何一個地方分得出來。** 這是本單最重的一題。若答案是「沒有」，
    那麼 §3.3 的 MUST **不是加一個檢查就能兌現**——它要求一個目前不存在的來源區分。
    請量：值裡有沒有任何位元組記得它的出處（provenance）？標準根投影出來的態射與
    使用者寫的同形值，**逐位元組**是否相同？

3.  **四個拒絕層各自的可觀測後果。** 對 parse／evolve／commit／apply 逐層回答：
    在該層拒絕，**使用者會看到什麼、staged 會變成什麼、既有的倉會怎樣**。
    四者不等價，這正是要裁的東西。

4.  **既存耐久值的處置。** 〔量〕標準根有 **251 個相異的內建名參照**。若在讀取
    路徑上拒絕 `%builtin`，**標準根自己會不會被拒絕**？請實測，不要推理。

5.  **偽造的射程有多寬。** `process.exit` 是最戲劇的一個，不是唯一一個。
    請列出 registry 裡**全部**的內建名，並標出哪些是使用者拿到後可造成
    (a) 行程終止 (b) 檔案系統寫入 (c) 網路 (d) 非決定性。
    **掃描不得截斷**——要的是全表，不是前 20 筆。

6.  **線上路徑確認仍然關著。** 舊量測說 `#advertise` 有求值前的字面閘，偽造載荷
    皆 `#rejected/#malformed`。**對 v0.28.0 重測一次**；若仍關著，本單射程即確定
    只含本地路徑。
