## 0. 這一弧是什麼

`.oo/` 今天沒有任何一個「狀態」是可以被一次原子替換的。`save_staged` 一次寫**五個檔**，
每個各自原子（temp＋rename），**合起來不原子**。W10 要的就是把它們變成**一個**物件，
好讓 Q-016 有東西可以做 compare-and-swap。

> **⚠ 縮寫**：本弧與 Q-016 文件裡的 `CAS` 是 **compare-and-swap**。
> `GLOSSARY` §11.1（2026-08-29 裁定）規定 `CAS` **只**指 Content-Addressed Storage，
> compare-and-swap **一律寫全稱**。本文以下一律寫全稱；讀舊文件時請注意這一格。

## 8.0 這個候選從哪來

用戶問：「有沒有更激進的作法？還是一樣會有成本，只是跑到其他地方去？」
並順帶指出：**今天的作法可能是學 git 造出來的，而本質不一樣。**

設計帳已經寫過兩次同一句話：`commit.md` §0.1 第 1 句（**git 需要合併節點是因為
三方合併不是函數；n/ 不需要是因為 meet 是全域決定性的全函數**）與 §1.3
（**git 的圖結構被值語言吸收掉了**）。而 `.oo/` 的版圖是 `.git/` 改名：
`HEAD`、`objects/`、`staged`（＝ index），現在再加 `savepoints/LOG`。

**`staged` 是其中最 git 的一個器官**：git 需要 index，因為它的工作樹是**可變的檔案**。
n/ 的工作集是**一個格元素**，而格元素靠 meet 累積——meet 不需要一個暫存的格子。

## 8.1 丙的定義

*   `evolve` **不讀-改-寫任何東西**。它**建立一個新檔**：一筆**注入記錄**，
    **隨機本地 id 作檔名**，內容不可變，走 `atomic_write`。
*   **工作集 ＝ 所有未提交注入的 meet**（fold）。
*   **目錄本身就是那個 log**——**不需要 `LOG` 檔**，因為目錄插入是原子的。
*   `commit` fold 完之後清空該目錄（**天然的壓實邊界**）。
*   `pin`／`effect` 意圖是**某一筆注入上的欄位**，不是全域旗標。
