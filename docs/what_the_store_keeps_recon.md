### 1.3 M3:整數字面值仍以未強制 Thunk 存入

〔量〕`data.app.k1` 的耐久形逐字:

```json
{"Thunk": {
  "expr": {"kind": {"Atom": {"Int": [1,[1]]}}, "span": {"start": 11, "end": 12}},
  "closure": [{"data": {"k1": {"Thunk": {"expr": {…同一個 Atom…}, "closure": []}}},
```

3. **帶 span**——源碼位元組偏移 `{11,12}` 是耐久資料。

## 2. 新發現:位址沒有覆蓋它的位元組

### 2.1 同一個 CAID,兩份不同的位元組

〔量〕兩個 scratch 倉,唯一差異是源碼多兩個空格(語義相同,span 位移):

| | 源碼 | 存下的 span | **物件位址** | **檔案實際 sha256** |
| :-- | :--- | :--- | :--- | :--- |
| a | `app: { k1: 1 }` | `{11,12}` | `16ba5683…` | `ed95f086…` |
| b | `app: {   k1: 1 }` | `{13,14}` | **`16ba5683…`** | `d478372d…` |

**位址相同,位元組不同。** 機制與 2026-07-29 的身分量測一致:雜湊走
`expr.to_nlang(0)`,而 span 不在 `to_nlang` 的輸出裡 —— **span 進 store,不進雜湊**。

⟹ 對 CAS 而言,`位址 ≠ hash(內容)`。

### 2.2 完整性檢查存在,而且會擋(控制已武裝)

直接竄改磁碟上的物件,三組:

| # | 竄改 | 在雜湊投影內? | 結果 |
| :-- | :--- | :--- | :--- |
| T1 | `span` `{11,12}` → `{9999,10000}` | 否 | **通過**。`oo inspect` 照常回 `k1: 1`,無任何警告 |
| T2 | `Int` `[1,[1]]` → `[1,[2]]`(**合法編碼**,值 = 2) | 是 | **`#caid_mismatch`**,退出碼 1 |
| C | 還原 | — | `k1: 1`,退出碼 0 |

**T2 是必要的控制**:我第一次寫的竄改是 `Int: [2,[2]]`,那是**形狀錯的載荷**——
sign 只能是 −1/0/1,於是它被 serde 擋在 `#object_undecodable`,**證明的是反序列化嚴格,
不是完整性被驗證**。這正是 v0.2.50 立下的規則(對抗項必須含一個會計算的載荷)。
換成合法編碼之後才看見真正的檢查。

⟹ **結論不是「沒有檢查」,是「檢查的覆蓋面是儲存位元組的真子集」。** `to_nlang`
投影之外的一切——至少包含 `span`——是一個**位在內容定址物件內部的未認證區**。

### 2.3 這一半有先例,幾乎自己會裁

O42(v0.17.0)已經為 `#blur` 的身分裁過同一件事:**不收原始碼 span 等讀數**。
把同一條理由套到耐久形,`span` 不該在裡面——它不是內容,是一次讀數。

## 3. M4 已修,於是 M5 第一次可以當結論

W8′ 偵察當時記著:`to_nlang` 的收尾是 `_ => format!("{:?}", self)`,Thunk／Code／Ref
三個變體掉進去,所以 22,269 B「**是印不出來的那版的長度**」。v0.13.0(W8′-a)修掉了它。

〔量〕v0.19.0 的三個數字,以及印出來的東西**少了什麼**:

| 形式 | 長度 | 相對 |
| :--- | ---: | ---: |
| JSON pretty(磁碟現況) | 252,435 B | 1× |
| JSON compact | 67,971 B | 3.7× 小 |
| **n/ 形(`oo inspect`)** | **21,837 B** | **11.6× 小** |

而 n/ 形裡 `span`／`closure`／`Thunk` 的出現次數:**0**。`k1` 印出來是 `k1: 1`。

⟹ 印表機**丟掉了不該存的三樣東西**,這一半是量到的。

> **⚠ 本節初版寫成「印表機今天印的就是『存語義值』那個選項的成品」,那是過強的,已更正
> (更正 E5,§8)。** M5 證明的是**它丟掉了不該存的**,**沒有**證明它**分開了所有該分開的**。
> 顯示序、聯集排序、`#blur` 投影、`%effect` 註解都是顯示層,`to_nlang` 有可能把兩個
> CAID 不同的值印成同一段字,或反之。**值形需要一份為身分寫的編碼(大致就是
> `content_hash` 的預像),不是顯示用的印表機。** 這不擋 A,擋的是「A ＝ 把 `oo inspect`
> 的輸出寫進 `.oo/`」。

**但這裡有一個真的不對稱**:印出來的東西**不能往回**變成磁碟上的東西(M6),而磁碟上的
東西也只能往前變成一個有損的顯示形。兩個方向都沒有單射的保證。

## 4. O35 要可裁,還缺什麼

O35 的原文:**`.oo/` 的耐久形要不要是可求值的?**

三個選項與各自代價(costs 為本輪量到或由量測直接推出):

> **⚠ 本節初版把「存什麼」與「用哪種字寫下來」併成一格,使 A 看起來比實際貴,並讓人
> 以為沒有 n/ 解碼器就不能裁 O35。已更正(更正 E1,§8)。** 兩件事必須分開:

| | 耐久形 | 讀取 | 代價 |
| :-- | :--- | :--- | :--- |
| **A** | **值形子語言,不可求值** | **解碼,不求值** | **CAID 全面失效**(M3)⟹ 破壞性 + 遷移。**與編碼形無關** |
| ↳ **A-json** | 磁碟仍 JSON,但存**強制後的 Value**(無 span／無閉包／無未強制 Thunk) | **serde,已經存在** | 只有遷移,**不需要新 decoder** |
| ↳ **A-nlang** | 印表機輸出當耐久形 | **需要新 decoder** | ＝ O31／W8′-c,**不是 O35 的前提** |
| **B** | 維持可求值 | 剖析 → 求值 | **讀取即執行**,與 disc 028 §8 供應鏈正面相撞。且 §2 的未認證區成為可藏東西的位置 |
| ~~**C**~~ | ~~值形為主,惰性以明示標記保留~~ | | **不是第三條路**(更正 E2,§8):明示標記若**不進身分**就是 span 同一病(位址 ≠ 位元組);若**進身分**,兩個語義相同的惰性就是兩個宇宙。⟹ C 在問題 (b) 裁完之前**沒有獨立內容**,它是 §4.1 答「要活過重啟」時 **A 的窄例外** |

**⟹ O35 可以只裁「存值、讀取不求值」,編碼形留給 W8′-c。** STATUS 寫「O35 擋在 O31
前面」是對的;把兩者併起來的是本檔初版,不是 STATUS。

**本輪把 (a) 的答案量出來了**:store 今天存的是**求值狀態**,而**語義值那一版已經存在**
(印表機,21,837 B)。所以 (a) 不再是未知,它是一個選擇。

**仍缺**(裁定與更正見 §7／§8):

1. **惰性要不要活過重啟。** 用戶 2026-08-13 給了一個比「全域開關」更貼規格的切法,
   見 §7.4——**staged 與 committed 可以不同答**。仍待裁。
2. **`system` 進不進根、進不進身分(M2)。** 本輪確認它十二個 minor 未累積,但
   **選 A 不會自動拿掉根裡那 61 KB**;印表機的 21,837 B 裡 `system` 仍在。⟹ **選了 A,
   M1 的 99% 還在。** 這是與 O35 同級的第二題,不是 Inbox 順帶項(更正 E3,§8)。

## 7. 裁定(用戶,2026-08-13)

### 7.1 ✅ 原則:CAS 物件裡的每一位元組,要嘛進雜湊,要嘛不該在磁碟上

用戶原話:

> §2 量到的不是「span 不該在」,是:**CAS 物件裡的每一位元組,要嘛進雜湊,要嘛不該在
> 磁碟上。** ⟹ `get_value` 重算的是 `content_hash()`(`to_nlang`／`bn_serial` 投影),
> 寫入的是 pretty JSON。**span 只是現在看得到的洞。** serde 的 `skip`／`default`、
> pretty 空白、以後任何「方便放進去但不進 digest」的欄,都是同一個洞。
> **O42 對 blur 裁的也是這句**,不是「blur 特例不要 span」。

⟹ 我原本把 O42 讀成一則個案先例,那是**修個案不修類別**。原則與 §7.2 同日裁定,
**工單仍只先拔 span**。

### 7.2 ✅ `span` 不是耐久內容 / 閉包同理

`span` 依 §7.1 與 O42 同句處理。

**閉包一併裁**(用戶,更正 E4):M3 的 JSON 裡比「未強制」更難看的是**閉包是外層作用域
的拷貝,而拷貝裡又含 `k1` 自己**。即便暫時維持可求值形,把整棵宇宙塞進每個欄位也**沒有
語義理由——作用域可由根＋路徑重建**。「閉包不是耐久內容」與「span 不是內容」**同一價、
同一便宜,且不需要先決定惰性**。

⟹ 本檔 §4 初版只列了 span。**閉包留下的話,A 的體積勝利有一半是幻覺**——使用者資料
那 516 B 裡很大一塊正是這面鏡子。

**順帶(不另裁)**:M7 的 `legacy_fields`／`legacy_local` 是同一族 serde 洞(寫了就讀不
回來)。剝 serde 洞時**順手釘「不准寫」**,掛在 span 那張工單即可。

### 7.3 ✅ O35 ＝ **A**:存值,讀取是解碼不是求值

**B 的代價成立,而選 B 基本上否定前面走過的路。**

**C 不是第三條路**,理由見 §4 表的更正列。

**兩項適用範圍必須明寫,否則下一個人會以為可以另裁**:

1. **線上就是 store。** OODP 送的是同一種物件,`peer fetch` ＝ `get_value`,
   ⟹ **O35 的答案自動是線上的答案:線上解碼、不求值。**
2. **`Code`／`rules` 仍會出現在值形裡。** 「不可求值」指的是**不 force、不 apply、
   不沿路徑跑**;把印出來的 `^.…` 還原成 `Value::Code` **是解碼**。那是**引號,不是
   Thunk**。不寫明會有人說「你還是在存程式」(態射體)。

### 7.4 ⏸ 惰性活不活過重啟——待裁,但框架已換

用戶:「我還沒想清楚,再討論。」同時給了一個比全域開關更貼規格的切法:

| 邊界 | 惰性 |
| :--- | :--- |
| **staged／工作階段** | **Thunk 可以活**(SPEC_04「未觀測即不計算」) |
| **commit** | **提交是一次固化邊界**——寫進歷史的是**觀測結果**,不是尚未跑的程式 |

好處:**SPEC_04 不必為了 store 改寫**;而「無限結構跨 `.oo/` 是什麼意思」的答案變成
**「它不能當 head,除非你觀測出一個有限的陳述。」** C 若還存在,只活在 staged,
**不進物件庫**。

### 7.5 ⏸ 仍待裁的兩題

1. **§7.4**(惰性的邊界)。
2. **M2:`system` 進不進根、進不進身分。** 兩個選項:根物件只存 `data`(及該存的軸),
   `system` 由引擎版本重建;或維持現況並接受**下一次新增內建是破壞性的**。
   **漏裁的話,A 做完 M1 的 99% 還在。**

### 7.6 破壞半徑比「CAID 全面失效」大(更正 E6)

M3 只說強制後 digest 變了。實際要遷的不只本地物件名:

- 已簽名的根、advert、`refine` 邊、**對等點手上的同一 CAID**
- **P4 那類「根以 `6e8eae8b…` 結尾」的釘**(W8′-a 已把它當成跨十週的身分)

⟹ **A 是破壞性 minor／紀元,不是「重算一遍 hash」。** 不改變裁定,改變的是
**發布時要不要連 OODP／簽名一起排**。本檔初版寫了遷移,沒寫網路身分。
