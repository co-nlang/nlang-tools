**規格裁定依賴**:**O48**(2026-08-13 裁)、O51(射程)、REAL_03 §6.6
**偵察**:`docs/what_the_store_keeps_recon.md`(Q-001)

## 1. 一句主張

> **同一個 CAID 的 CAS 物件,磁碟位元組必須相同。**

這是 O48「每一位元組要嘛進雜湊,要嘛不該在磁碟上」的可測形。引擎今天已經有**一個方向**
——位元組決定位址,合法的語義竄改被 `#caid_mismatch` 擋下。缺的是**另一個方向**:
**位址不決定位元組。**

## 2. 地上有什麼〔量 2026-08-13,引擎 v0.19.0〕

### A 鍵序不決定

三次獨立執行、**逐位元組相同的源碼**:

| | 位址 | 檔案 sha256 | 大小 |
| :-- | :--- | :--- | ---: |
| run 1 | `ba56831a…` | `84db4cfb…` | 252,435 B |
| run 2 | `ba56831a…` | `b23f5929…` | 252,435 B |
| run 3 | `ba56831a…` | `b9200dc9…` | 252,435 B |

大小相同,且**排序後的行多重集相同** ⟹ **純粹是重排**。`system` 頂層鍵序逐行程不同:
run 1 `[String, Effect, Config, …]`／run 2 `[Process, Csv, Cond, …]`。

**雜湊路徑本身是決定性的**(位址三次都沒動),不決定的是**序列化路徑**。

### B `span` 存進去、不進雜湊

| 源碼 | 存下的 span | 位址 |
| :--- | :--- | :--- |
| `app: { k1: 1 }` | `{11,12}` | `16ba5683…` |
| `app: {   k1: 1 }` | `{13,14}` | **`16ba5683…`** |

磁碟上竄改 span 的數字:**不被偵測**,`oo inspect` 照常回 `k1: 1`。竄改整數(合法編碼
`[1,[1]]`→`[1,[2]]`):**被偵測**。⟹ 檢查存在,**覆蓋面是位元組的真子集**。

### C pretty 空白

物件以 pretty JSON 寫出:磁碟 **252,435 B**,緊湊 **67,971 B** ⟹ **約 184 KB 的縮排,
沒有任何雜湊覆蓋它**。〔量〕根物件 **9,501 個換行**。

## 3. 可滿足性檢查(工單自身)

A ＋ B **完全解釋**全部位元組分歧,沒有第三個原因:把兩份「只差空白」的物件各自
**排序後**再比對,差異剩 **14 行,其中非 `start`／`end` 的行數 ＝ 0**(不截斷,全文列出)。

⟹ 修掉 A 與 B,R2／R3 即可滿足。**這一步是在寫閘之前做的**,不是事後解釋。

## 4. 射程

**做**:

1. **序列化採正準序**——與雜湊路徑同一個順序。
2. **`span` 不寫進 CAS 物件**。
3. **不寫 pretty 空白**。

**不做(明確)**:

| 不做 | 為什麼 |
| :--- | :--- |
| **強制求值** | Q-010b。本弧結束後 CAS 物件裡**仍有 Thunk**(R1 的存在半驗這件事) |
| **拔閉包** | 〔量〕閉包**進雜湊**(清空或加鍵皆得 `#caid_mismatch`)⟹ 拔它移動 CAID。放進本弧會逼出**第二個紀元** |
| **改 `system` 為 digest** | O50,隨 Q-010b 同一紀元 |
| **換編碼形(JSON → n/)** | O31／W8′-c |
| **動 `.oo/staged`** | O35／O48／O49 治的是 **CAS 物件**;`staged` 今天已是耐久檔但**沒有位址**,依 O51 **保留 Thunk**。**強制發生在 commit,不在 evolve**(P2 守這條) |

**⟹ 本弧不移動任何身分。** P1 釘住 `app: { k1: 1 }` 的根 CAID `16ba5683…`;若它變紅,
交付動到了雜湊投影,本弧就不再是非破壞性的,**不能與 Q-010b 分開出貨**。

## 5. 探針(已預先提交並校準)

**校準結果〔量 2026-08-13,基線〕:6 綠 / 4 紅,紅全部紅在對的理由上。**

| # | 探針 | 基線 | 守什麼 |
| :-- | :--- | :--- | :--- |
| **C0** | 倉裡真的有物件(≥2 個,根 >1000 B) | 綠 | **首位是刻意的**:R1／R4 斷言「某物不存在」,走訪器靜默失效時它們會靠「什麼都沒找到」而通過 |
| **C1** | 語義竄改被 `#caid_mismatch` 擋下 | 綠 | 偵測機制本身是活的。**載荷會計算**——`[1,[2]]` 是合法 Int(sign 1, digits [2]);形狀錯的載荷只會被 serde 擋成 `#object_undecodable`,那證明的是反序列化嚴格(v0.2.50 的教訓) |
| **C2** | 提交後仍讀得回 `k1: 1` | 綠 | 值沒有在過程中死掉 |
| **P1** | 根 CAID ＝ `16ba5683…` | 綠 | **本弧非破壞性的全部依據** |
| **P2** | `.oo/staged` 仍含 `Thunk` | 綠 | O51 射程。交付方伸手改共用序列化器時,可能無意間把工作階段的惰性也拿掉 |
| **P3** | 沒有任何地方**寫** `legacy_fields`／`legacy_local` | 綠 | M7:它們 `#[serde(skip)]` 卻進雜湊 ⟹ 寫了就讀不回來。本弧正好動 serde 面。**含存在半**(這些欄位仍被讀到 ≥1 處)＋掃描**排除自己**＋不截斷 |
| **R1** | 沒有 CAS 物件含 `"span"` | **紅** | 訊息列出仍帶 span 的物件。**存在半**:同一次執行內斷言 `Thunk` **仍在**——本弧不強制,若 Thunk 沒了就是交付越界,span 消失便不成立 |
| **R2** | 三次相同源碼 → 位元組相同 | **紅** | 「三次產生 3 個相異檔案」。位址與大小的相等先斷言,故它不會因為別的原因紅 |
| **R3** | 只差空白的兩支 → 位元組相同 | **紅** | **先斷言兩者共用 CAID**(前提還在),再比位元組。不用 `assert_eq!` 比 250 KB 的緩衝區——報第一個相異位移＋前後 30 位元組 |
| **R4** | 物件裡沒有排版換行 | **紅** | 「9,501 個換行,252,435 位元組」 |

**探針修改權在驗收方。交付只得移除 `#[ignore]`,本檔以外不得編輯此檔。**

   除 `#[ignore]` 之外**逐位元組不變**。

6. **加性關鍵量測**:新的根物件大小。預期由 252,435 B 降到 67,971 B 上下(−73%),
   **且 P1 的 CAID 不動**。

## 7. 交付方要注意的一個陷阱

`span` 的移除若用 `#[serde(skip)]`,讀回時會由 `Default` 填一個 `{0,0}`。那是一個
**被捏造的讀數**,而它會出現在載入後的錯誤訊息裡,指向源碼第 0 個位元組。

本弧不裁「span 該不該有一個『未知』的表示」——但**交付不得讓捏造值看起來像真的**。
若做不到,選擇讓載入後的值**沒有** span,而不是有一個假的。
