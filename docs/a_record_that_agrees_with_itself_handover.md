## 2. 射程（S1–S7）

**S1 — `mint_id` 不得讀計數。** `savepoint.rs:37` 今天是 `prev.len() + 1`。
改用 `injections.rs:24` 已有的 `SystemRandom`（同一支，重用不要重寫）。

**S2 — ○ 的框帶 `parents:`（D50）。** 在 combo **之外**（放進 `ComboVal` 會讓一個本地欄位
看起來像值）。三個約束：
(i) **空集合永遠寫出這一行**，後面沒有 id——不得省略（省略與「舊檔沒有這個欄位」分不開），
不得寫 `parent: _`（`_` 是格的單位元，不是空陣列；那是 `store_codec.rs:490` **Commit** 的寫法）；
(ii) 多元素**必須按 id 字典序正規化**後寫出；
(iii) decode 對未排序的處理由你選（拒絕／接受後重排），**在報告裡說明選了哪個與為什麼**。

**S3 — 前驅由目錄純導出。** `X 是 tip ⟺ 目錄裡沒有任何 ○ 的 parents 含 X`。
跳過 `LOG` 與 `.` 開頭者（與 `injections.rs` 同一條規則）。
**不得引入任何以 `tips` 檔為真相的路徑**——快取可以做（見 S7），但**核對永遠以目錄為準**。

**S4 — 產生判準（D47 ＋ D51）。⚠ 這一項最容易做錯，做錯的代價是無界成長。**
D51 **不是**「每次成功的 evolve 都鑄」。正確的去重規則是：

> **當且僅當候選的 `parents` 恰為單一元素 T、且候選 combo 與 T 的 combo 相同時，不鑄。**

否則鑄。逐項對照：
*   位置移動了 ⟹ 鑄（D47 (a)，今天已對）。
*   位置沒動、但 `parents` 有兩個以上（匯流）⟹ **鑄**（D51，今天沒有）。
*   位置沒動、`parents` 就是當前唯一 tip、combo 與它相同（循序 no-op）⟹ **不鑄**。
    **探針 `g1` 是這一格的守衛，今天綠，必須保持綠。**

**S5 — `ids ≠ ∅ ∧ tips = ∅` 必須拒絕 `record`。** 那是環或損壞，**不得**當成空倉去鑄一顆
空 `parents` 的 ○——那會是第二顆創世，與既有 DAG 不相連。**探針 `r2` 的第二個斷言釘這一格。**

**S6 — 移除 `LOG`。** S3 之後它是第二份真相，而兩份真相就是一個跨檔不一致窗
（今天 `record` 兩次 `atomic_write`，中間崩潰產生偵察 Q10 那兩種狀態）。
**同批更新版圖宣告**：`a_store_you_did_not_write_probe_test.rs` `p1`（`:220`–`:221`
宣告 `.oo/savepoints/LOG`）與 `a_working_set_that_is_a_set_probe_test.rs` `g2`
（`:255`–`:274`，釘 `LOG` 是一個檔且 commit 不改它的位元組）。
**那兩支釘的是形不是性質**：「○ 活過 commit」改讀目錄即可，而本工單的 `g2`
已經是那個性質的正確寫法。**逐支說明你怎麼改的，不得靜默刪測試。**

**S7 — `tips` 快取（可選）。** 做不做都可以，**做了要照偵察附錄 Q13 的形**：
`readdir` 取名字集合 → 與快取鍵集合核對 → 相等才信 → 不等只讀多出來的那幾個或全掃 →
鑄 ○ → 才寫快取。**寫者不以快取為輸入。** 不做就每次走 S3。
