# 工單：一個被讀成字串的標籤鍵（Q-085）

> 佇列 `nlang-spec/meta/WORK_QUEUE.md` Q-085（原 Inbox「分派表裡的標籤鍵不是約束」，併結「標籤鍵 `#a:` 與引號鍵 `"#a":` 是同一個座標」）／**裁定 D107**（2026-10-13 用戶裁定，選甲）：表把鍵讀成它拼出的座標——剖析器讀這個記號時得到的原子；引號只用來拼出名字，不改變座標。依據另有 D97（有模式鍵的 Combo 是表；每個非 meta 鍵是約束）、D101（一張表一個正規形）、D102（表怎麼印）、`SYNTAX_02` §4 #12（印出讀回是同一個值）
> 探針（已預先提交並校準）`crates/oo/tests/a_tag_key_read_as_a_string_probe_test.rs`
> 基線：dev `bfbbdbb`／`oo v0.86.0` ⟹ **1 綠 6 紅**；六支紅的都紅在一般斷言，只紅在非對照格，零空洞讀數。

## 1. 缺陷

〔量，v0.86.0；v0.78.0 起〕表裡的 `#a:` 是**字串 `"#a"`** 的約束，不是標籤 `#a`：

*   `({ @{ @str }: 1, #a: 2 }) #a` ⟹ `#no_matching_branch`；`({ @{ @str }: 1, #a: 2 }) "#a"` ⟹ `2`。
*   **有 `_:` 時靜默答錯**：`({ @{ @str }: 1, #a: 2, _: 0 }) #a` ⟹ `0`。
*   欄位裡、提交後、`&` 組出、展開組出、`|>`、以聯集為引數，皆同。
*   `{ @{ @int }: 1, #a: 2 } = { @{ @int }: 1, @{ #a }: 2 }` ⟹ `#false`；提交後 `k: { @{ @str }: 1, #a: 2, _: 0 }` 的根等於 `@{ "#a" }:`（字串）那張表的根 `ec806753…`，不等於 `@{ #a }:` 的 `99eb5e07…`。
*   `#_:`、`#_|_:` 同（`#no_matching_branch`）。
*   **印出端是鏡像**：字串約束 `@{ "4" }:` 印成 `4:`、`@{ "_" }:` 印成 `_:`、`@{ "+4" }:` 印成 `"+4":`——讀回都是另一個約束（整數、Top、整數）；`#a:` 印成 `"#a":`。

〔讀〕成因：

*   `crates/parser/src/lib.rs` `parse_field_key`：文法 `field_key` 的 `path` 排在 `tag` 前面，而 `path_segments` 收標籤，所以 `#a:` 剖成單段路徑鍵；`Rule::tag` 那一臂到不了。求值後它是資料鍵 `"#a"`——**與引號鍵 `"#a":` 是同一個座標**（`REAL_03` §6.2：欄位編碼是 `[軸][鍵: 字串]`）。
*   `crates/interpreter/src/dispatch.rs` `constraint_from_data_key`：把座標字串讀成約束，只認整數字樣與 `_`，其餘一律字串。
*   `crates/interpreter/src/value.rs` `table_display_rows`：原子約束一律裸印，不看讀回是不是它。

## 2. 裁定與依據

*   **D107**（甲）：鍵是座標字串；表把它讀成剖析器讀這個記號時會得到的原子——整數字樣 ⟹ 該整數、`#ident`（及 `#_`、`#_|_`）⟹ 該標籤、`_` ⟹ Top、其餘 ⟹ 該字串。**`#a:` 與 `"#a":` 是同一個座標，在表裡都是標籤 `#a`。** 要一個長得像別的原子的字串約束，寫 `@{ "#a" }:`。表印出時，原子約束**只在裸拼法讀回同一個約束時裸印**，否則印 `@{ … }:`。
*   **為什麼不是乙（鍵的種類入址）**：那是又一次紀元，而依鍵查找今天就不分兩者（`{ "#a": 1 } #a` ⟹ `1`）。D97 的兩款「標籤鍵是該標籤、引號鍵是該字串」在座標只是字串時不能同時成立（D101 要 `X & { #a: 2 }` 與 `X & { "#a": 2 }` 是同一張表）；D107 改寫後一款。
*   **位址**：沒有模式鍵的 Combo **一個位元組都不動**（g1：`k: { #a: 2 }` 根 `e841a181…`）。**帶標籤鍵（或引號拼出標籤的鍵）的表，根移動**——分支名從字串的摘要換成標籤的摘要，換到與 `@{ #a }:` 寫法同一根（r4）。不改磁碟格式。

## 3. 射程＝不變式（不是機制）

*   **I1 標籤鍵是標籤**：表裡的 `#a:`、`#_:`、`#_|_:` 是該標籤的約束，分支值是箭頭時照 D100 施用（r1）。
*   **I2 引號不改約束**：`"#a":` 與 `#a:` 是同一個約束，`"4":` 與 `4:` 也是；`@{ "…" }:` 寫的字串約束仍是字串（r2）。
*   **I3 每一條通到表的路都這樣讀**：字面、`&`、展開（展開帶進模式或帶進標籤鍵）、欄位、提交後、`|>`（含聯集右值）、以聯集為引數（r3、r4）。**若你找到另一個把座標字串讀成約束、或把約束印成鍵的地方，一併在射程內，並在 8.1 列出。**「表裡一個鍵的約束＝剖析器讀它的拼法得到的原子」是要守的不變式；改 `constraint_from_data_key` 只是一種機制。
*   **I4 印出讀回是同一張表**：每一張至少有一列非原子約束的表，印出、再讀回，`=` 判 `#true`（r5）；裸印恰好是讀回不變的那些（r6）。
*   **I5 沒有模式鍵的 Combo 不是表**：查找、`=`、位址皆不變（g1）。

### 8.4 工單指名要你回答的問題

**Q1** 把座標字串讀成約束，或把約束寫回成鍵：

1. `constraint_from_data_key`（`dispatch.rs`）照 D107。`_` 是 Top，整數字樣是該整數，`#_` 是 `TagEnd`，`#_|_` 是 `TagStart`，`#` 接識別碼是該標籤，其餘是該字串。三個呼叫者都走它：`normalize_table`（字面與展開落地時把資料鍵收進分支）、`rules_with_parent_data`（施用時旁邊的資料鍵併進已有的 `%rules`）、`table_branch_for_name`（依這個名字找分支）。
2. `table_display_rows`（`value.rs`）照 D107。原子約束先試裸鍵；`constraint_from_data_key` 讀回的分支名與這個約束相同才裸印，否則印 `@{ … }:`。`Value::to_nlang` 印表時走這裡。`oo eval` 與已落地的 `oo status` 都是這條。v0.86.0 上 evolve 之後、commit 之前，`k: { @{ @str }: 1, #a: 2, _: 0 }` 的 status 印 `"#a":`；交付印 `#a:`。提交之後兩邊的 status 都只說宇宙是靜止的，不再印那張表。
3. `bn_serial` 不讀拼法。它編的是已經定好的原子：字串與標籤的標記不同，所以帶標籤鍵的表，分支名從字串的摘要換成標籤的摘要，根跟著動。編碼器沒有改。`encoding≥5` 的耐久形是 `store_codec::encode_value`，同樣編原子，不從拼法猜約束。磁碟宣告沒有改。
4. `oo fmt` 印的是源碼（`program.to_nlang`），保留 `#a:`、`"#b":`、`@{ "#c" }:`、`@{ "4" }:`。兩版輸出相同。
5. 沒有模式鍵的 Combo 印欄位時仍走 `quote_nlang_field_key`，印的是座標字串。`{ #a: 2 }` 仍印成 `{ "#a": 2 }`。這是工單 §6 留下的，沒有改。
6. 剖析器仍把 `#a:` 剖成單段路徑鍵，與 `"#a":` 是同一個座標。沒有把它剖成模式鍵。
