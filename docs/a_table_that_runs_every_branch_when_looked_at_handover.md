# 工單：一張被看一眼就跑完每一支分支的表（Q-087）

> 佇列 `nlang-spec/meta/WORK_QUEUE.md` Q-087（原 Inbox「表的分支本體印出後讀不回」，偵察推寬）／**裁定 D109**（2026-10-14 用戶裁定，「都按建議」）：Q1 乙——需要輸入（本體自由出現 `$`）或帶效應的本體，在分派選中之前是程式碼，以程式碼定址、比 `=`、印源碼；封閉而純的本體照舊可提前求值、以值定址。Q2 甲——同一分支的多個本體各印一列，鍵重複。依據另有 `SPEC_07` §1（「本體**只在分派選中該分支時**才求值」；D101 一個正規形）、`SYNTAX_12` §4 #5（分支值中的 `$` 是被匹配的輸入）、`SYNTAX_02` §4 #12（印出讀回同一個值）
> 探針（已預先提交並校準）`crates/oo/tests/a_table_that_runs_every_branch_when_looked_at_probe_test.rs`
> 基線：dev `94ebbed`／`oo v0.88.0` 行為 ⟹ **1 綠 5 紅**；五支紅的都紅在一般斷言，只紅在非對照格，零空洞讀數。

## 1. 缺陷

〔量，v0.88.0；v0.78.0 同〕表被觀測時，分支本體被當成值強制：

*   **沒被選中的分支的效應執行**：`{ @{ @int }: 1, _: ~%Io./write_file ("q.txt", "x") }` 在 `oo eval`、`=`、`run --observe`、`oo commit` 都寫出 `q.txt`；施用（`… 5`）、`oo status`、`evolve` 不寫。
*   **提交把本體凍成強制的結果**：`k: { @{ @int }: $ * 10 }` 提交後 `_.k 5` ⟹ ⊥ `#no_context`（就地 `50`）；效應本體存成 `#true`，表從此不再寫檔；`k: { @{ @int }: $ + 1 }`、`… $ * 2`、`… $ * 10` 三者提交後**同根 `7c78f39a…`**。
*   **`=`**：`{ @{ @int }: $ + 1 } = { @{ @int }: $ * 2 }` ⟹ `#true`（施於 `5` 得 `6`／`10`）。
*   **印出**：`$` 本體印成 `_|_ ;; %cause: #no_context …`（巢狀在欄位裡、就地印也是）；多本體以 ` & ` 相接，讀回是一個本體。
*   **D101**：`({ @{ @int }: 1 } & { @{ @int }: 2 }) = { @{ @int }: 1, @{ @int }: 2 }` ⟹ `#false`。

〔讀〕成因（三處，同一件事的三面）：

*   `lib.rs` `force_recursive` 沿 meta 軸走進 `%rules` 的分支繭，把 `%val` 的 thunk 強制掉（`=` 先對兩邊 `force_recursive`；`oo eval` 印之前也是）。
*   `lib.rs` `project_for_commit`：非純 thunk 直接強制（效應執行）；純 thunk 強制後若得 ⊥ 就存 ⊥——`$ + 1` 被預測為純，在沒有輸入時強制得 `#no_context`。
*   本體集合的鍵（`join_rule_cocoons`）在本體是 thunk 時算一次、是值時算一次，兩條路不同；thunk 的身分又內嵌整個定義框（`bn_serial` `TAG_THUNK` 逐框 `serialize_combo`），同一個 `$ + 1` 放在不同的表裡身分就不同。

## 2. 裁定與依據

*   **核心不須裁**：`SPEC_07` §1 逐字「本體只在分派選中該分支時才求值」。
*   **D109 Q1 乙**：延後本體＝本體自由出現 `$`，或其預測效應不是 `#pure`。它在選中之前是程式碼——不被觀測強制、不被提交強制、以程式碼比 `=`、印源碼；**其身分像箭頭本體**：表達式加它捕捉的名字（不是周圍每一框的全部）。封閉而純的本體照舊。**不取甲**（每個本體都是程式碼）：每張表的根都會動，並把 Inbox「`=` 對 Thunk 外延、位址內涵」整個帶進來。
*   **D109 Q2 甲**：多本體各印一列、鍵重複——`{ @{ 4 }: "g", @{ 4 }: "f" }`；同一約束出現多次是同一分支、本體成集合（§1），讀回就是那個集合。
*   **位址**：〔量，參考實作〕**只移動今天就錯的根**——`$` 本體的三根由同根 `7c78f39a…` 分成三根（`b91f202d…`／`37026f7d…`／`38eab6ee…`）；封閉純本體的表不動（`43480b6b…`、`72ce697e…`、Q-084 的 `84df117f…`／`275bc55d…`）。

## 3. 射程＝不變式（不是機制）

*   **I1 看一張表不執行任何分支**：`oo eval`、`=`、`run --observe`、`evolve`、`status`、`commit`、提交後讀表——都不執行沒被選中的分支；選中的照常執行（r1）。
*   **I2 提交保存它拿到的東西**：延後本體提交後仍是程式碼——施用答案與就地同、效應本體在選中時才執行、兩支不同的函式兩個根（r2）。
*   **I3 `=` 相等的表答得一樣，同一張表怎麼寫成都相等**：不同的延後本體不相等；`&`、字面、展開組出的同一張表相等（D101）（r3）。
*   **I4 印出的表讀回是自己**：延後本體印源碼；巢狀、展開、兄弟名字（`$ + k`）皆讀得回（r4）。
*   **I5 多本體一個本體一列**（r5）。
*   **I6 封閉而純的本體是值**：`{ @{ 4 }: 1 + 1 } = { @{ 4 }: 2 }`、印 `2`、這種表的根不動（g1——**裁定 Q1 本身**）。
*   **若你找到另一個觀測表時強制本體的入口**（`identify`、`oo inspect`、`fmt`、某個內建收到表作引數……），一併在射程內，並在 8.1 列出。「本體只在選中時求值」是要守的不變式；改 `force_recursive` 與 `project_for_commit` 只是一種機制。

## 6. 明文不在射程內

*   一般欄位的效應在提交時執行（`k: { a: <效應> }`）：那是觀測（CbO）。
*   欄位裡的 `$`（`{ a: $ + 1 }`、`[$ + 1]`）印成 ⊥：那個 `$` 指外層演化，是另一件事。
*   兄弟欄位的效應沾到 `_.x` 的 `%effect` 標記（`_.x => 1 ;; %effect: #io`，v0.88.0 同）。
*   `k: { @{ 4 }: 1 + 1 }` 與 `k: { @{ 4 }: 2 }` 兩根而 `=` 為 `#true`：Inbox「`=` 對 Thunk 外延、位址內涵」，兩版同。
*   箭頭的印出形不可施用（Inbox「`SPEC_07` §5.2 定義 1 寫出的等價形不可施用」）。
*   規格文字與 `CHANGELOG`：驗收方收尾。
