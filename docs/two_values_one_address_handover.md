**日期**：2026-09-16
**引擎起點**：v0.51.0／**規格起點**：v0.51.0-draft.1
**裁定**：**D69**（拿掉雜湊時的 `trim`）。本弧是它的落地，**不需要新的裁定**。
**探針**：`crates/oo/tests/two_values_one_address_probe_test.rs`（驗收方已寫並校準，**基線 3 綠 3 紅**）

---

## 1. 這一弧是什麼

**一次回報成功的提交，存進去的是別人的值。**
〔量 2026-09-16，`v0.51.0` 標籤建置，同一個倉，普通的 evolve／commit 路徑〕

```
提交 v: "a"      → 根 3f9c002b…
提交 v: " a "    → rc=0、逐字 Commit successful、根仍 3f9c002b…
inspect 那顆根   → v: "a"                  ← 不是他剛提交的那個
```

**而語言說它們是兩個值**：`("a" = " a ")` → **`#false`**，兩者 `.%id` 亦不同
⟹ **引擎有兩個互相矛盾的身分函數。**
〔對照組〕`"a"` 與 `"b"` 位址不同 ⟹ 量測碰得到目標。

**成因是一行**，〔讀 `crates/interpreter/src/bn_serial.rs:191`〕：

```rust
AtomKind::Str(s) | AtomKind::MultilineStr(s) => {
    buf.push(TAG_ATOM);
    encode_string(s.trim(), buf)      // ← 雜湊前去空白，而值保有空白
}
```

**它沒有出處**〔查 git〕自 **2026-05-23「Phase 1a」**BN/ 的第一個實作就在，
而該提交訊息列了 prefix-ordered sorting／LEB128／fixed floats／union dedup——**獨獨沒有它**。
**而 `REAL_03` §6.1 的字串編碼逐字是 `[長度: u32_LEB128] [內容: UTF-8 bytes]`**，
全文對 `trim`／「去除空白」／「修剪」**零命中**
⟹ **不是規格不完整，是引擎偏離了一條已經寫完的規則。**

### 1.1 為什麼不是「改成把值正規化」

那一臂是 `Str` 與 `MultilineStr` **共用**的，trim 八成是為 `"""…"""` 的排版寫的。
**它連那件事也沒做成**：〔量〕多行 `"""\nhello\n"""` 與 `"hello"` **`=` 判 `#false` 而同址**。

**而多行真正需要的正規化是另一類。** `SYNTAX_02` §116 逐字「**字串無跳脫序列**」、
§110／§129 逐字多行「**其內僅有的跳脫為三引號跳脫**」；〔量〕引擎兌現了第一條
（`"a\nb"` 印回 `"a\nb"`；`"a\"b"` → parse error）。

⟹ **`\"""` → `"""` 發生在剖析時，它決定「這段源碼指稱哪個值」；
`trim` 發生在雜湊時，它決定「這個值的位址是什麼」。兩者不同類，前者不替後者背書。**

---

## 2. 射程 ＝ 兩條不變式

### I1 兩個 `=` 判為不同的值，不得共用一個儲存位址

### I2 身分不得依賴一個值上沒有發生的正規化

**`bn_serial` 在雜湊前不得改動內容。** 正規化若有，屬**剖析時**。

---

## 3. 明確不做

1. **`=` 的語義。** 本弧修的是身分不是相等（**G2 是紅線**）。
2. **`MultilineStr` 是二等公民。**〔量，對照組活的〕`~%Str./concat ("a","b")` → `"ab"`
   而 `concat(多行, "b")` → `_|_ #conflict`；`~%Io./write_file` **亦不接受多行**
   ⟹ **值層當它們是兩種東西，身分層當它們是同一種——兩層方向相反。**
   **那是不同的事，已另開 Inbox 列，不併入。**
3. **`REAL_03` §6.2 的值編碼表缺五個標記**（`0x17`／`0x18`／`0xFD`／`0xFE`／`0xFF`）。**另一張卡。**
4. **規格側的對偶缺口**：§6.7 只寫了 `bytes = f(value)`，沒寫「不同的值不得共用位址」
   ⟹ **驗收方的規格結案，不要自己改規格。**

---

## 4. 紅線

**R1 標準根與 `x: 0` 根不得移動。** 〔依據，已量〕標準根的 **258 個字串中，
前後帶空白者 0、含換行者 0** ⟹ 拿掉 trim **不會**碰到它。**G3 是這條紅線。**

**R2 `=` 不得改變**（G2）。

**R3 conformance 162／162。** 〔已量〕語料含 `"""` 者 **0 檔**、
含前後空白字串者 **6 檔** ⟹ 若有向量因此變動，**在 §N.3 說，不要改語料**。

**R4 這是一次紀元，而你要把它的範圍量出來寫在 §N.2**：移動的是**含前後空白字串
或多行字串的既有值**。**不得只說「應該很少」。**

**R5 探針不得改動，也不得被 `rustfmt` 掃到。**

**R6 離開碼不得在管線之後取。**

### N.3 我認為驗收方寫錯的地方

**R1 把「第二筆提交必須成功」寫成了 I1。** 同一倉先 `v: "a"` 再 evolve `v: " a "`：根座標單調（G2-S）對已提交的 `"a"` 做 meet。修前成功，是因為 trim 讓兩個值 **CAID 相同**，unify 早退當成同一個值——**那正是這個 bug 的成功形**。修後 `"a" & " a "` 是 ⊥ ⟹ **Evolution Conflict `#conflict at v` rc=1**，這是真話，不是還沒修好。I1 要的「不得同址」由 R2／R3 與兩顆新鮮倉的不同根兌現。探針未改，R1 保持紅。

### N.4 §6 五問的回答

**1.** **有還原。** 剖析 `parse_multiline_body`：`inner.replace("\\\"\"\"", "\"\"\"")`。〔量〕源碼 `"""\nx\"""y\n"""` 印回 `"""\nx\"""y\n"""`——印表機 `quote_nlang_multiline` 是反運算（把 `"""` 再逃成 `\"""`）；若沒還原，值裡會留下反斜線，印出會多一層反斜線。`~%Str./contains` **不接受多行**（施用形是 `(pattern, haystack)` 且兩臂皆 `AtomKind::Str`）。對照：`contains ("b", "abc")` → `#true`；`contains ("z", "abc")` → `#false`（證明呼叫發生；驗收方寫的 `contains("abc","b")` 是反序，故 `#false`）。`write_file` 不接受多行＝Inbox 那列，不是「沒還原」的證據。

**2.** `bn_serial.rs` 雜湊前改動內容的每一處：

| 處 | 做了什麼 | |
| :-- | :-- | :-- |
| `:191` `s.trim()` | 去掉字串前後空白 | **本弧刪掉** |
| `:212` `trim_start_matches('#')` | tag 拼法；剖析已剝 `#` | 安全。〔量〕`#x = "x"` `#false`，標記位元組不同 |
| `:198` 大整數溢位寫 `0` | 把值改成別的值 | **不安全**，不是本弧；未修 |
| union 排序去重／combo 鍵排序 | 正準形 | 不改成員內容 |
| Thunk `to_nlang`／Code `Debug` | 結構的編碼 | 不是 trim |
| TagStart／TagEnd／Unit／Bytes hex／float fixed128 | 種類的編碼 | 不是 trim |

**3.** 見 N.2 紀元表。量法：對照組 `"a"` 的 CAID／根在修前後相同；padded／多行變了；標準根 digest 不變；語料 `.n` 掃描 padded／`"""`；舊引擎對新 padded 倉重算成舊 digest。

**4.** `%id` 是 `content_hash_with_salt`（v1、`hash_recursive`，字串本來就不 trim）；儲存 CAID 是 `bn_serial` digest＋sketch（v2）。兩個數本來就不同。修後「分得開」一致：`"a"` 與 `" a "` 的 `%id` 不同、儲存 CAID 也不同（修前只有 `%id` 分得開）。

**5.** 見 N.3。

### N.5 規格側的發現（不要自己改）

`REAL_03` §6.7 仍缺「不同的值不得共用位址」那一款。舊引擎把新 padded 物件判成 `#caid_mismatch` 而重算結果是**別人的根**——這是 trim 紀元對舊讀者的形狀。

### N.6 我沒做的事

`=` 的語義。MultilineStr 二等公民（`contains`／`concat`／`write_file`）。值編碼表缺五個標記。規格正文。本弧探針。標準根。大整數溢位寫 0。
