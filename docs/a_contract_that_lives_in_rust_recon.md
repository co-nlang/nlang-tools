## 1. 施用層的 seam 是一個點，不是 217 個

〔讀 `crates/interpreter/src/lib.rs:3138-3170`〕內建的派送與失配處理逐字是：

```rust
if let Some(func) = self.builtin_registry.get(builtin_id) {
    let res = func(unified_arg.clone(), self, ctx);
    if let Value::Top = res {
        …建出部分施用的繭…
    }
```

⟹ **「形狀沒對上 → 部分施用的繭」這個機制今天就存在，而且集中在一個地方。**
內建表達「我沒對上」的方式是**回 `Value::Top`**。

〔讀 `:3027-3074`〕`unified_arg` 的組成也在同一處，且**已含 2026-07-25 那次修法**：
態射累積的數字鍵 ＋ 引數的數字鍵（arg-pack）或引數本身放進下一個位置（並加 `%arg` 標記）
＋ **引數的非 `%` 具名欄位被抬到頂層**（註解逐字引 SPEC_08 §3.5）。

**⟹ 施工不必動 217 個呼叫點的「失配路徑」，只需要在這一個點之前加一次「宣告比對」。**

〔量 2026-08-26，對 `crates/interpreter/src/builtins/*.rs` 全體做語法擷取

⟹ **207／241（85.9%）是固定 arity 的純位置形，鍵集可由現有原始碼機械讀出。**

**那 34 個「無 `get_field`」不是例外，是走了共用 helper**〔讀，抽樣〕：

**結論：卡片上那個風險不成立。** 施工形狀是「**在註冊點加一個鍵集宣告 ＋ 在單一 seam 前比對**」，

## 4. 這一族到底有幾種約定 —— 比 Inbox 那一列記的多

〔量 2026-08-26，v0.36.0，每一格兩種順序各跑一次〕

| 內建 | list-first | pred-first | 判定 |
| :--- | :--- | :--- | :--- |
| `~%List./filter` | `[1,2,3]` ✅ | `[1,2,3]` ✅ | **嗅探（兩種都吃）** |
| `~%List./map` | `[9,9,9]` ✅ | `[9,9,9]` ✅ | **嗅探** |
| `~%List./take_while`／`/drop_while` | `[1,2,3]` ✅ | **`[]`** ❌無聲 | **list-first** |
| `~%List./flat_map` | **`[]`** ❌無聲 | `[1,2]` ✅ | **pred-first** |

## 5. ⚠ 射程裡有一件用戶必須裁的事，卡片上沒有

**O76 讓「每個態射自己宣告」成為規範 —— 但它不要求兩個態射宣告同一種。**

在 O76 之下，`~%Query./where` 宣告 list-first、`~%List./count` 宣告 pred-first，
**兩者都合規**。規格因此會允許一個**自己內部不一致的標準庫**。

而「一個概念一種正準拼法」是**方法論**，不是規格條文；它管的是語言的拼法，
不當然管標準庫的簽名風格。⟹ **這一題不是 O76 的推論，得另外裁：**

> **Q-039 的射程含不含「把標準庫的 callback 約定統一成一種」？**

*   **(A) 只要宣告，不統一** —— 最小改動，向後相容（今天寫對的呼叫繼續對）。
    代價：標準庫永久保有四種約定，只是從此**錯的形會響**。
*   **(B) 宣告並統一** —— 標準庫從此一種約定。
    代價：**破壞性**，今天寫對的呼叫有一半會變成錯的。

**價碼已量**（見 §6）：(B) 的爆炸半徑在語料裡**只有兩支 conformance 向量**。

## 6. 爆炸半徑：小，但兩支 conformance 向量在裡面

〔量〕全機 **224 個 `.n` 檔**，呼叫這一族的**只有 1 處**——而那一處是 **conformance L2-116**。
Rust 測試側：`/any` 6、`/find` 5、`/all` 4、`/partition` 4、`/filter` 2、`/count` 2 處。

**兩支向量在射程內，性質不同：**

*   **L2-104**（`~%Engine./project_down { target:, masa: }`）——**紅線，不得改**。
    O76 明文允許具名鍵；那七個具名內建不是要改成位置式，是要**宣告**。
*   **L2-116**（`~%List./filter ([1,2,3], (x -> …))`，list-first）——**若走 (B) 須改寫，而改寫是安全的**：
    〔量〕兩種引數序**都得 `⊥ #effect_violation`** ⟹ 它釘的主題（被丟掉的布林仍帶著障礙）
    **與引數序無關**。
*   **L2-117**（`~%Query./where ([{a:1}], (r -> #true))`，list-first）——**⚠ 這一支不安全**：
    〔量〕list-first → `1`（正確）／pred-first → **`0`**。
    它釘的主題（誠實的純謂詞寫得出來）**在觀測到的答案上就是引數序敏感的** ⟹
    若走 (B) 且把 `where` 統一成 pred-first，**必須連同 `where` 的實作一起改**，
    否則這支向量會從「1」變成「0」而仍然綠 —— **那正是本弧要治的那個病的又一個實例**。

## 7. 明確不做

*   **不裁「哪一種順序是正準的」作為語言規則** —— O76 已定：由態射宣告。§5 那一題是**標準庫的家規**，層級不同。
*   **不動 `~%Cond./cond`／`./match` 的分支表語義** —— 只要它宣告它收什麼。
*   **不動身分** —— 根 `932a9f9d…`／標準根 `7038e250…` 為紅線。
    〔註〕宣告若進入內建的**值**（`%rules`／`%params`），**標準根內容會變 ⟹ digest 移動 ⟹ 紀元**。
    **這是本弧最大的一個未決口，見 §8。**
*   **不改 apply 層的 `unified_arg` 組成** —— 2026-07-25 已裁並修好。

## 8. ⚠ 開單前必須先答的第二題（偵察方在本文件中發現，卡片上沒有）

O76 ③ 說宣告的住處是「態射自身的值」（`%rules`／`%params`）。**若照字面做，內建的值會多出欄位。**

〔量〕標準根裡有 **251 個相異的內建名稱參照**，其耐久形逐字是
`{ meta: { builtin: "bytes.at", morphism: #true } }`。**任何一個內建的值多一個欄位，
標準根的 digest 就會移動，而標準根 ⊕ 進每一個根的身分**（O58）⟹ **這是一次紀元。**

而 `WORK_QUEUE` §9.0 逐字寫著：**身分只該搬一次**，且今天已經排著另外兩件要併的
（**D-3 `fetch` 效果 ＋ Q-035 的 Q1 引用式 import**）。

**⟹ 三個選項，必須在開工單前裁：**

| | 做法 | 代價 |
| :-- | :--- | :--- |
| **(i)** | 宣告住在**引擎的 registry**，不進值 | 不動身分、可立刻做；但 O76 ③ 的字面「住在值裡」**沒有兌現**，規格得改措辭 |
| **(ii)** | 宣告進值，**本弧自己付一次紀元** | 違反 §9.0「身分只該搬一次」 |
| **(iii)** | 宣告進值，**與 D-3 ＋ Q1 併成同一次紀元** | 對，但 Q-039 因此**被那兩件擋住**，不能現在做 |

**偵察方的建議：(i)。** 理由是 O76 ③ 的**目的**是「合約必須是一件規格事實，不是一件 Rust 事實」，
而 registry 的宣告若由規格定義其形狀與內容，這個目的就達成了；「住在值裡」是**手段**。
若用戶要維持字面，則本弧應改列 Blocked，掛在那次紀元底下。

## 11. 用戶裁定（2026-08-26，本偵察交付後）與它引出的量測

**§5 → (B) 宣告並統一。** 用戶語：「我覺得這比較像是把沒說清的東西說清。」
並附一個限制：**判斷要更有彈性**——不確定現有的不一致「單純只是一種習慣，還是一種必須」；
給的例子是「**同一個模組底下，相似型的態射要傾向使用同一種**」。

**§8 → (i) 宣告住 registry，不進值。** ⟹ 不動身分，本弧不是紀元，不必掛在 D-3 ＋ Q1 那次搬遷底下。

### 11.1 「習慣還是必須」——這一題有量測答案，不必靠美感

〔量 2026-08-26，v0.36.0〕`|>` **把被管的值放進下一個空位**（`lib.rs:3049`
逐字 `nf.insert((max_idx + 1).to_string(), arg.clone())`）。逐格量：

| 群 | `data |> /f (callback)` |
| :--- | :--- |
| pred-first（`/any`／`/all`／`/count`／`/flat_map`） | ✅ 正確 |
| 嗅探（`/map`／`/filter`） | ✅ 正確（靠嗅探救回來） |
| **list-first（`/take_while`／`/drop_while`）** | **`[]` —— 無聲的錯答案** |
| **list-first（`~%Query./where`）** | **`⊥ #conflict`** |

⟹ **`|>` 只與「資料放最後」組合得起來。** 這不是風格判斷，是 curry 累積的後果：
callback 先填滿前面的位置，管道補上最後一個。

**因此那個不一致是「習慣」，但兩種習慣不等價**——其中一種**在結構上與語言的核心運算子不相容**。
最鋒利的一格：**`~%Query` 是查詢模組，最該被管道用，而 `~%Query./where` 今天在管道下是 ⊥。**

⟹ **偵察方建議的正準判準（非美感、可證偽）**：

> **凡意圖被 `|>` 使用的態射，其資料參數必須是最後一個。**

它與用戶的「同一模組相似型傾向同一種」不衝突，而是**更強**：它給出「傾向哪一種」的理由，
而不只是「要一致」。模組內一致性可留為 SHOULD，本判準為 MUST 的候選。

### 11.2 統一的射程比 §4 那張表大：`list.fold` 是第五種形

〔讀 `list.rs`，`list.fold`〕它取**兩個**鍵、**嗅探**哪一個是清單，
而另一個必須是一個 combo `{ %val: 初值, %f: 態射 }` ——
**種子與函式打包在一個記錄裡**。〔量〕`fold(f, init, list)`／`fold(list, init, f)`
兩種三引數寫法**都得繭**。

⟹ 「統一」不只是把 list-first 翻成 pred-first；`fold` 的形**與其他任何一個都不同**，
而它是最常被引用的高階態射之一。**工單必須逐個列出全部 40 個 `~%List` 註冊點的現行形**，
不能只處理已量到的那幾個。

## 12. 驗收時對本偵察的兩處更正（2026-08-26，驗收方）

**① §2／§6 的「七個具名內建」是六個。** `diff.patch` 不在其中——〔讀 `diff.rs`〕它的
`path`／`to` 是 **diff 清單裡每一個條目（`ec`）上的欄**，不是態射綁定的鍵；該態射綁的是
`0`＝值、`1`＝diff 清單。**成因**：驗收方的擷取腳本把閉包內任何 `get_field("<名字>")`
都算成引數上的鍵，沒有區分它讀的是 `arg` 還是迴圈裡的條目。**由交付方在 §7.3 指出。**
其餘六個（`engine.project_down`／`project_up`／`set_strategy`／`check_oml`、
`disc.find`、`query.select`）逐一複查，確實讀自引數。

**② §3 的「整個面只有六行」是錯的，真正的面有三個 helper。** 除了那六處印出形比對，還有：

*   `list.rs` 的 **`is_truthy_pred`**（`take_while`／`drop_while` 用）
*   `query.rs` 的 **`is_truthy`**（`query.where` 用）

**兩個都是寬鬆形**（`_ => true`，即「不是 `#false` 就算真」）而且**同樣把 ⊥ 折成假**
（`Value::Bottom(_) => false`）。**成因**：驗收方的 grep 只找 `to_string_plain()` 併同
true／false 的行，兩個寬鬆 helper 不符合那個 pattern。

⟹ **這是同一弧內第二次同型失誤**（第一次是 `~%Refl` 拼法）：
**量到缺陷的一種拼法，就以為量到了整個面。** 交付方三個都找到並統一了，比工單要求的徹底。

**③ 那個統一帶來一個 §7.2 未指名的行為變更**（驗收時量到，見 `ENGINE_SYNC` 本弧條目）：
真值判準由「不是 `#false` 就算真」收窄為「只有 `#true` 算真」，影響
`~%Query./where`／`~%List./take_while`／`~%List./drop_while`。
〔量，兩個真二進位各用自己版本的正確引數序〕謂詞回 `5` 或 `#none`：v0.36.0 **保留**，交付 **丟棄**。
**規格從未定義「謂詞為真」**（`SPEC_09` 僅在 `/lt` 一格寫「→ `#true`／`#false`」）⟹ §2.5。
由驗收方於收尾補條文與向量。
