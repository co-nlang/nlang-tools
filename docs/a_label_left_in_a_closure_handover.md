# 一個留在閉包裡的標記（Q-132）

## 0. 判準

*   **標記就是在最後的工作集裡建一次這個值會得到的標記**：
    *   後到的名字把標記給讀它的坐標（Q-128 M2）；讀者的讀者也是讀者，傳到底（Q-129）。
    *   一個 thunk 帶著寫它的那個節點的一份快照（`capture_free_fields`）。快照裡的 `x: b` 讀 `b`，也是讀者。函式連快照一起存進根。
    *   記錄自己的標記，是建構它時從欄位收來的：`data`、`@` 型別、`/` 規則、`%` meta、`~` local 五軸。函式值和繭不算。
*   **就地落地等於交會**（Q-117 shadow 紅線）。
*   **同一個 session 裡，一筆寫入分幾次演化，存同一顆根**（`SYNTAX_03` §2 #1）。前提是沒有觀測時機的差別：若有一格在它讀的名字寫進來之前就被觀測，那是不同的寫入（D127），不在此列。
*   **pin 成純的，等於一開始就寫純的**（Q-129 M5）。
*   **不須裁**：以上都是已寫下的不變式。

## 1. 缺陷

〔量，`v0.131.0` 標籤建置；`acc/q132/recon.py`、`fn.py`、`dump.sh`、`pindump.sh`；提交前傾印 `acc/q132/dbg3.py`（`Q132_DUMP`）〕

*   **先寫函式、後寫它讀的名字，根不同**（v0.127.0 就有）：
    *   `a: { e: (n -> n), x: b }`、`b: { f: ~%Env.get … }`：一筆寫完、先 `b` 後 `a` 分兩次演化，根都是 `3b761b02…`；先 `a` 後 `b` 是 `4cc43a08…`。
    *   傾印：`a.e` 是一個 thunk，帶 `a` 的快照；快照裡的 `x: b` 和快照本身，一邊 `#io`、一邊純。印出來逐字相同，讀數相同。
    *   記錄環加函式（`b: { y: a, f: … }`）同樣。清單裝著記錄（`b: [a, …]`）同樣。
*   **pin 成純的，根不是寫純的**（Inbox「pin 之後的根」(2)、(4)）：
    *   `a: { c: ~%Env.get "K", y: b }`、`b: [p]`，pin `p: 7`：`a.y` 快照裡的 `c: ~%Env.get …` 被標成**純**，寫純的那一邊是 `#io`。
    *   `a: { @T: ~%Env.get "K", y: p }`、`m: [a]`，pin 之後 `a` 自己是純的；寫純的是 `#io`。`/r:`、`%k:` 同樣。
*   **環上，就地落地與交會不等**（開 `OO_Q117_SHADOW` 就 panic；v0.128.0 起，v0.130.0 範圍變寬）：
    *   `a: { e: E, x: b }`、`b: { y: a }` 一類，十二形，大部分順序。
    *   Q-131 的探針 r4 開 shadow 有 8／13 筆 panic。
*   **成因**〔讀碼，修法與插樁驗證〕：
    *   `clear_thunk_effects` 只在 thunk 自己不純時才走進快照；`raise_thunk_effects`、`refresh_thunk_effects` 只在 thunk 自己的標記變了時才走進去。快照裡的標記於是可能停在被清成的純（pin），或停在寫它時的舊值（後到的名字）。
    *   `fields_effect` 與 `raise_thunk_effects` 收記錄的標記只看 `data`、`local`，建構時看五軸。
    *   **另一個成因，和閉包無關**：Q-128 的就地落地，要等讀者收斂完才把新鍵加進讀者索引。在穿過新名字的環上（先寫 `b: { y: a }`、再寫 `a: { …, x: b }`），新值自己是它的讀者的讀者，卻沒被收斂，`a.x: b` 停在純。交會那一側從整份工作集找讀者，所以兩邊不等。
