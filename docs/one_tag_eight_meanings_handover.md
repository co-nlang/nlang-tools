## 1. 一句主張

〔量，`v0.52.0` 標籤建置，對照組 `"x"` ≠ `"y"` 活著〕

```
"ab"  r"ab"  p"ab"  u"ab"  t"ab"     五個值，一個位址 2f5992b8…
"()"  ()                             兩個值，一個位址 5f6b36a7…
"6162"  b"ab"                        兩個值，一個位址 4414b39b…
```

每一對 `=` 皆 `#false`，而 meet 全部吸收（`("()" & ())` → `"()"`）。
成因：`serialize_atom` 有八條臂都推 `TAG_ATOM`（`0x10`）再寫一個裸字串
（`Str`／`MultilineStr`／`Code`／`PathLit`／`Unit`／`Regex`／`Uri`／`Time`／`Bytes`）。

## 2. 射程 ＝ 兩條不變式

**I1　語言分得開的兩個值不得共用位址。**
判準是 `=`／反射 `%id`，不是「哪一條臂」。凡今天 `=` 判 `#false` 而位址相同者，本弧治它。

**I2　一個值的種類必須進入它的位址。**
身分不得只由「它的文字碰巧長什麼樣」決定。
**這一條比 I1 強，而它是刻意的**：只滿足 I1 的修法（例如給四個前綴字面一個共同的新標記）
會讓探針 R2 的第一個迴圈通過而第二個迴圈紅——**兩個迴圈都要綠**。

## 3. 必須做的事

**S1　讓每一種 `AtomKind` 的位址分得開。** 標記位元組怎麼配是交付方的決定，
但**必須是決定，不是巧合**：交付回報要逐項列出最終的標記配置（見 S3）。

**S2　不得動 `=`、不得動任何求值語義。** 本弧只治身分。

**S3　交付回報必須附一張逐位元組的標記表**：每一個今天會被寫進 CAS 的標記位元組、
它的意思、以及它的酬載形狀。**這張表是規格結案的輸入**（`REAL_03` §6.2 由驗收方寫）。
表裡必須包含今天 §6.2 缺的五個：`0x17` Thunk／`0x18` Range／`0xFD` Blur／`0xFE` Bottom／`0xFF` Top
——後三個今天**連具名常數都沒有**，是逐字 `buf.push(0xFD)`。

**S4　紀元範圍要量出來寫，不得只說「應該很少」。**

各有多少 `r"`／`p"`／`u"`／`t"`／`b"`／`()` 值，以及標準根裡有沒有。

### N.4 工單指名要你回答的問題

**Q1** 量不出碰撞。入口：`~%Discovery./identify_and_store { u: (1 \| 2) }`（引數是 Combo，不會對 union 分配）。對照：裸 `(1 \| 2)` 經同一入口回兩個 CAID 的 union（`a8b1b4fe… \| 17564af7…`，即 2 與 1）——這是驗收方作廢的那條路。包著的 Combo：`{ u: (1\|2) }` `60a0a450…` ≠ `{ u: 1 }` `4141b60a…` ≠ `{ u: 2 }` `94fa9807…`；`{ u: ("a"\|"b") }` `08c33a67…` ≠ `{ u: "a" }` `bc8938f4…`。`%id`（v1）對 union 有 `0x03` 前綴，`(1\|2).%id` `abdb8eee…` ≠ `1.%id`。成員編碼皆自定界，串接不是單一原子的編碼。單元素 Union 在 `normalize_union` 塌掉，不會以「無標記的一份拷貝」入雜湊。

## R.1 修補回合 1：三引號是書寫法，不是型別（D70）

> **裁定：D70（用戶 2026-09-18）。** 本回合**不需要你再做任何裁定**。
> 探針基線 **8 綠 2 紅**（已校準）。**R1–R4 與 G1–G4 一字未動，不得動。**

### R.1.1 為什麼有這個回合

**不是因為交付做錯了。** 交付給 `MultilineStr` 標記 `0x1F` 是對的——
兩形 `=` 判 `#false` 而修補前同址，那是 §6.7 第二條的違反。

**是因為那個修補讓一個從未被裁過的答案被鑄進位址**，而驗收方為此做簡報時量到：

```
v: "a⏎b"        單行寫法，內含真換行      2024d616…
v: """a⏎b"""    三引號寫法                ecb0980d…
("a⏎b" = """a⏎b""")                       #false
而 run --observe 把兩者都印成  """a⏎b"""
```

⟹ **把第一個值印出來、原封讀回去，得到的是第二個值。**
**一個印成自己的正準形之後就不再是自己的值。**

這是 §6.6／§6.7 那組雙射**在語法層的對偶違反**：那邊兩個值共用一個**位址**，
這邊兩個值共用一個**印出形**。

**而它使「多行是另一種型別」不可能，不是不划算**：那要成立，印出端必須分開兩者，
而 `SYNTAX_02` §4.11（單行**無法**表示 `"` 字元，需要引號者用多行）
與 §4.12（多行**必須**印為三引號形）**正是規格自己禁止印出端做那個區分**。

### R.1.2 射程 ＝ 一條不變式

**I3　一個值印成它自己的正準形再讀回來，必須還是同一個值。**

判準是 round-trip，不是「哪一個 `AtomKind`」。
怎麼做是你的決定——**剖析時即產出單一字串值**是最直接的一條，但不是唯一一條；
**只要 I3 成立、且 I1／I2 不回退，怎麼做都可以。**

### R.1.3 隨之而來的三件（是推論，不是另外的要求）

*   `=` 對兩形變 `#true`。**這是語義變更、破壞性，用戶已知並裁可。**
*   多行值的位址再動一次。〔已量，代價近零〕conformance `"""` **0 次**、標準根 **0**。
*   `0x1F` **保留為死號，不得重用**。規格 §6.2 的那一列由驗收方改寫。

### R.1.4 紅線（不得回退）

*   **R1–R4 仍須全綠**：`()`／`r"`／`p"`／`u"`／`t"`／`b"` 與字串仍須各自分開，
    且四個前綴字面彼此也要分開。**本回合治的是多行，不是把上一回合撤銷。**
*   **G4 邊界不動**：`"a"` `cdf2d551…`／`0` `08da7c45…`／`1.5` `cb3bcb50…`／`#true` `1bc573f2…`。
*   **標準根不動** `7038e250…`；conformance **162／162**；全樹 ×3 逐 target 聚合並留失敗測試名。

### R.1.5 指名要你回答的問題

**Q5　`a"b`（內含引號的文字）今天只能寫成三引號形。合一之後它印回什麼、讀回去是不是同一個值？**
探針 R6 目前只跑 `a⏎b` 與 `hello` 兩個樣本，**刻意沒有跑 `a"b`**——
因為驗收方寫不出它的單行形（§4.11 說寫不出），無從構造「兩種寫法」的對照。
**請你量它的 round-trip（印出→讀回→位址相同），並寫出你怎麼量的。**

**Q6　`oo fmt` 與 `run --observe` 今天對同一個值給兩種寫法**
（〔量〕`fmt` 把 `v: "a⏎b"` 原樣留著，`--observe` 印成三引號形）。
**本回合不要求你修它**（已入 Inbox，與 D70 無關），
