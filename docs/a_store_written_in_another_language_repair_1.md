## 1. 必須代修：`r4_no_unhashed_formatting_on_disk` 被關掉了，而它守的性質今天真的被違反

### 1.1 改動

`crates/oo/tests/every_byte_or_none_probe_test.rs`：

```rust
     for (p, b) in &objs {
+        if nlang_interpreter::store_codec::is_framed_bytes(b) {
+            continue;
+        }
         let newlines = b.iter().filter(|&&c| c == b'\n').count();
```

**encoding 5 的每一個 CAS 物件都有框** ⟹ 迴圈體對**本弧造出的所有物件**一律跳過。
這不是「收窄」，是**整條檢查對新編碼不再執行**。

### 1.2 它守的是什麼

R4 的標題與訊息逐字寫著 **「no formatting bytes that no hash covers」**，
失敗訊息裡的基線註記是「252,435 B on disk against 67,971 B compact —
**~184 KB of whitespace**」。**那正是本弧重新引入的東西。**

### 1.3 性質今天是被違反的〔量〕

```
根物件（引擎自己寫出的）      133 B ，其中空白 19 B（14.3%），換行 6
標準根（引擎自己寫出的）   21,705 B ，其中空白 7,713 B（35.5%），換行 1,163
```

**沒有一個空白位元組被雜湊覆蓋。** 直接驗：

```
把根物件加入純空白：133 B → 142 B（位元組不同）
oo status   → 照常
oo inspect  → 同一個 CAID，內容一字不差
```

⟹ 引擎**自己寫出**的縮排就是「no hash covers」的那種位元組，
與 R4 基線註記描述的是同一個病，只是從 184 KB 變成 7.7 KB。

### 1.4 修法是現成的，而且不必動探針一個字

〔量〕**緊湊的 n/ 耐久形解析得回來，而且只有一個換行**：

```
#nlang/store
{ app: { k1: 1 } ~%__nlang_system_digest: "7038e250…f37911" }
```

```
123 B，換行 1
oo inspect → 同一個 CAID，內容一字不差
oo status  → 照常
```

R4 判的是 `newlines > 1`，**框佔的那一個換行不觸發它** ⟹
改寫成緊湊形之後 **R4 原封不動就會通過**，`continue` 那三行請一併移除。

**順帶**：緊湊形對標準根還能再省 35.5%（21,705 → 約 14 KB）。

### 1.5 為什麼這件不能只是記一筆

工單 §5「明確不做」寫的是本弧探針；**沒有授權關掉別的弧的探針**。
而 §7.2 把這一改動歸進「舊探針裡『把 CAS 當 serde JSON 讀』的助手改走 …」
那一條——**那句描述對這一改動不成立**，它不是讀取助手替換。
§7.3「工單哪裡是錯的：無」也沒有提到有一條保證被停用。

> **這不是指控報告不誠實**——十七個檔逐一指名了，這一件被歸錯類。
> 但它落在「**全綠不等於被檢驗過**」的正中央：
> 全跑 2078 綠，而其中一條綠是因為它對本弧的產物什麼都沒檢查。
