## 1. 缺陷

〔量，v0.81.0；v0.27.0、v0.40.0、v0.60.0、v0.75.0 逐格相同——從來沒對過〕

*   **態射的聯集被施用，一律 ⊥ `#conflict`**：`((x @int -> x + 1) | (x @str -> x + "!")) 5`（規格 `6`）、`"hi"`（規格 `"hi!"`）、`((x -> 1) | (y -> 2)) 4`、`({ @{ @int }: 1 } | { @{ @str }: 2 }) 4`、`(~%Math./add 1 | (x -> x)) 4`、`5 |> ((x -> x + 1) | (y -> y * 10))`；具名、在 Combo 裡、提交後皆同。兩支都不匹配（`((@int -> "int") | (@str -> "s")) #a`）也是 `#conflict`。
*   聯集值本身是對的（兩種寫法都保持 `A | B`，各成員完好）；導航遇聯集逐支分配（`({ a: 1 } | { a: 2 }).a` ⟹ `1 | 2`），引數是聯集時施用也逐支分配——只有「被施用的是聯集」沒有。
*   **引數側全 ⊥ 時丟掉成因**：`(x @int -> x) ("a" | "b")`、`{ a: 1 } ("b" | "c")`、`("a" | "b") |> (x @int -> x)` ⟹ `#conflict`，兩支各自是 `#no_matching_branch`。

## 2. 裁定與依據

*   **D104（A）**：態射的 `|` 就是 Combo 的 `|`。箭頭換回它的 Combo 形，兩個態射的聯集是兩個 Combo 的聯集；被施用時逐支分配——`(A | B) x ≡ A x | B x`。**特定性只在單一成員內比**：要跨分支比特定性，寫成一張表。例：`((@int -> "int") | (5 -> "five")) 5` ⟹ `"int" | "five"`，而表 `{ @{ @int }: "int", 5: "five" } 5` ⟹ `"five"`。
*   ⊥ 支剪掉（`SPEC_06` §1.3 第 4 條）；全 ⊥ 時結果是主因果位階最高的那個成員的 ⊥，**原樣**傳出（`REAL_04` §4 工程補充；同位階取相遇序最左）。引數側今天違反這一條。

## 3. 射程＝不變式（不是機制）

*   **I1 施用一個聯集就是逐支施用**：直接施用、管道（右手邊是寫出來的聯集，或經路徑、欄位到達的聯集）、柯里化的每一步、在 Combo 裡、具名、提交後、`run --observe`，皆得 `A x | B x`（r1、r2、r6、r7、r8）。
*   **I2 成員之間不比特定性；成員之內照舊**：一張表、一支帶模式的箭頭的分派完全不變（r2、g1）。
*   **I3 每一種成員就以它自己被施用**：表、箭頭、內建、部分施用、依鍵查找的 Combo；不可施用的成員（原子）得 ⊥、被剪掉（r3、g4）。
*   **I4 ⊥ 支剪掉；全 ⊥ 取主因果、原樣傳出——兩側同一條規則**：被施用的聯集、被套用的聯集（含管道左手邊）（r4、r5）。
*   **I5 兩側都是聯集：每一對都在**（r9）。
*   **I6 每個成員、每個分支只施用一次**：帶效應的成員各執行一次（r10、g5）。
*   **I7 其餘不動**：被套用的聯集有倖存支時照舊（g2）；管道接一般值的聯集照舊是逐支相交（g3）；聯集值、表、沒有施用在裡面的值，位址不動（g4）；態射的 `&`（`SPEC_07` §5.3 定義 1，待裁）讀數一字不動（g6）。
