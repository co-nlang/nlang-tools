### 1.2 ○ 與 ● 從不互相指涉——本卡最重要的一句

〔量 2026-08-30，上述標籤二進位〕`evolve x:1` → `commit c1` → `evolve y:2` → `commit c2` → `evolve z:3` → `commit c3`，
三個 ○ 檔逐字如下：

```
.oo/savepoints/3097eaac…   #nlang/store savepoint / parents:                    / { x: 1 }
.oo/savepoints/d781573f…   #nlang/store savepoint / parents: 3097eaac…          / { y: 2 }
.oo/savepoints/ce9e361c…   #nlang/store savepoint / parents: d781573f…          / { z: 3 }
```

而 `oo log` 走的是**另一條鏈**（`ccef99ce…` → `c54202d8…` → `5fce07a5…`），
每一顆帶 `message`、`Date`、`root`。

*   **○ 檔裡沒有任何一個 CAID。** 沒有 commit 的位址，沒有 root 的位址。
*   **`Commit` 結構裡沒有任何一個 ○ 的識別碼。**〔讀 `value.rs:2405`〕
    欄位是 `parent` / `root` / `meta` / `kind` / `refine_info`，**一個都不指向 ○**。

⟹ **兩張圖在磁碟上完全不相連。** `commit.md` §1.7.1 說「那是兩張圖，不是一張」——
今天兌現的是這句話的字面意思：**兩張圖，而且沒有任何一條邊把它們接起來。**

⟹ **A2 逐字所寫的那條路徑今天走不通。** §4.1 A2 說「歷史走訪須先改走 ○ 鏈」——
但 ○ 鏈裡**沒有歷史**：它裝的是每一刻的**工作集**（`{ z: 3 }`），不是宇宙，也不是提交。
`oo log` 今天印的四樣東西（commit CAID／message／Date／root）**在 ○ 裡一樣都沒有**。

### 1.3 ○ 是一條快照鏈，不是一份日誌——而它的成本是平方的

〔量〕連續 `oo evolve`（每次加一個相異欄位），單一倉，不提交：

| n（○ 數） | 單次 `evolve` 牆鐘 | `savepoints/` 總位元組 |
| :-- | :-- | :-- |
| 1 | **0.02 s** | 41 |
| 200 | **0.45 s** | **182,998** |
| 322 | **0.84 s** | **482,115** |

*   **位元組是平方的，已驗到 1.5%**：$(322/200)^2 = 2.59$，實測 $482115/182998 = \mathbf{2.63}$。
    成因〔量〕：**每一顆 ○ 存的是當下的整個工作集，不是差量**——第 1 顆 41 B（`{ f1: 1 }`），
    第 200 顆 1,857 B（`{ f1: 1 f10: 10 … f200: 200 }`，200 個欄位全在裡面）。
*   **單次成本超線性**：n=322 時是 n=1 的 **42 倍**。成因〔讀 `savepoint.rs:118`〕
    `record` 每次都 `load_nodes`（讀**全部**檔）以算 `tips_of` ⟹ **沒有 tip 指標**。
*   **400 次連續 `evolve` 在兩分鐘內跑不完**（逾時中止於第 322 次）。
*   **`commit` 不回收 ○**〔量〕：三次提交後 `injections/` 由 3 清為 **0**，`savepoints/` 維持 **3**。
    §3.1 耐久款要的正是這個（○ 必須在 Commit 之後繼續存在）⟹ **不是缺陷，是條文的直接後果**。

**⚠ 一個必須說清楚的限定**：**平方是「每個提交區間之內」的，不是全域的。**
提交會清掉 `injections/`，所以下一顆 ○ 只裝新的注入（實測 `{ y: 2 }` 而非 `{ x: 1, y: 2 }`）。
⟹ **檔案數無界成長是全域的；單檔大小的平方是區間內的。** 不要把這兩句合成一句。

⟹ **A3「日誌條目的正準形」不是一個命名問題。** 今天一個「條目」＝**一份完整快照**，
而日誌的定義是記**事件**。這張卡問的正是：一條記錄裡該有什麼。

### 1.6 一個把 `CommitMeta` 加欄位的定價，比看起來便宜

〔讀 `value.rs:3626`〕`Commit::content_hash` 把 meta 以 **`format!("{:?}", self.meta)`** 進雜湊。

提交是一個**事件**，而 §1.11 已裁**歷史層不繼承值層的冪等性** ⟹ 事件不冪等
⟹ **它本來就該有自己的一顆 ○**（鑄造圖）；那顆 ○ 一進一出、只帶「我變成了 C」
⟹ 畫圖時**收成一條邊上的標籤**（呈現圖）。**同一件事在鑄造圖裡是點，在呈現圖裡是邊。**

**二、D53 帶來一條紅線，而它是一個數字對一個數字。**
歷史 DAG 是一維 CW 複形，$\operatorname{rank} H_1 = E - V + C$，
而一個獨立環路**恰好是一次分叉又合流**。收縮一顆一進一出的 ○ 是**邊收縮 ＝ 同倫等價**
⟹ H₁ 不變；刪掉一個分叉／匯流點則 $E-V+C$ 會掉。

> **呈現圖的 $E-V+C$ 必須等於鑄造圖的。**
> 少一個洞 ＝ 藏起了一次匯流；多一個洞 ＝ 無中生有一次匯流。
