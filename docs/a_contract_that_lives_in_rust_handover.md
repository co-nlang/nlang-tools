## 0. 一句主張

**內建繞過了語言自己的施用機制，於是把它做對的兩件事各自重做了一遍，而兩遍都做錯。**

*   **入口**：內建接受哪些鍵，只以 Rust 閉包裡的 `get_field("0")` 存在。沒有任何東西宣告它，
    所以**角色互換的呼叫通過了形狀檢查並被真的施用**。
*   **出口**：`list.rs` 的六行以**印出形**判真，於是「謂詞塌了」「謂詞說不」「謂詞回了 5」
    是同一格，而**字串 `"true"` 算成原子 `#true`**。

## 1. 射程

### S1 —— 內建必須宣告它綁定哪些鍵（O76 ③、O78 ②）

宣告**住 registry，不進值**。〔理由，O78 ②〕內建的值多一個欄位會移動標準根 digest，
而標準根 ⊕ 進每一個根的身分（O58）⟹ 那是一次紀元，本弧不付。

宣告**必須是一件規格事實**：`SYNTAX_09` §2 #1 已寫下這條 MUST 並附未兌現宣告。
交付要做的是讓它兌現——形狀由你選，但**必須能回答「這個內建收哪些鍵」而不必執行它**。

〔偵察已量，可直接用〕241 個註冊點中 **207（85.9%）是固定 arity 的純位置形**，鍵集可由現有
原始碼機械讀出；34 個「無 `get_field`」走共用 helper（`get_two_args` 8 處、`extract_str_arg`
11 處）或不吃引數（`math.random` 逐字 `|_arg|`）；7 個具名。

### S2 —— 未宣告的鍵形不得被靜默接受（O76）

**失配路徑已經存在且集中**：〔讀 `lib.rs:3138-3170`〕內建回 `Value::Top` 時，施用層自動建出
部分施用的繭。**這一弧不需要新造失配機制**，只需要在呼叫 `func` 之前多一次宣告比對。

**探針 r4** 釘的是性質不是拼法：失配後的結果**不得是一個看起來合理的答案**。
繭、`⊥`、其他，都可以；`0` 不可以。

### S3 —— 標準庫統一（O78 ①③）

**正準判準（O78 ③，本弧採用）**：

> **凡意圖被 `|>` 使用的態射，其資料參數必須是最後一個。**

〔理由，已量〕`|>` 把被管的值放進**下一個空位**（`lib.rs:3049` 逐字
`nf.insert((max_idx + 1).to_string(), arg.clone())`）⟹ 管道只與「資料放最後」組合得起來。

**要動的**（探針 r1／r2／r3／r7／r8 各釘一格）：

| 現行 | 內建 | 動作 |
| :--- | :--- | :--- |
| list-first | `~%List./take_while`、`./drop_while` | 改為資料在最後 |
| list-first | `~%Query./where` | 同上。**⚠ 見 §3 的 L2-117** |
| 嗅探 | `~%List./filter`、`./map` | **拿掉嗅探**，宣告一種 |
| 第五種形 | `~%List./fold` | 見 §5 的必答題 |

**⚠ 射程含全部 40 個 `~%List` 註冊點**，不只上表這幾個。偵察只量到已知的四群，
**你必須逐個列出現行形**並在 §7.1 交出那張表——否則「統一」這件事沒有人知道做完了沒有。

**O78 ① 的彈性條款要照字面讀**：一致性的**粒度是模組**，「同一個模組底下，相似型的態射
**傾向**使用同一種」。⟹ 若某個內建的現行形是**必須**（有結構理由，不只是習慣），
**不要動它**，把理由寫進 §7.3。**判準已經有一條可證偽的**（管道），用它，不要用美感。

### S4 —— 迭代型內建不得把 ⊥ 判為假（O77）

〔偵察已量〕整個面**只有六行**，全在 `list.rs`：`:351`（`filter`）／`:458`（`any`）／
`:485`（`all`）／`:513`（`find`）／`:653`（`count`）／`:715`（`partition`）。

〔對照，不要一起改〕另外 **11 處** `trim_start_matches('#')` 是**安全的**——它們先
`match AtomKind::Tag(t)`，`⊥`／字串／數字根本不進那條臂。**動它們是順手改動，須在 §7.2 指名。**

`SPEC_08` §4.3 的新款**刻意不要求中止**，要求的是**可分辨**。形狀由你選，
探針 r5 只釘「塌陷 ≠ 說不」。

### 7.4 工單指名要你回答的問題

1. `list.fold`：
   - **現行（本弧前）**：兩鍵，嗅探哪個是清單；另一個必須是 `{ %val: 初值, %f: 態射 }`。`f` 以柯里化施用：`apply(apply(f, acc), item)`。三引數 `fold(f, init, list)` 到不了。`~%List./fold ~l { %val: 0, %f: ~f }` 與 `xs |> /fold { %val, %f }` 靠嗅探都能跑。
   - **選的協定**：仍是兩鍵，**不再嗅探**。`0`＝`{ %val, %f }`，`1`＝清單。資料在最後，故 `xs |> /fold { %val, %f }` 仍對；list-first 的 `fold ~l rec` 改為繭。
   - **可跑的呼叫**：`~%List./fold ({ %val: 0, %f: (acc -> (x -> acc + x)) }, [10, 20, 30])` → `60`。管道：`[10, 20, 30] |> ~%List./fold { %val: 0, %f: (acc -> (x -> acc + x)) }`。

2. 34 個無 `get_field` 的宣告：掛在**登記表的註冊點**（每個 id 一列），不是掛在 helper 的型別上。`get_two_args` 的 8 個宣告為必填 `0`、`1`；`extract_str_arg` 的宣告為必填 `0`。`math.random`（以及 `time.now`、`env.args` 等不讀引數／`|_arg|`）宣告**空必填鍵**——施用即開火，多出來的鍵（慣用 `_`）不擋。

3. 「必須」而非「習慣」者（未改）：
   - `concat`／`zip`：兩個運算元都是資料，順序就是結果的順序；翻轉會讓 `a |> /concat b` 變成 `b ++ a`。
   - `range`：兩個整數產出清單，沒有 callback。
   - 一元清單態射：唯一的資料槽已經是那一個。
   - `query.select`：`0`＝值，`path`／`1`＝路徑（七個具名裡的 `path`）。這是導航不是 callback；把資料翻到最後會讓具名 `{ path: … }` 與 L2-104 那一族的「具名＝所綁的鍵」不一致。`query.pluck`／`deep_merge` 同型，維持。
   - `~%Cond./cond`／`./match`：工單要它宣告、不要改分支表。已宣告；g6 綠。
