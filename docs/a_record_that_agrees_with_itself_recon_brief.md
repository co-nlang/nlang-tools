### 1.5 產生判準 (a) 是以位元組實作的，不是以「格上的位置」

〔量，可逐字重跑〕

```bash
D=$(mktemp -d); cd $D
printf 'a: 1\n' > a.n; printf 'b: 2\n' > b.n
oo evolve a.n; oo evolve b.n; oo commit -m one
ls .oo/objects/sha256/*/* | sed 's|.*/sha256/||' | sort > o1.txt   # 3 個物件
oo evolve a.n          # 重新注入一個「已經提交、內容相同」的定義
ls .oo/savepoints | grep -v LOG | wc -l                            # 3  ← 鑄出了新的 ○
oo commit -m two
ls .oo/objects/sha256/*/* | sed 's|.*/sha256/||' | sort > o2.txt
comm -13 o1.txt o2.txt                                             # 只有 1 個新物件
```

**只多一個物件 ＝ 只多了 commit 物件，root 物件被重用 ⟹ 宇宙在格上的位置沒有移動。**
而 ○ 照鑄。原因是 commit 之後工作集被清空，於是「工作集的位元組」與「格上的位置」
在**提交邊界上分家**，而 `record` 比對的是前者。

**⚠ 去重本身沒有壞，不要把它寫成「去重壞掉了」。**〔量 2026-08-30，三種情形逐一跑過〕

| 情形 | 結果 |
| :-- | :-- |
| `evolve a` → `evolve a`（中間不提交） | **不鑄**（去重命中） |
| `evolve a` → `commit` → `evolve a` | **不鑄**——上一個 ○ 的 body 恰好也是 `{ a: 1 }` |
| `evolve a` → `evolve b` → `commit` → `evolve a` | **鑄出 ○3**，而 root 未變（上面的 `comm` 只吐一個新物件） |

⟹ **缺陷只在「上一個 ○ 的 body ≠ 提交後的工作集」時出現**，
而提交邊界正是讓這兩者分家的地方。**是比對基準選錯了，不是比對壞了。**

### 1.7 產生判準 (b) 與 `_|_` 那一款：**零兌現**

〔量〕`--observe` 是真的化約了 thunk——**呼叫已證明發生**（§8 開弧 4）：


那次失敗即不可檢查**」——**現在正是那個情況**。
（附帶：⊥ 觀測 **rc=0**，與 Inbox 那列「commit 撞 ⊥ 回報成功且 exit=0」同型，這是第三個面。）

### 1.8 但有一個結構性混淆因子，你必須把它算進來

## 5.1 裁定：`parents` 是複數（D50，用戶 2026-08-30）

`SPEC_10` §3.1「順序（MUST）」壓了**兩件不同的事**：
**parent ＝ 一個函數**（本地宣告的邊，「這顆從哪顆來」）與
**可比 ＝ 一個關係**（「任兩顆判得出先後」）。
**parent ⟹ 可判定的偏序，但不 ⟹ 全序；全序 ⟹ parent，但把分叉壓成一條線。**

**判別器是 `oo log`**：畫樹要的是**覆蓋關係**（哪一條邊該畫），裸的偏序只給**可達性**。

**用戶的裁定與理由（逐字轉述）**：「`.parent` 只是從 commit 在用變成 savepoint 在用……
而 `commit.parent` 是單數是原本的設計，反而跟現在不太合。」
⟹ **搬的是欄位，不是設計。**

**驗收方複驗到的佐證比理由更強**：`REAL_01` §2 **控制面**逐字是
`"parents": ["hash:…"]` **陣列**，而 `value.rs:1765` 是 `Option<ContentHash>` **單數**——
`commit.md` §2.6 早就把這一列記為不合。⟹ **規範面本來就是複數，單數只活在 Rust。**

**三個後果**：

1.  **§3.1 的順序款改寫為 `parents` 款，全序讀法作廢。**
    **你 Q2 的三個理由都成立**（中文「先後」是觀測者的時間序／深度若是讀數則全序／
    今天 `LOG` 是一條線），**被換掉的是前提，不是推理**。
2.  **A 與 C 只記位置、不記前驅，表達不了 `parents`** ⟹ **B2 是唯一與 D50 相容的形。**

## 5.3 要你回答的（Q11–Q16）

*   **Q11 — tip 集合能不能由不可變的 ○ 集合純導出？**
