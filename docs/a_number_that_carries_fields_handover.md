# 一個帶著欄位的數（Q-109）

## 0. 判準（規格原文）

*   **`SYNTAX_06` §4 #6**：資料原子與資料記錄合併，產生既有值又有欄位的**混血節點**，`x: 1 & { name: "Alice" }` 即 `{ %val: 1, name: "Alice", %kind: #data }`。**值語境統一律（G6）**：一切值語境——觀測、算術運算元、態射應用與管道的引數、原子比較——都讀 `%val`。
*   **D119**：值語境裡還不是值的運算元（型別、區間、補）答 `_`。
*   **D121**（2026-10-28 用戶裁定，甲）：沒有 `%val` 的記錄在值語境裡答 `_`——與一個值交會它就是混血節點，還不是一個值。取代 G6「無 `%val` 之普通 combo 在算術／原子比較下照舊 `_|_`」與 #5／#12「`==` 誤用於不可塌縮 Combo → `_|_`」。
*   **`SPEC_12` §2.1**：不得破壞格論的單調精煉；`&` 是交會——結合、交換。
*   **Q-103 的不變式**：一檔、兩次演化、兩次提交同讀數、同根。

## 1. 缺陷

〔量，`v0.109.0` 標籤建置；eval 在空目錄；`acc/q109/recon.sh`、`acc/q109/ways.sh`〕

*   **交會不結合**：`(@int & 5) & { a: 1 }` 是混血 `5`，`@int & ({ a: 1 } & 5)`、`(@int & { a: 1 }) & 5` 是 ⊥ `Value is not an integer`。⟹ `x: @int` 再寫 `x: 5 & { note: "n" }` 演化拒絕（反過來寫也拒），eval 的交會 ⊥。`(1..) & { a: 1 }`、`(1..) & (5 & { a: 1 })` ⊥ `Incompatible types`；`@float & (5 & { a: 1 })` ⊥。
*   **字面的混血節點**：`{ %val: 5, a: 1 }` 觀測讀 `5`、`== 5` 讀 `#true`，而 `+ 1`、`* 2`、管道 ⊥；`{ a: 1 } & { %val: 5 }` ⊥；`@int & { %val: 5, a: 1 }` ⊥。〔讀〕字面的 `%val` 欄位是還沒強制的 thunk，值語境只強制最外層（`eval_math_values`），交會的 `force(..).collapse()` 塌出 thunk 後不再強制。
*   **內建**：`~%Math./add (5 & { a: 1 }, 1)`、`~%Math./sqrt (4 & { a: 1 })` ⊥——內建的引數不讀 `%val`。
*   **D119 沒看穿混血節點**：`{ %val: @int, a: 1 } + 1` ⊥。
*   **D121**：`{ a: 1 } + 1`、`{ a: 1 } == 5`、`{ a: 1 } == { a: 1 }` ⊥；`h: { a: 1 }`、`r: h + 1` 再寫 `h: 5` ⟹ 一檔、兩次演化、兩次提交都提交出 ⊥，eval 讀 `6`；`h: 5` 寫在前面時兩次提交 ⊥、另兩條 `6`、兩個根。

## 2. 依據；位址

*   **一題已裁（D121，甲）**；其餘不須裁：結合律決定 `@int & { a: 1 }` 不得是 ⊥（它與 `5` 的交會必須等於 `@int & ({ a: 1 } & 5)`，那是混血 `5`）——原子型別、區間與記錄交會時進 `%val`，`@int & { a: 1 }` ⟹ `{ %val: @int, a: 1 }`；字面 `{ %val: … }` 就是混血節點（#6 的等式）；內建的引數讀 `%val`（G6「態射應用之引數」）。
*   **位址**：讀錯的那些格子的根移動（以前提交的是 ⊥ 或拒絕）；**讀對的根不動**（g2 十一顆，v0.109.0 釘）。破壞性，收尾時記 `CHANGELOG`。

## 3. 射程＝不變式（不是機制）

*   **M1 值語境讀 `%val`，不管怎麼寫成**：交會得來的、字面寫的、`%val` 還沒強制的；算術兩邊、`==`／`!=`、管道、`~%Math`／`complex.` 內建的打包引數（r1）。
*   **M2 還不是值的答 `_`**：`%val` 是型別或區間的混血節點、沒有 `%val` 的記錄（開放或封閉）（r2）。
*   **M3 交會結合、交換**：同樣三個運算元，六種排列、兩種分組，讀數與欄位都一樣（r3；型別、區間、`@float` 投射、字串、字面 `%val`、兩個記錄）。
*   **M4 三條路**：型別座標與混血節點、記錄與之後的值，一檔、兩次演化、兩次提交同讀數同根（r4）；三個寫入五種分組一個根（r5）。
*   **另一半——不是混血節點的照舊**（g1）：真矛盾照舊 ⊥（`@str & (5 & { a: 1 })`、`(6..) & …`、`{ %val: 5, a: 1 } & 6`、`("a" & { a: 1 }) + 1`、`[1] + 1`、`(x -> x) + 1`、`@int & [1]`、`@list & { a: 1 }`）；錨點先封（`#_ + { a: 1 }` ⟹ `#arithmetic_on_anchor`）；`=` 家族不剝殼（`(3 & { note: "n" }) = 3` ⟹ `#false`）；座標導航進記錄；`@combo` 不進 `%val`；**記錄本身當內建的引數是具名參數**（`SPEC_08` §3.5：`~%Math./add { x: 7, y: 17 }` 仍是部分施用）——D121 管的是打包引數裡的運算元。讀對的根不動（g2）。
*   若你找到另一處值語境不讀 `%val`、或另一種會進 `%val` 的運算元（補、聯集、另一個內建族），一併在射程內，在 8.1 列出。

## 5. 必答（請在交付報告裡回答，逐題）

*   **Q1 判準**：你怎麼判「能被交會進 `%val` 的記錄」與「原子型別」——清單、態射、型別值、`@option`／`@result`、封閉的 `{{ }}`、帶 `%kind` 的記錄各怎麼答。

*   **Q5 交會的其他形**：補（`!0 & { a: 1 }`）、聯集（`(1 | 2) & { a: 1 }`）、記錄 × 記錄（`{ %val: 5 } & { %val: @int }`）你怎麼答，有沒有違反結合律的。
