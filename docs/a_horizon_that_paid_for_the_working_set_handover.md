## 0. 判準

*   **一筆寫入的成本由寫入的大小界定**（Q-116、Q-117、Q-128 同一個不變式）：N 個坐標的寫入，4N 個的時間少於 N 個的 8 倍。
*   **視界是快照**（D127）：存下的視界不因之後到的坐標而改讀數。
*   **不須裁**。

## 1. 缺陷

〔量，`v0.128.0` 標籤建置；`acc/q130/blur.sh`、`chain.sh`〕

*   **每一個落地成視界的坐標，付一次整個工作集**：`/f: (x -> x == 0 ? 0 : /f (x - 1))`、`h: /f 5000`，再加 N 個 `k_i: h + i`，同一次 `evolve`：N=500／1000／2000 演化 9.53／34.60／142.02 秒（平方級）。同樣的欄位讀 `h: /f 50`（存配方，不是視界）：5.99／11.36／22.35 秒。
*   **超過深度上限的鏈，名字先寫**：每一節都存成視界（D130），N=400／800 演化 5.08／21.36 秒；讀者先寫 4.83／11.70。
*   **成因**〔讀碼，修法驗證〕：Q-117 的就地落地只收原子、配方、由它們組成的記錄與聯集（`fast_value`），視界不在裡面，所以每一個視界都走完整交會加整份重新蓋章。
*   **為什麼現在要修**：Q-127 的參考照讀取順序落地，每一種寫法都付名字先寫的價——純鏈 N=2000 約 125 秒（v0.128.0 讀者先寫 32.57、名字先寫 136.48）。

### 8.4 工單指名要你回答的問題

**Q1。** 兩個前提，各有判斷守著。

坐標上原本沒有東西。就地落地要求每一個新鍵都不在工作集的 data 與 local，也不在這次 session 的差量裡（`staged.get_field`、`get_local_field`，以及 `session_has_delta` 時的 `session_delta`）。鍵已經在工作集裡，這筆寫入改走 `unify_universe`。

視界的讀數不因之後到的坐標而變。收進來的是 `Value::Blur`，也就是已經停下的快照。`collect_bare_reads` 與 `root_reads` 都不走進 `Blur`，所以它不登記成任何名字的讀者，後來的寫入也不會把它拿去重蓋。交會遇非 ⊥ 留下視界、快照不改（`unify.rs` 視界與其他值那兩臂）。這條路只在坐標是空的時候把快照放進去。

HEAD 上已經提交的值不在這兩個判斷裡，見 Q3。

**Q2。** 頂層的視界收。裝在記錄的 data、local 裡的視界也收，裝在聯集裡的也收，因為這兩個臂會再呼叫 `fast_value`。型別、規則、system、`%kind` 以外的 meta、spread、封閉的記錄，`fast_combo` 先把整筆記錄拒掉。

*   `Top`、`TopCaused`：不收。與 `_` 交會時 `_` 被丟掉，留下的不是原來那個值。
*   `Atom`：收 `Int`、`Float`、`Complex`、`Str`、`MultilineStr`、`Tag`、`Unit`。`TagStart`、`TagEnd`、`Regex`、`Top`、`Bottom`、`PathLit`、`Bytes`、`Uri`、`Time` 維持 Q-117 的不收。
*   `Combo`：`fast_combo` 通過，而且 data 與 local 的每個值都通過，才收。欄位裡的視界因此收。清單的 `%kind` 也要是可收的值。
*   `Union`：每個成員都可收才收。成員是視界就收。成員是 ⊥ 就不收。
*   `Code`：不收。
*   `Thunk`：沒有 `context`、也沒有自由的 `$` 才收。那是配方，讀數在重蓋時重算。
*   `Ref`：不收。引用要等它指的東西到了，讀數才定。空坐標上交會也原樣留下引用，所以「收引用」的變異可以是綠的；本卡的參考不收。
*   `Bottom`：不收。交會留下裸的 `#conflict`（D117）。
*   `Blur`：收。
*   `Range`、`Complement`：不收。

**Q3。** 捷徑不跟 HEAD 交會。每個坐標在進捷徑之前仍先對根做 `meet_clash`。視界與值交會留下視界，演化收下，不報衝突。

工作集裡還沒有這個鍵時，捷徑把新值插進空位。演化時的完整交會也只交會工作集與這筆寫入。兩邊放進工作集的是同一份；shadow 比的就是這個。提交仍把根與工作集交會，這條路沒有改。
