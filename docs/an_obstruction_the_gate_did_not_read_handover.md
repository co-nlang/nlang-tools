## 0. 這一弧要證明的一句話

**宣告 `#pure` 的守衛，判的必須是「這個值的障礙是不是零」，而不是「我靜態看不看得到」。**

〔量 v0.34.0〕把一層態射應用放在宣告與時鐘之間，同一支程式就從 ⊥ 變成被收下：

```
{ %effect: #pure, v: ~%Time.now _ }              → ⊥ #effect_violation
{ %effect: #pure, v: { w: ~%Time.now _ } }       → ⊥ #effect_violation
{ %effect: #pure, v: [~%Time.now _] }            → ⊥ #effect_violation
{ %effect: #pure, v: ((x -> ~%Time.now _) 1) }   → **被收下**
{ %effect: #pure, v: ~%List./map (xs, 不純) }     → **被收下**
```

**最鋒利的一格**：被收下的那個值**自己印著它的效果**——
`~%List./map ([1,2,3], (x -> { t: ~%Time.now _, r: 1 }.r))` 印出
`[1 ;; %effect: #io, 1 ;; %effect: #io, 1 ;; %effect: #io]`，`.%effect` 答 `#io`，
**而站在它旁邊的守衛說沒問題**。

| # | 裁定 |
| :-- | :--- |
| **①** | **內建施用呼叫者的態射時，必須把該次施用的效果 union 進結果——不論態射的回傳值有沒有被留下。** |
| **②** | **`SPEC_08` §4.3 的「靜態守護」由本體降為實作註記**；判準改採 `TAG_REGISTRY` 那一句：**宣告的截面被非零障礙反證**。 |
| **③** | 理由不是務實選擇。**disc 023 §3** 的字典表逐字把這個守衛列為「宣告『有全域截面』(`#pure`) 但**障礙非零** → 說謊 → ⊥」，而 `#pure` 在該表的定義是「**值完全由 CAID 決定；全域截面存在**」⟹ **被檢查的是一個障礙是不是零，那是值的性質**。**障礙不是資料流性質**：`/filter` 為了決定去留看了三次時鐘，把布林丟掉不會讓那三次觀測沒發生過。 |
| **④** | **`~%Query./where` 的無條件 IO 底線在 ① 完成後拆除。** 它今天連誠實的純謂詞都擋。 |

**與既有法的接合**：`REAL_03` §6.9（v0.33.0）裁「**位址決定值**」，而 `#pure`
逐字就是「§6.9 對這個值成立且沒有格外的觀測座標」——**一個靜態檢查無法見證一個
關於值的宣稱**。同 §6.9 第二款：不進位址的東西**得**在因果通道上可觀測，
`%effect` 正是那條通道。

## 2. 量測（2026-08-25，`oo v0.34.0` 真二進位）

> 二進位使用前先問了已知答案的問題：`~%Math./add (1,2)` → `3` ✓

### 2.1 callback 矩陣——舊帳那句話今天只對 1/5

| callback（給不純的態射） | 閘 | **值自己的 `.%effect`** |
| :--- | :--- | :--- |
| `~%List./map` | 收下 | **`#io`** — 值對、閘瞎 |
| `~%List./filter`（不純謂詞） | 收下 | **`#pure`** — **值自己是假的** |
| `~%List./take_while`（不純謂詞） | 收下 | **`#pure`** — 同上 |
| `~%Cond./match`（不純分支） | 收下 | **`#pure`** — 同上 |
| `~%Query./where`（**純謂詞**） | **⊥ 擋下** | `#io`（無條件底線） |

**⟹ 佇列上原本那條路徑 (a)「守衛改動態（值已帶正確效果，只差有人讀）」，
括號裡那句在五格裡只對一格**——其餘四格**根本沒有東西可讀**。

### 2.2 機制

**效果只在態射的回傳值被實際放進結果時存活。** `map` 把回傳值放進輸出清單，
效果跟著進去；謂詞形 callback 把布林用完就丟，效果跟著蒸發。
⟹ 今天的實作把「**回傳值有沒有被留下**」與「**障礙是不是零**」綁在一起，
而依 ③ 這兩件事無關。

### 2.3 路徑 (b) 的代價也量到了

〔量〕`~%Query./where ([{ a: 1 }], (r -> #true))` 在 `%effect: #pure` 之下 **⟹ ⊥**。
那個謂詞什麼都沒觀測。⟹ `/where` **不是「對」，是「保守」**，
代價是**誠實的純用法一併被拒絕**。這正是 (b) 若被選中會永久化的東西。

### 2.4 身分紅線（已量定）

〔量〕效果**不進 BN/ 雜湊**。同輸出 `[1, 1, 1]`、一純一不純的兩個計算：

```
identify(~%List./map ([1,2,3], (x -> 1)))                            = a04c6b85…c42e28
identify(~%List./map ([1,2,3], (x -> { t: ~%Time.now _, r: 1 }.r)))  = a04c6b85…c42e28
```

**逐字元相同。** 本弧使效果傳染變多，**不得**使任何位址移動（`G4` 是紅線探針）。

### 2.5 開單時更正的兩處舊帳

*   **「28 個 callback 內建」數的是實作端呼叫點**。〔量〕`~%Option`／`~%Result`
    **不是使用者可及的模組**（`⊥ #missing_key`）；使用者面是 `~%Cond` 3 個
    ＋ `~%List` 約 16 個帶態射者 ＋ `~%Query./where`。
*   **舊 recon 的「引擎算對了」只對 `~%List./map` 一格**，見 §2.1。

## 3. 射程

### S1 —— 效果必須在 callback 存活（O74 ①）

凡施用呼叫者態射的內建，**必須**把該次施用觀測到的效果 union 進結果，
**不論回傳值有沒有被留下**。這是**類別**，不是個案——`/filter` 修好而
`/take_while` 沒修，等於沒做（`R3` 與 `R4` 是同一條律的兩個家族）。

### S2 —— 守衛判的是值（O74 ②）

守衛**必須**依值實際帶有的效果判定。S1 做完之後，值就誠實了；
**S1 沒做而只改守衛，四格仍然漏**（§2.1）。

### S3 —— 拆掉 `/where` 的 IO 底線（O74 ④）

**在 S1 完成之後**才拆。拆完誠實的純謂詞必須寫得出來（`R5`），
而不純謂詞仍然被擋——**這時是被 S1 擋的，不是被底線擋的**。

### 明確不做

*   **不得**動任何身分。〔量〕效果不進 BN/ 雜湊；`G4` 是紅線探針。
*   **不得**關掉繭的屏蔽。disc 023 §4：繭是**自帶截面的局部 frame**，
    傳染在邊界停——它不是守衛上的洞，是障礙被 discharge 的地方。`G2` 看守。
*   **不得**碰 `/if` 的態射分派。〔量〕`/if (#true, (@any -> 1), (@any -> 2))`
    今天答 `_`；那是既有且已記錄的缺口，本檔**沒有任何探針碰它**。
*   **不得**碰 `~%List` 那組在恆真謂詞下給錯答案的 callback
    （`/any`／`/count`／`/find`／`/partition`／`/group_by`／`/sort_by`）——
    **與效果無關，已另立 Inbox**。把它併進來會使一個弧變成兩件事。
*   **不得**改規格——規格收尾是驗收方的事。

## 7. 交付回報（交付方填；本行以上一字不得動）

### 7.1 射程逐項對照

S1 類別，不是逐個 builtin。`apply_morphism` 對每一次施用推一層 frame：該次施用裡
實際發生的觀測（含內層 builtin、含回傳值被丟掉的謂詞）都 union 進結果。
`/filter` 與 `/take_while` 因而同一條律；沒有改那些給錯答案的 List callback
的回傳值。

S2 守衛改讀值的實際障礙。構造期 `predict_effect`（被呼叫者的宣告標籤）不再是
判準。`force_recursive` 對開 combo 以欄位實際效果重算 `effect`；宣告 `#pure`
的 combo 在固化／導航時走 `refuse_lying_pure`。繭仍不把內部效果 join 出去。

S3 `query.where` 不再無條件 `union(IO)`。誠實純謂詞寫得出來（R5）；不純謂詞
由 S1 帶上障礙，再由 S2 擋住。標準根上 `/where` 仍標 `#io`（身分紅線，未改）。

### 7.2 順手改動（逐項指名）

*   `engine.project_down` 對 target 改 `force_recursive`：結果成為 solid combo，
    才不會在觀察時被開 combo 重算洗掉 builtin 已寫的 `#state`（L2-104 的尾巴）。
    這是 S2 重算的後果，不是 project_down 行為改寫。
*   無 `cargo fmt` 整檔重排。

### 7.3 工單哪裡是錯的

無。補充一項工單已寫、實作必須守的：`~%Query./where` 在標準根上的宣告標籤
仍是 `#io`（`as_shipped` 進 digest）。S3 拆的是把那張標籤蓋到結果上的底線，
不是改庫裡的字。

### 7.4 工單指名要你回答的問題

`(x -> { t: ~%Time.now _, r: 1 }.r)` 的 `.%effect` 為 `#io`；包在
`{ %effect: #pure, v: … }` 下為 ⊥ `#effect_violation`。誠實純分支仍成立。
